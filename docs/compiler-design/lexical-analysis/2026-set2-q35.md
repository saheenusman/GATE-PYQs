# 2026 CS2 Q35: Counting tokens produced by a lexical analyser

## Question

A lexical analyser uses the following token definitions:

```text
letter -> [A-Za-z]
digit  -> [0-9]
id     -> letter (letter | digit)*
number -> digit+
ws     -> (blank | tab | newline)+
```

For the string `x1 23mm 78 y 7z zz5 14A 8H AaYcD`, the number of tokens (excluding $ws$) produced by the lexical analyser is _____. (answer in integer)

<details class="success" markdown="1">
<summary>Answer</summary>

**13**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Refresher.** A lexical analyser uses **longest match** (maximal munch): from the current position it takes the longest string that fits any token.

An `id` must start with a letter, and a `number` is digits only. So a run like `23mm` splits where the class changes: digits form a `number`, then a letter starts a new `id`.

| Piece of input | Tokens | Count |
|---|---|---|
| `x1` | id | 1 |
| `23mm` | number `23`, id `mm` | 2 |
| `78` | number | 1 |
| `y` | id | 1 |
| `7z` | number `7`, id `z` | 2 |
| `zz5` | id (letters then a digit are allowed) | 1 |
| `14A` | number `14`, id `A` | 2 |
| `8H` | number `8`, id `H` | 2 |
| `AaYcD` | id | 1 |

Total: $1+2+1+1+2+1+2+2+1 = 13$.

**Verified** by tokenising the string with a regex scanner in Python: 13 tokens.

**Key idea:** an identifier cannot start with a digit, so `23mm` is a number then an identifier, while `x1` and `zz5` are single identifiers.

</details>
