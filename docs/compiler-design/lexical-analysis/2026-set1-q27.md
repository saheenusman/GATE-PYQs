# 2026 CS1 Q27: Lexical vs syntax vs semantic errors in C string declarations

## Question

Consider the following C statements:

```c
char *str1 = "Hello;      /* Statement S1 */
char *str2 = "Hello;";    /* Statement S2 */
int  *str3 = "Hello";     /* Statement S3 */
```

Which of the following options is/are correct?

- (A) S1 and S2 have syntactic errors
- (B) S2 has a lexical error and S3 has a syntactic error
- (C) S1 has a lexical error and S3 has a semantic error
- (D) S1 has a syntactic error and S3 has a semantic error

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Refresher.** Compilation finds errors in three stages:

| Stage | Error means | Example |
|---|---|---|
| Lexical | the characters do not form a valid token | unterminated string, illegal character |
| Syntax | the tokens do not fit the grammar | missing `;`, unbalanced braces |
| Semantic | grammar is fine but the meaning is wrong | type mismatch, undeclared variable |

**S1** `char *str1 = "Hello;` The string literal opens with `"` but never closes. The lexer cannot form a string token, so this is a **lexical error**. (gcc: *missing terminating " character*.)

**S2** `char *str2 = "Hello;";` The `;` is inside the quotes, so it is just part of the string. This statement is **valid**.

**S3** `int *str3 = "Hello";` Syntactically fine. But the string literal has type `char *`, and assigning it to `int *` is a **type mismatch**, a **semantic** error. (gcc: *initialization of 'int *' from incompatible pointer type 'char *'*.)

**Why the others fail:**

- **(A)** S1 is lexical, not syntactic, and S2 has no error.
- **(B)** S2 has no error, and S3 is not a syntax error.
- **(D)** S1 is lexical, not syntactic.

**Verified.** I compiled each line with `gcc -Wall`: S1 gives *missing terminating " character*, S2 compiles, S3 gives the incompatible-pointer-type diagnostic. (gcc 13 reports S3 as a warning. The C standard calls it a constraint violation, and newer compilers make it an error.)

**Key idea:** an unterminated string is caught by the lexer. A wrong type is caught after parsing, by semantic analysis.

</details>
