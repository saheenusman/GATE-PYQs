# 2020 CS Q19: Symbol table, recursion and declaration errors in a compiler

## Question

Consider the following statements.

- I. Symbol table is accessed only during lexical analysis and syntax analysis.
- II. Compilers for programming languages that support recursion necessarily need heap storage for memory allocation in the run-time environment.
- III. Errors violating the condition '*any variable must be declared before its use*' are detected during syntax analysis.

Which of the above statements is/are TRUE?

- (A) I only
- (B) I and III only
- (C) II only
- (D) None of I, II, and III

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

All three statements are false.

| Statement | Verdict | Reason |
|---|---|---|
| I | **False** | The symbol table is used in *many* phases. Semantic analysis looks up types and scopes in it, and code generation and optimization read the stored attributes (type, size, address). It is not limited to the first two phases. |
| II | **False** | Recursion is handled with a **stack** of activation records, one per call. Heap storage is needed only for dynamically allocated data (such as `malloc` or `new`), not for recursion itself. |
| III | **False** | "Declared before use" depends on context: whether this name was declared earlier. A context-free grammar used in syntax analysis cannot express that. It is checked in **semantic analysis**, by looking the name up in the symbol table. |

**Why the other options fail:** (A), (B) and (C) each include at least one of these false statements, so only (D) is left.

**Key idea:** syntax analysis checks the *shape* of the program (context-free). Checks that need context, such as declarations and types, belong to semantic analysis, and recursion needs a stack, not a heap.

</details>
