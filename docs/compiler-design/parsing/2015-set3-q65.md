# 2015 CS3 Q65: Whether LL(1) and LR(1) can parse a grammar with a repeated terminal

## Question

Consider the following grammar $G$

$$S \to F \mid H$$
$$F \to p \mid c$$
$$H \to d \mid c$$

where $S$, $F$, and $H$ are non-terminal symbols, $p$, $d$, and $c$ are terminal symbols. Which of the following statement(s) is/are correct?

- S1. LL(1) can parse all strings that are generated using grammar $G$
- S2. LR(1) can parse all strings that are generated using grammar $G$

- (A) Only S1
- (B) Only S2
- (C) Both S1 and S2
- (D) Neither S1 nor S2

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The string $c$ can be derived in two ways:

$$S \Rightarrow F \Rightarrow c \qquad\text{and}\qquad S \Rightarrow H \Rightarrow c$$

So $G$ is **ambiguous**. No ambiguous grammar is LL(1) or LR(1).

**LL(1) fails.** $\text{FIRST}(F) = \lbrace p, c \rbrace$ and $\text{FIRST}(H) = \lbrace d, c \rbrace$ overlap on $c$. On input $c$ the parser cannot choose between $S \to F$ and $S \to H$.

**LR(1) fails.** After shifting $c$, the state holds both $F \to c\cdot$ and $H \to c\cdot$, each with lookahead \$. That is a **reduce/reduce conflict**.

Neither S1 nor S2: option (D).

**Code check:** counting parse trees of $c$ under $G$ gives 2.

**Key idea:** ambiguity, a shared FIRST symbol, or a reduce/reduce conflict each rules out deterministic parsing.

</details>
