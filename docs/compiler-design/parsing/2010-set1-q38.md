# 2010 CS Q38: Is the grammar S -> aSa | bS | c LL(1) and LR(1)

## Question

The grammar $S \to aSa \mid bS \mid c$ is

- (A) LL(1) but not LR(1)
- (B) LR(1) but not LR(1)
- (C) Both LL(1) and LR(1)
- (D) Neither LL(1) nor LR(1)

*Printed as is: option (B) reads "LR(1) but not LR(1)" in the paper. That is a typo for "LR(1) but not LL(1)". It does not affect the answer.*

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**LL(1).** There is no $\varepsilon$-production, so each production is chosen by its first symbol. The three right-hand sides start with $a$, $b$ and $c$, which are all different. The table has one entry per terminal and no conflicts, so the grammar is LL(1).

**LR(1).** Every LL(1) grammar is LR(1). As a direct check, the LR(0) automaton has $8$ states and the SLR(1) table has no shift-reduce or reduce-reduce conflicts, and SLR(1) grammars are LR(1).

So the grammar is **both**: (C).

- (A) says it is not LR(1), but LL(1) grammars are always LR(1).
- (B) (as printed) contradicts itself; as intended ("LR(1) but not LL(1)") it fails because the grammar is LL(1).
- (D) would need a conflict in both parsers, and there is none.

**Code check:** a Python script computed FIRST $=\lbrace a, b, c \rbrace$, FOLLOW $=\lbrace a, \$ \rbrace$, built the LL(1) table (no conflicts) and the SLR(1) table over $8$ LR(0) states (no conflicts).

**Key idea:** LL(1) grammars are a subset of LR(1) grammars; distinct first symbols make this grammar LL(1).

</details>
