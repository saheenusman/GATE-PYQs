# 2007 CS Q52: Why the if-then-else grammar is not LL(1)

## Question

Consider the grammar with non-terminals $N = \lbrace S, C, S_1 \rbrace$, terminals $T = \lbrace a, b, i, t, e \rbrace$, with $S$ as the start symbol, and the following set of rules:

$$S \to iCtSS_1 \mid a$$
$$S_1 \to eS \mid \varepsilon$$
$$C \to b$$

The grammar is **NOT** LL(1) because:

- (A) it is left recursive.
- (B) it is right recursive.
- (C) it is ambiguous.
- (D) it is not context-free.

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

This is the classic dangling-else grammar ($i$ = if, $t$ = then, $e$ = else).

$\mathrm{FIRST}(eS) = \lbrace e \rbrace$, and $\mathrm{FOLLOW}(S_1) = \mathrm{FOLLOW}(S) = \lbrace e, \$ \rbrace$. For $S_1$ the entry $M[S_1, e]$ must hold both $S_1 \to eS$ (since $e \in$ FIRST) and $S_1 \to \varepsilon$ (since $e \in$ FOLLOW). That conflict is the dangling else.

The string $ibtibtaea$ has two parse trees (the `e` can attach to either `t`), so the grammar is **ambiguous**; an ambiguous grammar cannot be LL(1): (C).

- (A) There is no left recursion: every recursive occurrence follows a terminal.
- (B) $S_1 \to eS$ is right recursive, but right recursion is harmless for LL(1).
- (D) The rules are context-free by form.
