# 2009 CS Q42: Statements on parsing, recursion, L-attributed definitions and optimization

## Question

Which of the following statements are TRUE?

- I. There exist parsing algorithms for some programming languages whose complexities are less than $\Theta(n^3)$.
- II. A programming language which allows recursion can be implemented with static storage allocation.
- III. No L-attributed definition can be evaluated in the framework of bottom-up parsing.
- IV. Code improving transformations can be performed at both source language and intermediate code level.

Options:

- (A) I and II
- (B) I and IV
- (C) III and IV
- (D) I, III and IV

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

- **I. True.** General context-free parsing (CYK, Earley) takes $O(n^3)$, but the grammars of programming languages are mostly deterministic. LL(1) and LR(k) parsers run in $\Theta(n)$.
- **II. False.** Recursion needs a fresh copy of the local variables for every active call, so the number of copies is not known at compile time. Static allocation gives each variable one fixed address, which cannot support that. Languages with recursion use stack (dynamic) allocation.
- **III. False.** Every S-attributed definition is also L-attributed, and S-attributed definitions are exactly the ones evaluated naturally during bottom-up parsing. So at least some L-attributed definitions can be evaluated bottom-up. (More generally, L-attributed definitions on an LL(1) grammar can be handled in a bottom-up parser by adding marker non-terminals.)
- **IV. True.** Optimizations are applied to the source or syntax tree (for example algebraic simplification, loop restructuring) and to intermediate code (for example common-subexpression elimination, dead-code elimination).

True statements: I and IV, so (B).

- (A) includes II, which is false.
- (C) and (D) include III, which is false.

**Code check:** none (conceptual statements, nothing to run).

**Key idea:** one counterexample kills a "no ... can ..." claim (S-attributed definitions are L-attributed and work bottom-up); recursion forces stack allocation.

</details>
