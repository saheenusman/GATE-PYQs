# 2008 CS Q55: When an LALR(1) parser has shift-reduce conflicts

## Question

An LALR(1) parser for a grammar $G$ can have shift-reduce (S-R) conflicts if and only if

- (A) the SLR(1) parser for $G$ has S-R conflicts
- (B) the LR(1) parser for $G$ has S-R conflicts
- (C) the LR(0) parser for $G$ has S-R conflicts
- (D) the LALR(1) parser for $G$ has reduce-reduce conflicts

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

An LALR(1) parser is built by **merging LR(1) states** that have the same core. Merging combines lookahead sets of reductions, but it never combines the *shift* actions of a state, because states with the same core have the same shift transitions.

- So merging can create **new reduce-reduce** conflicts, but it can never create a new shift-reduce conflict.
- Conversely, an S-R conflict in the LR(1) parser survives in the merged state.

So LALR(1) has an S-R conflict **iff** the canonical LR(1) parser has one: (B).

- (A) is wrong: SLR(1) uses coarser (FOLLOW-set) lookaheads and can report S-R conflicts that LALR(1) does not.
- (C) is wrong: LR(0) has no lookahead, so it reports many conflicts that LALR(1) avoids.
- (D) is unrelated: R-R conflicts say nothing about S-R conflicts.

**Key idea:** merging LR(1) states can add reduce-reduce conflicts but never shift-reduce ones.

</details>
