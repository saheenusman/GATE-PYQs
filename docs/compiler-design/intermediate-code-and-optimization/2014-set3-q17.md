# 2014 CS3 Q17: Purpose of intermediate code in compilers

## Question

One of the purposes of using intermediate code in compilers is to

- (A) make parsing and semantic analysis simpler.
- (B) improve error recovery and error reporting.
- (C) increase the chances of reusing the machine-independent code optimizer in other compilers.
- (D) improve the register allocation.

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The compiler front end translates the source into a **machine-independent intermediate representation** (IR). Optimisation can then be done on the IR and reused: the same optimiser can serve several source languages (different front ends) and several target machines (different back ends). This reuse is the main reason for having an IR.

- (A) false: parsing and semantic analysis run on the source, before the IR exists.
- (B) false: error recovery and reporting happen in the front end phases (lexical, syntax, semantic analysis).
- (D) false: register allocation is **machine-dependent** and is done in the back end on target code.

**Key idea:** with an IR, $m$ front ends and $n$ back ends need $m + n$ pieces, not $m \times n$, and the optimiser is shared.

</details>
