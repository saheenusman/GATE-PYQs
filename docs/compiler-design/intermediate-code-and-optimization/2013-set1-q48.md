# 2013 CS Q48: Minimum spills with two registers

## Question

**Common data for Questions 48 and 49.** The following code segment is executed on a processor which allows only register operands in its instructions. Each instruction can have at most two source operands and one destination operand. Assume that all variables are dead after this code segment.

```c
c = a + b;
d = c * a;
e = c + a;
x = c * c;
if (x > a) {
    y = a * a;
}
else {
    d = d * d;
    e = e * e;
}
```

Suppose the instruction set architecture of the processor has only two registers. The only allowed compiler optimization is code motion, which moves statements from one place to another while preserving correctness. What is the minimum number of spills to memory in the compiled code?

- (A) 0
- (B) 1
- (C) 2
- (D) 3

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Lower bound: at least 1 spill.**
The comparison `x > a` needs both $x$ and $a$ in registers. Whatever else the else-branch needs afterwards must also be kept: $d$ and $e$ in the original order, or $c$ if they are moved. So at least **3 values** are live at the comparison ($a$, $x$ and one more), and 2 registers cannot hold them. At least one value goes to memory.

**Upper bound: 1 spill suffices, using code motion.**
$d$ and $e$ are used only in the else-branch, so move `d = c*a` and `e = c+a` into it:

```
R1 = a ; R2 = b
R2 = R1 + R2      // c
spill c           // the only store
R2 = R2 * R2      // x
if (R2 > R1) { R2 = R1 * R1 }
else {
  R2 = load c ; R2 = R2 * R1 ; R2 = R2 * R2   // d
  R2 = load c ; R2 = R2 + R1 ; R2 = R2 * R2   // e
}
```

Only $a$ stays in R1 throughout; R2 holds one temporary at a time. $d$ and $e$ are dead after the segment, so their values need not be kept.

**Why the others fail:** (A) is impossible by the live-value count. (C), (D) are not minimal, since one spill suffices.

**Code check:** a Python model of this 2-register schedule (one store of $c$) produced the same $y$, $d$, $e$ as the original code on 2000 random inputs.

**Key idea:** count live values at the busiest point; code motion can shrink that point by pushing computations into the branch that needs them.

</details>
