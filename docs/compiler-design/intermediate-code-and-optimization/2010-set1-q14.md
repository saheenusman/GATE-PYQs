# 2010 CS Q14: Which languages necessarily need heap allocation at run time

## Question

Which languages necessarily need heap allocation in the runtime environment?

- (A) Those that support recursion
- (B) Those that use dynamic scoping
- (C) Those that allow dynamic data structures
- (D) Those that use global variables

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Heap storage is for data whose size or lifetime is not known at compile time and which must outlive the call that created it. Dynamic data structures (lists, trees, dynamically sized arrays) fit that exactly: (C).

- (A) Recursion needs a **stack** of activation records, not a heap.
- (B) Dynamic scoping resolves names by walking the call stack; it is a lookup rule, not a storage need.
- (D) Global variables have fixed addresses and live in the **static** area.

**Classification note:** this is run-time environments, which the fixed topic list does not have. I filed it under `intermediate-code-and-optimization` as the nearest topic.

**Key idea:** static data goes in the static area, call frames on the stack, and dynamically created data on the heap.

</details>
