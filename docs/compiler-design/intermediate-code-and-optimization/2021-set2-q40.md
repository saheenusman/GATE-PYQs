# 2021 CS2 Q40: Additions and dereferences after common sub-expression elimination

## Question

Consider the following ANSI C code segment:

```c
z = x + 3 + y->f1 + y->f2;
for (i = 0; i < 200; i = i + 2){
  if (z > i) {
    p = p + x + 3;
    q = q + y->f1;
  } else {
    p = p + y->f2;
    q = q + x + 3;
  }
}
```

Assume that the variable `y` points to a `struct` (allocated on the heap) containing two fields `f1` and `f2`, and the local variables `x`, `y`, `z`, `p`, `q`, and `i` are allotted registers. Common sub-expression elimination (CSE) optimization is applied on the code. The number of addition and dereference operations (of the form `y->f1` or `y->f2`) in the optimized code, respectively, are:

- (A) 403 and 102
- (B) 203 and 2
- (C) 303 and 102
- (D) 303 and 2

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

With CSE, the common values are computed once, before the loop:

```c
t1 = y->f1;  t2 = y->f2;  t3 = x + 3;
z  = t3 + t1 + t2;
```

Inside the loop the body uses only `t1`, `t2`, `t3`.

**Dereferences:** `y->f1` and `y->f2` are each loaded once, so **2**.

**Additions:**

- Before the loop: `x+3` (1) and two more in `z` (2), total 3.
- Loop runs for $i=0,2,\dots,198$, which is 100 iterations.
- Per iteration: `i = i + 2` (1) plus two additions in the if or else branch (2), total 3.
- Loop total: $100\times3=300$.

Total additions $=3+300=303$.

I coded the optimised version with counters and compiled it with `gcc -Wall` with no warnings. It reports 303 additions and 2 dereferences.

- (A), (C): 102 would mean the fields are re-read in each iteration.
- (B): 203 undercounts the additions.

**Key idea:** CSE hoists repeated expressions (`x+3`, `y->f1`, `y->f2`) into temporaries computed once; count what remains.

</details>
