# 2008 CS Q12: Why code optimization works on intermediate code

## Question

Some code optimizations are carried out on the intermediate code because

- (A) they enhance the portability of the compiler to other target processors
- (B) program analysis is more accurate on intermediate code than on machine code
- (C) the information from dataflow analysis cannot otherwise be used for optimization
- (D) the information from the front end cannot otherwise be used for optimization

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Intermediate code is **machine-independent**. Optimisations done on it (constant folding, common subexpression elimination, dead code removal and so on) are written once and reused for every target processor; only the code generator changes per target. So optimising on intermediate code improves the compiler's **portability**: (A).

- (B) is not the usual reason: analysis can also be done on machine code, just less conveniently.
- (C) is false: dataflow information can also be used on other representations.
- (D) is false: front-end information can also be passed on without intermediate code.

**Caveat.** The wording of (B) is arguable (analysis really is easier on a simple IR), but (A) is the standard textbook answer and the key's choice.

**Key idea:** machine-independent optimisation on intermediate code lets one optimiser serve many target machines.

</details>
