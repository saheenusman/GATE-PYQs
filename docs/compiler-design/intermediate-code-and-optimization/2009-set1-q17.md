# 2009 CS Q17: Match compiler techniques with compiler phases

## Question

Match all items in **Group 1** with correct options from those given in **Group 2**.

| Group 1 | Group 2 |
|---|---|
| P. Regular expression | 1. Syntax analysis |
| Q. Pushdown automata | 2. Code generation |
| R. Dataflow analysis | 3. Lexical analysis |
| S. Register allocation | 4. Code Optimization |

- (A) P-4, Q-1, R-2, S-3
- (B) P-3, Q-1, R-4, S-2
- (C) P-3, Q-4, R-1, S-2
- (D) P-2, Q-1, R-4, S-3

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

| Item | Phase | Why |
|---|---|---|
| P. Regular expression | 3. Lexical analysis | Tokens are described by regular expressions and recognised by finite automata. |
| Q. Pushdown automata | 1. Syntax analysis | Parsers for context-free grammars are pushdown automata. |
| R. Dataflow analysis | 4. Code optimization | Optimizers use dataflow analysis (live variables, reaching definitions) to decide safe transformations. |
| S. Register allocation | 2. Code generation | Assigning values to machine registers is part of generating target code. |

So P-3, Q-1, R-4, S-2: (B).

- (A) pairs P with code optimization and S with lexical analysis.
- (C) pairs Q with code optimization and R with syntax analysis.
- (D) pairs P with code generation and S with lexical analysis.

Each of these wrong options breaks at least one pairing above.

**Code check:** none (matching of definitions, nothing to run).

**Classification note:** this question touches lexical analysis, parsing, optimization and code generation. I filed it under `intermediate-code-and-optimization` because two of the four pairs (R and S) belong to the back end, and listed `lexical-analysis` and `parsing` under `also`.

**Key idea:** regular expressions go with the lexer, pushdown automata with the parser, dataflow analysis with the optimizer, and register allocation with the code generator.

</details>
