# 2008 CS Q54: True statements about storage allocation and activation records

## Question

Which of the following are true?

- I. A programming language which does not permit global variables of any kind and has no nesting of procedures/functions, but permits recursion can be implemented with static storage allocation
- II. Multi-level access link (or display) arrangement is needed to arrange activation records only if the programming language being implemented has nesting of procedures/functions
- III. Recursion in programming languages cannot be implemented with dynamic storage allocation
- IV. Nesting of procedures/functions and recursion require a dynamic heap allocation scheme and cannot be implemented with a stack-based allocation scheme for activation records
- V. Programming languages which permit a function to return a function as its result cannot be implemented with a stack-based storage allocation scheme for activation records

Options:

- (A) II and V only
- (B) I, III and IV only
- (C) I, II and V only
- (D) I, III and V only

<summary>Answer</summary>

<details class="info" markdown="1">
<summary>Solution</summary>

**Official key:** the key table in the supplied PDF has no entry for Q54, so I cannot check against it. The answer below is my own derivation.

- **I. False.** Static allocation gives each procedure exactly one fixed frame. Recursion needs a *new* frame for every active call of the same procedure, so it needs dynamic (stack) allocation.
- **II. True.** Access links or a display are needed to reach non-local variables, and non-local access arises only when procedures can be nested.
- **III. False.** Recursion is implemented *with* dynamic storage allocation (a stack of activation records).
- **IV. False.** Nesting plus recursion works with a stack: Pascal-style languages use a stack of frames connected by static (access) links. No heap is required.
- **V. True.** If a function can be returned as a result (a closure), the frame holding its non-local variables must outlive the call that created it, so a pure stack discipline cannot be used.

So II and V only: (A).

- (B), (C) and (D) all contain I, which is false.

**Classification note:** runtime storage organisation is not listed as its own topic. I filed it under `intermediate-code-and-optimization`, as the earlier years' activation-record questions are.

**Key idea:** recursion needs stack-allocated frames, nesting needs access links, and returning functions breaks the pure stack model.
