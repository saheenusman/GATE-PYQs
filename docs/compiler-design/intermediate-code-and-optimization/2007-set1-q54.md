# 2007 CS Q54: Minimum MOV instructions for a basic block on a two-register machine

## Question

In a simplified computer the instructions are:

- `OP Rj, Ri` - Performs $R_j$ OP $R_i$ and stores the result in register $R_i$.
- `OP m, Ri` - Performs $val$ OP $R_i$ and stores the result in $R_i$. $val$ denotes the content of memory location $m$.
- `MOV m, Ri` - Moves the content of memory location $m$ to register $R_i$.
- `MOV Ri, m` - Moves the content of register $R_i$ to memory location $m$.

The computer has only two registers, and OP is either ADD or SUB. Consider the following basic block:

$$t_1 = a + b,\quad t_2 = c + d,\quad t_3 = e - t_2,\quad t_4 = t_1 - t_3$$

Assume that all operands are initially in memory. The final value of the computation should be in memory. What is the minimum number of MOV instructions in the code generated for this basic block?

- (A) 2
- (B) 3
- (C) 5
- (D) 6

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**A 3-MOV program:**

```
MOV c, R1     ; R1 = c            (MOV 1)
ADD d, R1     ; R1 = c + d = t2
SUB e, R1     ; R1 = e - t2 = t3
MOV a, R2     ; R2 = a            (MOV 2)
ADD b, R2     ; R2 = a + b = t1
SUB R2, R1    ; R1 = R2 - R1 = t1 - t3 = t4
MOV R1, t4    ; store result      (MOV 3)
```

`SUB e, R1` computes $e - R_1$ and `SUB R2, R1` computes $R_2 - R_1$, exactly the operand order needed. No intermediate value is spilled.

**Why not 2:** the result must be stored (one MOV). Both registers have to be initialised by a load before they can be an operand of an ALU instruction, and $t_1$ and $t_3$ are built independently and must meet in registers (or one of them must be spilled, which costs another MOV). With only one load there is nothing in the second register, so at least two loads plus the final store are needed: $\ge 3$.

So the minimum is $3$: (B).

- (A) 2 is impossible by the argument above.
- (C) 5 and (D) 6 are what you get by loading every operand and storing every temporary, which is wasteful.

**Code check:** Python Dijkstra search over (register 1, register 2, memory) states, where a value is an expression tree (operand order matters, no reassociation), values limited to the sub-expressions of $t_4$, and MOV costing 1: minimum cost 3 (1,028 states explored).

**Key idea:** keep intermediate results in registers and use the memory-operand form of ADD/SUB; only the loads of the two initial operands and the final store need MOVs.
