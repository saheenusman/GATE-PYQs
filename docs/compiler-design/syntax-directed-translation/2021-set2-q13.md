# 2021 CS2 Q13: Which compiler phase reports an undeclared type name

## Question

Consider the following ANSI C program:

```c
int main() {
    Integer x;
    return 0;
}
```

Which one of the following phases in a seven-phase C compiler will throw an error?

- (A) Lexical analyzer
- (B) Syntax analyzer
- (C) Semantic analyzer
- (D) Machine dependent optimizer

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

- **Lexical analyzer (A).** `Integer` is a valid identifier token and `x` is another, and `;` is a valid token. No error.
- **Syntax analyzer (B).** In C, an identifier can be a user-defined type name, so a pair of identifiers followed by `;` fits the declaration grammar (type name, then variable). The parser cannot tell, by grammar alone, that `Integer` was never declared as a type. No syntax error.
- **Semantic analyzer (C).** It looks up `Integer` in the symbol table, finds no type with that name, and reports "unknown type name". **This phase throws the error.**
- **Machine-dependent optimizer (D).** The program never reaches this phase.

So (C).

**Key idea:** the grammar accepts the shape of the declaration. The check that a type name actually exists is a semantic (symbol table) check.

</details>
