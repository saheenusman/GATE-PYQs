# 2016 CS1 Q46: Output order of a bottom-up parser using an SDTS

## Question

Consider the following Syntax Directed Translation Scheme (SDTS), with non-terminals $\lbrace S, A \rbrace$ and terminals $\lbrace a, b \rbrace$.

- $S \rightarrow aA \ \lbrace \text{print } 1 \rbrace$
- $S \rightarrow a \ \lbrace \text{print } 2 \rbrace$
- $A \rightarrow Sb \ \lbrace \text{print } 3 \rbrace$

Using the above SDTS, the output printed by a bottom-up parser, for the input $aab$ is:

- (A) 1 3 2
- (B) 2 2 3
- (C) 2 3 1
- (D) syntax error

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Each action sits at the **end** of its rule, so a bottom-up parser runs it when it **reduces** by that rule.

**Parse $aab$.** The rightmost derivation is

$$S \Rightarrow aA \Rightarrow aSb \Rightarrow aab$$

A bottom-up parser performs the reductions in the reverse order:

| Step | Reduction | Action |
|---|---|---|
| 1 | the second $a$ becomes $S$ by $S \to a$ | print 2 |
| 2 | $Sb$ becomes $A$ by $A \to Sb$ | print 3 |
| 3 | $aA$ becomes $S$ by $S \to aA$ | print 1 |

Output: $2\ 3\ 1$, which is **(C)**.

**Why the others fail.**

- (A) $1\,3\,2$ is the order of the rules in the derivation itself (top-down); a bottom-up parser fires them in reverse.
- (B) $2\,2\,3$ would need $S \to a$ to be reduced twice, but $aab$ uses it once.
- (D) $aab$ is in the language, so there is no syntax error.

**Key idea:** end-of-rule actions fire at reductions, which occur in reverse rightmost-derivation order.

</details>
