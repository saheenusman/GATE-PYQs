# 2019 CS2 Q46: Choosing attribute positions in an inherited-type grammar

## Question

Consider the following grammar and the semantic actions to support the inherited type declaration attributes. Let $X_1, X_2, X_3, X_4, X_5$, and $X_6$ be the placeholders for the non-terminals D, T, L or $L_1$ in the following table:

| Production rule | Semantic action |
|---|---|
| D → T L | $X_1$.type = $X_2$.type |
| T → int | T.type = int |
| T → float | T.type = float |
| L → $L_1$ , id | $X_3$.type = $X_4$.type; addType(id.entry, $X_5$.type) |
| L → id | addType(id.entry, $X_6$.type) |

Which one of the following are the appropriate choices for $X_1, X_2, X_3$ and $X_4$?

- (A) $X_1 = L,\ X_2 = T,\ X_3 = L_1,\ X_4 = L$
- (B) $X_1 = T,\ X_2 = L,\ X_3 = L_1,\ X_4 = T$
- (C) $X_1 = L,\ X_2 = L,\ X_3 = L_1,\ X_4 = T$
- (D) $X_1 = T,\ X_2 = L,\ X_3 = T,\ X_4 = L_1$

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

`T.type` is **synthesized** from the keyword (`int` or `float`). The type must then flow **down** to the identifiers in `L` as an **inherited** attribute.

**Rule $D \to T\,L$.** The type moves from $T$ (the left sibling) to $L$:

$$L.\text{type} = T.\text{type} \;\Rightarrow\; X_1 = L,\; X_2 = T.$$

**Rule $L \to L_1\,,\,\text{id}$.** The child $L_1$ inherits from its parent $L$:

$$L_1.\text{type} = L.\text{type} \;\Rightarrow\; X_3 = L_1,\; X_4 = L.$$

Then `addType(id.entry, L.type)` records the type, so $X_5 = X_6 = L$.

**Why the others fail:** (B), (C) and (D) either assign to $T$ (whose type comes only from its own keyword) or pass the type up or sideways in the wrong direction.

**Key idea:** an inherited attribute is computed from the parent or a left sibling and assigned to a child.

</details>
