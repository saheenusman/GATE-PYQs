# 2017 CS1 Q41: Which tuple relational calculus queries are safe

## Question

Consider a database that has the relation schemas EMP(EmpId, EmpName, DeptId), and DEPT(DeptName, DeptId). Note that the DeptId can be permitted to be NULL in the relation EMP. Consider the following queries on the database expressed in tuple relational calculus.

- (I) $\lbrace t \mid \exists u \in \text{EMP}\,(t[\text{EmpName}] = u[\text{EmpName}] \wedge \forall v \in \text{DEPT}\,(t[\text{DeptId}] \ne v[\text{DeptId}]))\rbrace$
- (II) $\lbrace t \mid \exists u \in \text{EMP}\,(t[\text{EmpName}] = u[\text{EmpName}] \wedge \exists v \in \text{DEPT}\,(t[\text{DeptId}] \ne v[\text{DeptId}]))\rbrace$
- (III) $\lbrace t \mid \exists u \in \text{EMP}\,(t[\text{EmpName}] = u[\text{EmpName}] \wedge \exists v \in \text{DEPT}\,(t[\text{DeptId}] = v[\text{DeptId}]))\rbrace$

Which of the above queries are safe?

- (A) (I) and (II) only
- (B) (I) and (III) only
- (C) (II) and (III) only
- (D) (I), (II) and (III)

<details class="success" markdown="1">
<summary>Answer</summary>

**D (official key). My analysis finds only (III) clearly safe, which is not an option: see the solution**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Safety.** A tuple calculus expression $\lbrace t \mid P(t)\rbrace$ is *safe* if every value in a result tuple comes from the domain of the expression, i.e. from the relations it mentions (or constants in it). A safe expression always returns a finite result.

**The official key: (D), all three safe.** The key treats the queries as safe because every quantifier is bounded by a stored relation (`EMP` or `DEPT`), and the result's `EmpName` is copied from an `EMP` tuple.

**My analysis disagrees on (I) and (II).** The tuple $t$ also has a `DeptId` component, and it is constrained there in a different way in each query:

| Query | Constraint on $t[\text{DeptId}]$ | Possible values |
|---|---|---|
| (I) | differs from *every* `DEPT.DeptId` | any other value: unbounded |
| (II) | differs from *some* `DEPT.DeptId` | almost any value: unbounded |
| (III) | equals *some* `DEPT.DeptId` | only values stored in `DEPT`: bounded |

In (I) and (II), $t[\text{DeptId}]$ is limited only by "not equal", so any value from an infinite domain that is not excluded, including values stored nowhere in the database, satisfies the condition and appears in the result. By the textbook definition those two queries are **not safe**, while (III) is. That combination, "(III) only", is not among the options.

So I record the key (D), and flag that its reading of safety is more lenient than the standard definition. Since the option set has no "(III) only", the question seems to rely on the "all quantifiers are bounded" reading.

**Code check:** as a model I took 2 employees and `DEPT` ids $\lbrace1,2,3\rbrace$, then counted result tuples $(\text{EmpName},\text{DeptId})$ when the `DeptId` domain has 10, 100 and 1000 values. (I) returned 14, 194, 1994 tuples; (II) returned 20, 200, 2000; (III) stayed at 6. The result sizes of (I) and (II) grow with the domain, while (III) does not.

**Status note:** marked `disputed` because my reading differs from the key on (I) and (II).

**Key idea:** a calculus query is safe only if each output component is forced into the database's own values; a "not equal" condition does not do that.

</details>
