# 2015 CS3 Q29: SQL condition to find theatres with the maximum capacity

## Question

Consider the following relation

*Cinema(theater, address, capacity)*

Which of the following options will be needed at the end of the SQL query

```sql
SELECT P1.address
FROM Cinema P1
```

such that it always finds the addresses of theaters with maximum capacity?

- (A) `WHERE P1.capacity >= All (select P2.capacity from Cinema P2)`
- (B) `WHERE P1.capacity >= Any (select P2.capacity from Cinema P2)`
- (C) `WHERE P1.capacity > All (select max(P2.capacity) from Cinema P2)`
- (D) `WHERE P1.capacity > Any (select max(P2.capacity) from Cinema P2)`

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

- `>= ALL (subquery)` is true when the row's capacity is at least **every** capacity in the table, which means it equals the maximum. Ties are kept because of `>=`. (A) is correct.
- (B) `>= ANY` is true when the capacity is at least **one** capacity. Every row is $\ge$ itself, so all theatres qualify.
- (C) `> ALL (max)` asks for a capacity *strictly greater* than the maximum, which no row has. It returns nothing.
- (D) `> ANY (max)`: the subquery returns one value, the maximum, so this is the same as (C). It returns nothing.

**Code check:** on a table with capacities 100, 250, 250, 80 (run in DuckDB, which supports `ALL` and `ANY`): (A) returned both 250-capacity theatres, (B) returned all four, (C) and (D) returned nothing.

**Key idea:** `>= ALL` selects the maximum; `>= ANY` is always true.

</details>
