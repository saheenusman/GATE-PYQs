# 2020 CS Q23: Rows returned by a join with an AVG subquery

## Question

Consider a relational database containing the following schemas.

![Three tables. Catalogue(sno, pno, cost) has 9 rows: S1 P1 150; S1 P2 50; S1 P3 100; S2 P4 200; S2 P5 250; S3 P1 250; S3 P2 150; S3 P5 300; S3 P4 250. Suppliers(sno, sname, location) has 3 rows: S1 M/s Royal furniture Delhi; S2 M/s Balaji furniture Bangalore; S3 M/s Premium furniture Chennai. Parts(pno, pname, part_spec) has 5 rows: P1 Table Wood; P2 Chair Wood; P3 Table Steel; P4 Almirah Steel; P5 Almirah Wood.](../../assets/2020/set1-q23.png)

The primary key of each table is indicated by underlining the constituent fields.

```sql
SELECT s.sno, s.sname
FROM   Suppliers s, Catalogue c
WHERE  s.sno = c.sno AND
       cost > (SELECT AVG (cost)
               FROM Catalogue
               WHERE pno = 'P4'
               GROUP BY pno);
```

The number of rows returned by the above SQL query is

- (A) 4
- (B) 5
- (C) 0
- (D) 2

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Step 1: the subquery.** Part P4 appears twice in Catalogue: supplier S2 at 200 and supplier S3 at 250.

$$\text{AVG(cost)} = \frac{200 + 250}{2} = 225.$$

The `GROUP BY pno` gives one group, so the subquery returns a single value, which is fine for a `>` comparison.

**Step 2: the join and filter.** Each Catalogue row is joined with its supplier. Keep the rows with cost $> 225$:

| sno | pno | cost | Kept? |
|---|---|---|---|
| S1 | P1 | 150 | no |
| S1 | P2 | 50 | no |
| S1 | P3 | 100 | no |
| S2 | P4 | 200 | no |
| S2 | P5 | 250 | **yes** |
| S3 | P1 | 250 | **yes** |
| S3 | P2 | 150 | no |
| S3 | P5 | 300 | **yes** |
| S3 | P4 | 250 | **yes** |

Four rows pass. The query has no `DISTINCT`, so the output keeps one row per Catalogue row:

| sno | sname |
|---|---|
| S2 | M/s Balaji furniture |
| S3 | M/s Premium furniture |
| S3 | M/s Premium furniture |
| S3 | M/s Premium furniture |

**4 rows.** I ran the query in SQLite on these tables and got 4 rows, with an average of 225.0.

**Why the others fail:**

- **(D) 2** is the number of *distinct* suppliers. It would be right only with `SELECT DISTINCT`.
- **(B) 5 and (C) 0** do not match the filter. The cost threshold removes five rows but keeps four.

**Key idea:** SQL keeps duplicate rows unless `DISTINCT` is used, so count rows, not suppliers.

</details>
