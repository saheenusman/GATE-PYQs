# 2014 CS2 Q30: Nested loop join: which relation should be the outer loop

## Question

Consider a join (relation algebra) between relations $r(R)$ and $s(S)$ using the nested loop method. There are 3 buffers each of size equal to disk block size, out of which one buffer is reserved for intermediate results. Assuming $size(r(R)) < size(s(S))$, the join will have fewer number of disk block accesses if

- (A) relation $r(R)$ is in the outer loop.
- (B) relation $s(S)$ is in the outer loop.
- (C) join selection factor between $r(R)$ and $s(S)$ is more than 0.5.
- (D) join selection factor between $r(R)$ and $s(S)$ is less than 0.5.

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Only 2 buffers remain: one for the outer relation and one for the inner. So the outer relation is read once, one block at a time, and the whole inner relation is scanned for **each** outer block:

$$\text{cost} = b_{outer} + b_{outer} \times b_{inner}$$

Let $b_r < b_s$.

- $r$ outer: $b_r + b_r b_s$
- $s$ outer: $b_s + b_s b_r$

The second is larger by $b_s - b_r > 0$, so the **smaller relation $r$ should be in the outer loop**: (A).

- (B) is the more expensive order.
- (C) and (D) the join selection factor changes the size of the result, which goes to the reserved output buffer. It does not change the number of block reads.

**Classification flag:** join cost is filed under `relational-algebra-and-sql`, with `indexing-and-file-organization` as the second topic.

**Key idea:** block nested loop join cost is $b_{outer} + b_{outer} b_{inner}$; the smaller relation goes outside.

</details>
