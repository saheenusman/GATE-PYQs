# 2025 CS2 Q54: Valid SQL for students enrolled in course 1470

## Question

Consider the following relational schema:

$Students(rollno: integer, name: string, age: integer, cgpa: real)$

$Courses(courseno: integer, cname: string, credits: integer)$

$Enrolled(rollno: integer, courseno: integer, grade: string)$

Which of the following options is/are correct SQL query/queries to retrieve the names of the students enrolled in course number (i.e., courseno) 1470?

**(A)**

```sql
SELECT S.name
FROM Students S
WHERE EXISTS (SELECT * FROM Enrolled E
              WHERE E.courseno = 1470
                AND E.rollno = S.rollno);
```

**(B)**

```sql
SELECT S.name
FROM Students S
WHERE SIZEOF (SELECT * FROM Enrolled E
              WHERE E.courseno = 1470
                AND E.rollno = S.rollno) > 0;
```

**(C)**

```sql
SELECT S.name
FROM Students S
WHERE 0 < (SELECT COUNT(*)
           FROM Enrolled E
           WHERE E.courseno = 1470
             AND E.rollno = S.rollno);
```

**(D)**

```sql
SELECT S.name
FROM Students S NATURAL JOIN Enrolled E
WHERE E.courseno = 1470;
```

<details class="success" markdown="1">
<summary>Answer</summary>

**A, C and D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

| Option | Verdict | Reason |
|---|---|---|
| **A** | Correct | A correlated `EXISTS`: keep a student if some enrolment row has that $rollno$ and $courseno = 1470$ |
| B | **Invalid** | `SIZEOF` is not an SQL function, so the query is a syntax error |
| **C** | Correct | A correlated scalar subquery counts the matching enrolments and keeps the student if the count is above 0 |
| **D** | Correct | $Students$ and $Enrolled$ share only $rollno$, so `NATURAL JOIN` joins on $rollno$, and the `WHERE` keeps course 1470 |

I loaded a small sample database into SQLite and ran all four. A, C and D returned the same names (the students enrolled in 1470). B failed with a syntax error.

**Key idea:** `EXISTS` and `COUNT(*) > 0` are the standard ways to test for the existence of related rows. `SIZEOF` does not exist in SQL.

</details>
