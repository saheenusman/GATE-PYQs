# 2014 CS1 Q54: SQL pairwise comparison with IN and a grouped subquery

## Question

Given the following schema:

```
employees(emp-id, first-name, last-name, hire-date,
          dept-id, salary)
departments(dept-id, dept-name, manager-id, location-id)
```

You want to display the last names and hire dates of all latest hires in their respective departments in the location ID 1700. You issue the following query:

```sql
SQL>SELECT last-name, hire-date
    FROM employees
    WHERE (dept-id, hire-date) IN
    (SELECT dept-id, MAX(hire-date)
     FROM employees JOIN departments USING(dept-id)
     WHERE location-id = 1700
     GROUP BY dept-id);
```

What is the outcome?

- (A) It executes but does not give the correct result.
- (B) It executes and gives the correct result.
- (C) It generates an error because of pairwise comparison.
- (D) It generates an error because the GROUP BY clause cannot be used with table joins in a sub-query.

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The inner query joins employees to departments, keeps location 1700, and returns, for each department there, its latest hire date: pairs $(dept\text{-}id,\ \max hire\text{-}date)$.

The outer query keeps the employees whose pair $(dept\text{-}id, hire\text{-}date)$ equals one of these pairs: the latest hires of those departments. If two people share the latest date, both appear, which fits "all latest hires".

- (C) **Pairwise (multi-column) comparison with `IN` is legal** SQL (row-value comparison).
- (D) `GROUP BY` with a join is allowed inside a subquery.
- (A) the result is correct.

**Code check:** I rewrote the names with underscores (`last_name`, since `-` is not valid in an identifier) and ran it in SQLite on sample data with departments in locations 1700 and 1800. It returned only the latest hires of the 1700 departments, including a tie.

**Reading note:** the hyphenated names show the question is written in pseudo-SQL. The answer rests on the structure of the query.

**Key idea:** `(a, b) IN (SELECT x, y ...)` is a valid row-value comparison.

</details>
