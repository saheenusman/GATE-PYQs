# 2018 CS Q51: Which query is not equivalent to a select-join

## Question

Consider the relations $r(A, B)$ and $s(B, C)$, where $s.B$ is a primary key and $r.B$ is a foreign key referencing $s.B$. Consider the query

$$Q:\ r \bowtie (\sigma_{B<5}(s))$$

Let $LOJ$ denote the natural left outer-join operation. Assume that $r$ and $s$ contain no null values.

Which one of the following queries is NOT equivalent to $Q$?

- (A) $\sigma_{B<5}(r \bowtie s)$
- (B) $\sigma_{B<5}(r\ LOJ\ s)$
- (C) $r\ LOJ\ (\sigma_{B<5}(s))$
- (D) $\sigma_{B<5}(r)\ LOJ\ s$

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Key fact.** Because $r.B$ is a foreign key to $s.B$, **every** tuple of $r$ has a matching tuple in $s$. So $r\ LOJ\ s = r \bowtie s$ (no padding with NULLs).

$Q$ returns the tuples of $r$ with $B<5$, joined with their $s$-tuple.

- **A:** join first, then filter on $B<5$: the same tuples.
- **B:** $LOJ$ equals the join here, then filter: the same.
- **D:** filter $r$ first, then $LOJ$ with $s$. Every remaining tuple matches, so no NULLs appear: the same.
- **C:** $\sigma_{B<5}(s)$ removes tuples of $s$ with $B\ge5$. A tuple of $r$ with $B\ge5$ now has no match, but a left outer join *keeps it* with $C = \text{NULL}$. So the result has extra tuples that $Q$ does not: **not equivalent**.

The answer is **C**.

**Code check:** on 2000 random instances in SQLite that respected the primary-key and foreign-key constraints, A, B and D always matched $Q$; C differed in 1383 of them.

**Key idea:** a left outer join keeps all left tuples, so filtering the right side first (option C) leaves unmatched, NULL-padded rows.

</details>
