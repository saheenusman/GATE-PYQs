# 2013 CS Q35: Equivalent queries for course 107

## Question

Consider the following relational schema.

- Students(<u>rollno</u>: integer, sname: string)
- Courses(<u>courseno</u>: integer, cname: string)
- Registration(<u>rollno</u>: integer, <u>courseno</u>: integer, percent: real)

Which of the following queries are equivalent to this query in English?
"Find the distinct names of all students who score more than 90% in the course numbered 107"

(I)
```sql
SELECT DISTINCT S.sname
FROM Students AS S, Registration AS R
WHERE R.rollno = S.rollno AND R.courseno = 107 AND R.percent > 90
```

(II) $\pi_{sname}\left(\sigma_{courseno = 107 \wedge percent > 90}(Registration \bowtie Students)\right)$

(III) $\lbrace T \mid \exists S \in Students,\ \exists R \in Registration\ (S.rollno = R.rollno \wedge R.courseno = 107 \wedge R.percent > 90 \wedge T.sname = S.sname) \rbrace$

(IV) $\lbrace \langle S_N \rangle \mid \exists S_R\, \exists R_P\ (\langle S_R, S_N \rangle \in Students \wedge \langle S_R, 107, R_P \rangle \in Registration \wedge R_P > 90) \rbrace$

- (A) I, II, III and IV
- (B) I, II and III only
- (C) I, II and IV only
- (D) II, III and IV only

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

All four compute: names of students $s$ for which some registration row has the same `rollno`, `courseno = 107` and `percent > 90`, with duplicates removed.

- **(I)** SQL join on `rollno` with both filters; `DISTINCT` removes duplicate names.
- **(II)** The natural join matches on the only common attribute, `rollno`. Then select on course and percentage, and project `sname` (projection removes duplicates in relational algebra).
- **(III)** Tuple relational calculus: the same join condition and filters, returning the `sname`. A calculus result is a set, so no duplicates.
- **(IV)** Domain relational calculus: the variable $S_R$ ties the Students row to the Registration row (second component fixed to 107), with $R_P > 90$.

So all four are equivalent: (A).

**Why the others fail:** (B), (C) and (D) each leave one correct formulation out.

**Code check:** the four formulations (SQL run in SQLite, and the other three evaluated directly) agreed on 300 random databases.

**Key idea:** SQL, relational algebra, TRC and DRC can all express a select-project-join; check that the join condition, filters and duplicate removal match.

</details>
