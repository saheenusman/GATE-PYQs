# 2020 CS Q46: A table in 3NF but not in BCNF

## Question

Consider a relational table $R$ that is in 3NF, but not in BCNF. Which one of the following statements is TRUE?

- (A) $R$ has a nontrivial functional dependency $X \to A$, where $X$ is not a superkey and $A$ is a prime attribute.
- (B) $R$ has a nontrivial functional dependency $X \to A$, where $X$ is not a superkey and $A$ is a non-prime attribute and $X$ is not a proper subset of any key.
- (C) $R$ has a nontrivial functional dependency $X \to A$, where $X$ is not a superkey and $A$ is a non-prime attribute and $X$ is a proper subset of some key.
- (D) A cell in $R$ holds a set instead of an atomic value.

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**The two definitions.** For every nontrivial FD $X \to A$ in $R$:

- **BCNF** requires: $X$ is a superkey.
- **3NF** requires: $X$ is a superkey, **or** $A$ is a prime attribute (part of some candidate key).

**Apply to $R$.**

- $R$ is **not in BCNF**, so some nontrivial FD $X \to A$ has $X$ **not a superkey**.
- $R$ **is in 3NF**, so that same FD must meet the other 3NF clause: $A$ is **prime**.

That is exactly statement (A).

**Why the others fail:**

- **(B)** and **(C)** have $X$ not a superkey and $A$ *non-prime*. That violates 3NF. (B) is a transitive dependency and (C) is a partial dependency, so $R$ would not be in 3NF.
- **(D)** says a cell holds a set, which violates 1NF. A table in 3NF is already in 1NF.

**Key idea:** the only gap between 3NF and BCNF is an FD whose right side is a prime attribute but whose left side is not a superkey.

</details>
