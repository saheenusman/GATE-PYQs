# 2026 CS1 Q31: Dependency-preserving decompositions

## Question

In the context of relational database normalization, which of the following statements is/are true?

- (A) It is always possible to obtain a dependency-preserving 3NF decomposition of a relation
- (B) It is always possible to obtain a dependency-preserving 1NF decomposition of a relation
- (C) It is not always possible to obtain a dependency-preserving BCNF decomposition of a relation
- (D) It is not always possible to obtain a dependency-preserving 2NF decomposition of a relation

<details class="success" markdown="1">
<summary>Answer</summary>

**A, B and C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Refresher.** A decomposition is *dependency-preserving* if every functional dependency of the original relation can be checked inside one of the new relations, without joining them.

| Normal form | Dependency-preserving decomposition always possible? |
|---|---|
| 3NF | **Yes.** The 3NF synthesis algorithm gives a lossless, dependency-preserving decomposition into 3NF. |
| 1NF | **Yes.** The relation itself already satisfies every dependency (and in practice relations are in 1NF by definition). Keeping the relation as it is preserves all dependencies. |
| BCNF | **Not always.** The classic example is $R(A,B,C)$ with $AB \to C$ and $C \to B$: the only BCNF decomposition loses $AB \to C$. |
| 2NF | **Yes.** Every 3NF decomposition is also in 2NF, so the 3NF synthesis result works. |

So:

- (A) true,
- (B) true,
- (C) true,
- (D) false, because a dependency-preserving 2NF decomposition always exists (use the 3NF one).

**Key idea:** the standard result is that 3NF is always dependency-preserving and lossless, while BCNF is always lossless but may lose dependencies.

</details>
