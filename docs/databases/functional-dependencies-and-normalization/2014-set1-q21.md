# 2014 CS1 Q21: Key of a relation from functional dependencies

## Question

Consider the relation scheme $R = (E, F, G, H, I, J, K, L, M, N)$ and the set of functional dependencies $\lbrace \lbrace E,F \rbrace \to \lbrace G \rbrace,\ \lbrace F \rbrace \to \lbrace I,J \rbrace,\ \lbrace E,H \rbrace \to \lbrace K,L \rbrace,\ \lbrace K \rbrace \to \lbrace M \rbrace,\ \lbrace L \rbrace \to \lbrace N \rbrace \rbrace$ on $R$. What is the key for $R$?

- (A) $\lbrace E,F \rbrace$
- (B) $\lbrace E,F,H \rbrace$
- (C) $\lbrace E,F,H,K,L \rbrace$
- (D) $\lbrace E \rbrace$

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

$E$, $F$ and $H$ never appear on a right-hand side, so every key must contain them. Compute the closure of $\lbrace E,F,H \rbrace$:

| Step | Using | Adds |
|---|---|---|
| 1 | $EF \to G$ | $G$ |
| 2 | $F \to IJ$ | $I, J$ |
| 3 | $EH \to KL$ | $K, L$ |
| 4 | $K \to M$ | $M$ |
| 5 | $L \to N$ | $N$ |

$\lbrace E,F,H \rbrace^+ = $ all ten attributes. It is also minimal, so it is the key.

- (A) $\lbrace E,F \rbrace^+ = \lbrace E,F,G,I,J \rbrace$. It lacks $H, K, L, M, N$.
- (C) is a superkey but not minimal; $K, L$ are already derived from $E,H$.
- (D) $\lbrace E \rbrace^+ = \lbrace E \rbrace$ only.

**Code check:** a closure program over all attribute subsets finds `EFH` as the only candidate key.

**Key idea:** start from attributes that appear on no right-hand side, then check the closure.

</details>
