# 2025 CS2 Q46: 3NF check on two schemas

## Question

Consider the following relational schema along with all the functional dependencies that hold on them.

$R_1(A, B, C, D, E)$: $\lbrace D \to E,\ EA \to B,\ EB \to C\rbrace$

$R_2(A, B, C, D)$: $\lbrace A \to D,\ A \to B,\ C \to A\rbrace$

Which of the following statement(s) is/are TRUE?

- (A) $R_1$ is in 3NF
- (B) $R_2$ is in 3NF
- (C) $R_1$ is NOT in 3NF
- (D) $R_2$ is NOT in 3NF

<details class="success" markdown="1">
<summary>Answer</summary>

**C and D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

A relation is in 3NF if for every FD $X \to Y$ (with $Y \not\subseteq X$), either $X$ is a **superkey** or every attribute of $Y$ is **prime** (part of some candidate key).

**$R_1(A,B,C,D,E)$.**

- $AD^+ = \lbrace A, D, E, B, C\rbrace$ (from $D \to E$, then $EA \to B$, then $EB \to C$), so $AD$ is a key. Neither $A$ nor $D$ alone is, so the only key is $AD$ and the prime attributes are $A, D$.
- $D \to E$: $D$ is not a superkey and $E$ is **not prime**. This violates 3NF.

So $R_1$ is **not** in 3NF.

**$R_2(A,B,C,D)$.**

- $C^+ = \lbrace C, A, D, B\rbrace$ (from $C \to A \to D, B$), so $C$ is a key. $C$ never appears on a right-hand side, so it is in every key: the only key is $C$, and the only prime attribute is $C$.
- $A \to D$: $A$ is not a superkey and $D$ is **not prime**. This violates 3NF.

So $R_2$ is **not** in 3NF.

I confirmed the keys and the violating FDs with an attribute-closure computation.

| Option | Verdict |
|---|---|
| A | False |
| B | False |
| **C** | True |
| **D** | True |

**Key idea:** list the candidate keys by closure, then check each FD: a non-superkey determinant must determine only prime attributes.

</details>
