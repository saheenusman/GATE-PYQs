# 2017 CS2 Q17: When can the table for relationship R be merged into the table of entity A

## Question

An ER model of a database consists of entity types A and B. These are connected by a relationship R which does not have its own attribute. Under which one of the following conditions, can the relational table for R be merged with that of A?

- (A) Relationship R is one-to-many and the participation of A in R is total.
- (B) Relationship R is one-to-many and the participation of A in R is partial.
- (C) Relationship R is many-to-one and the participation of A in R is total.
- (D) Relationship R is many-to-one and the participation of A in R is partial.

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**When can R's table be folded into A's table?** R's own table has the keys of A and B. It can be merged into A's table by adding B's key as a **foreign key column in A**. That works only if each $A$-tuple has **exactly one** related $B$-tuple.

- **Many-to-one** (many $A$ to one $B$) means each $A$ is related to at most one $B$, so one extra column in $A$ suffices.
- **Total participation** of A means every $A$ is related to some $B$, so that column is never NULL.

Both together give **(C)**.

**Why the others fail.**

- (A) and (B): one-to-many means one $A$ can relate to *several* $B$, so one column in $A$ cannot hold them. Such a relationship is merged into $B$'s table instead.
- (D): many-to-one is fine, but with partial participation some $A$ have no partner, so the merged column would contain NULLs. The standard textbook rule merges only when participation is total, which is why the key asks for it. (With a nullable foreign key the merge is still possible, but that is not the expected answer.)

**Status note:** no program applies; the answer matches the official key.

**Key idea:** a many-to-one relationship with total participation on the "many" side is absorbed into that side's table as a non-null foreign key.

</details>
