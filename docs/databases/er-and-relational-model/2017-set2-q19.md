# 2017 CS2 Q19: Cascading deletes and SET NULL with mutual foreign keys

## Question

Consider the following tables T1 and T2.

| P | Q |
|---|---|
| 2 | 2 |
| 3 | 8 |
| 7 | 3 |
| 5 | 8 |
| 6 | 9 |
| 8 | 5 |
| 9 | 8 |

(table **T1**, columns P and Q)

| R | S |
|---|---|
| 2 | 2 |
| 8 | 3 |
| 3 | 2 |
| 9 | 7 |
| 5 | 7 |
| 7 | 2 |

(table **T2**, columns R and S)

In table T1, P is the primary key and Q is the foreign key referencing R in table T2 with on-delete cascade and on-update cascade. In table T2, R is the primary key and S is the foreign key referencing P in table T1 with on-delete set NULL and on-update cascade. In order to delete record $\langle 3, 8\rangle$ from table T1, the number of additional records that need to be deleted from table T1 is ______.

<details class="success" markdown="1">
<summary>Answer</summary>

**0**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Deleting $\langle 3,8\rangle$ from T1 removes the key value $P = 3$.**

Who refers to $P=3$? Only T2's foreign key $S$ (T2 is the *child* of T1 through $S \to P$). T2 rows with $S = 3$: just $\langle 8, 3\rangle$.

- The rule on T2.S is **on delete SET NULL**. So that row is **not deleted**; its $S$ becomes NULL: $\langle 8, \text{NULL}\rangle$.

**Does that trigger anything in T1?** T1's foreign key $Q$ references $R$ in T2 (T1 is the *child* of T2 through $Q \to R$). A cascade into T1 would need an $R$ value to be deleted or updated. Here only $S$ changed; $R = 8$ still exists. So nothing cascades back to T1.

**Result:** 0 additional records are deleted from T1.

**Common slip:** reading "on-delete cascade" on $Q$ as "deleting a T1 row deletes related T2 rows". Cascade runs from the **parent** to the **child**, not the other way round. Deleting the T1 row $\langle 3,8\rangle$ does not touch T2 through $Q$.

**Code check:** a small script over the two tables found that the only T2 row with $S = 3$ is $\langle 8,3\rangle$ (so it is the only row affected by the delete). The rule on it is SET NULL, so no row is removed from either table.

**Key idea:** referential actions flow from the referenced (parent) table to the referencing (child) table; `SET NULL` does not delete.

</details>
