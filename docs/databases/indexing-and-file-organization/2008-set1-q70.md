# 2008 CS Q70: Blocks in a multi-level secondary index

## Question

Consider a file of 16384 records. Each record is 32 bytes long and its key field is of size 6 bytes. The file is ordered on a non-key field, and the file organization is unspanned. The file is stored in a file system with block size 1024 bytes, and the size of a block pointer is 10 bytes. If the secondary index is built on the key field of the file, and a multi-level index scheme is used to store the secondary index, the number of first-level and second-level blocks in the multi-level index are respectively

- (A) 8 and 0
- (B) 128 and 6
- (C) 256 and 4
- (D) 512 and 5

<details class="info" markdown="1">
<summary>Solution</summary>

**Official key:** the key table in the supplied PDF has no entry for Q70, so I cannot check against it. The answer below is my own derivation.

A secondary index on a key field is **dense**: one entry for every record, because the file is not ordered on that field.

- Index entry size: key + block pointer $= 6 + 10 = 16$ bytes.
- Entries per index block: $\lfloor 1024 / 16 \rfloor = 64$.
- **First level:** $16384$ entries $/ 64 = 256$ blocks.
- **Second level:** one entry for each first-level block, so $256$ entries $/ 64 = 4$ blocks.

So the numbers are $256$ and $4$: (C). (The third level would be one block, and the process stops there.)

- (A) 8 and 0 and (B) 128 and 6 do not follow from 16-byte entries.
- (D) 512 is the number of *data* blocks ($16384 / 32$ records per block), not index blocks.

**Code check:** a short script gave $32$ records per block, $64$ entries per index block, $256$ first-level and $4$ second-level blocks.

**Key idea:** a secondary index on a key has one entry per record, and each higher level has one entry per block of the level below.
