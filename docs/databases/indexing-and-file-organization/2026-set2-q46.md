# 2026 CS2 Q46: Dense and sparse indexes

## Question

An index is **dense** if an index entry appears for every search-key value in the indexed file. Otherwise it is **sparse**. Consider:

- S1: A hash index must be a dense index.
- S2: A $B^+$ tree index can be a sparse index.

Which option is correct?

- (A) Both S1 and S2 are true
- (B) Both S1 and S2 are false
- (C) S1 is true and S2 is false
- (D) S1 is false and S2 is true

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**S1 is true.** A hash index finds a record by hashing its key. The hash function sends a key to a bucket, and the bucket must contain an entry for **each** key to find it. There is no sorted order to "skip ahead" from, so a hash index cannot be sparse.

**S2 is true.** A $B^+$ tree can be built as a *sparse* (primary, clustering) index over a file that is **sorted** on the search key: it stores one entry per data block, and a lookup finds the right block and scans it. A $B^+$ tree can also be dense (one entry per key), so both are possible.

**Dense vs sparse:**

| | Needs sorted file? | Entries |
|---|---|---|
| Dense | no | one per key |
| Sparse | yes | one per block |

Both statements are true, which is **(A)**.

**Key idea:** sparse indexes rely on sorted order (so they suit trees, not hashing).

</details>
