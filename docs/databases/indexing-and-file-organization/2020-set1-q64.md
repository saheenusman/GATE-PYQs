# 2020 CS Q64: Disk accesses to search a B+ tree

## Question

Consider a database implemented using B+ tree for file indexing and installed on a disk drive with block size of 4 KB. The size of search key is 12 bytes and the size of tree/disk pointer is 8 bytes. Assume that the database has one million records. Also assume that no node of the B+ tree and no records are present initially in main memory. Consider that each record fits into one disk block. The minimum number of disk accesses required to retrieve any record in the database is ______.

<details class="success" markdown="1">
<summary>Answer</summary>

**4**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

"Minimum" means we want the shortest tree, so every node is filled as much as possible. Block size is $4096$ bytes.

**Internal node** with $p$ child pointers and $p - 1$ keys:

$$8p + 12(p - 1) \le 4096 \;\Rightarrow\; 20p \le 4108 \;\Rightarrow\; p = 205.$$

**Leaf node** with $k$ (key, record pointer) pairs and one next-leaf pointer:

$$20k + 8 \le 4096 \;\Rightarrow\; k = 204.$$

**Levels for $10^6$ records:**

| Level | Nodes |
|---|---|
| Leaves | $\lceil 10^6 / 204 \rceil = 4902$ |
| Level above | $\lceil 4902 / 205 \rceil = 24$ |
| Root | $\lceil 24 / 205 \rceil = 1$ |

Two levels are not enough: a root with 205 children reaches at most $205 \times 204 = 41820$ records. So the tree has 3 levels.

**Accesses for one lookup.**

- Root: 1
- Middle node: 1
- Leaf: 1
- Data block holding the record: 1

Total: $3 + 1 = 4$. No node is cached, as the question states.

I recomputed the fan-outs and level sizes in code and got 205, 204, 4902, 24 and 1.

**Key idea:** the height of a B+ tree is the number of levels needed to cover all keys at maximum fan-out. Add one more access for the data block.

</details>
