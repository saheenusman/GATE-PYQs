# 2009 CS Q44: Maximum number of leaf splits in a B+ tree

## Question

The following key values are inserted into a B+ tree in which order of the internal nodes is 3, and that of the leaf nodes is 2, in the sequence given below. The order of internal nodes is the maximum number of tree pointers in each node, and the order of leaf nodes is the maximum number of data items that can be stored in it. The B+ tree is initially empty.

$10, 3, 6, 8, 4, 2, 1$

The maximum number of times leaf nodes would get split up as a result of these insertions is

- (A) 2
- (B) 3
- (C) 4
- (D) 5

<summary>Solution</summary>

**Status: disputed.** The supplied key accepts (A) 2 or (B) 3. My own count gives (D) 5 as the maximum. Both follow.

**Setting.** A leaf holds at most $2$ keys. Inserting a third key makes it overflow and it splits into two leaves ($1 + 2$ keys or $2 + 1$ keys, the rule is not given). Splits of internal nodes do not change how many **leaf** splits happen, so only the leaf level matters.

**Count.** Seven keys must be stored, so at the end there are between $4$ leaves ($2+2+2+1$) and $6$ leaves ($7$ keys, each leaf has at least $1$). Every leaf split adds one leaf, starting from one, so the number of leaf splits is between $3$ and $5$. Both ends happen, depending on the split rule:

| Rule on overflow | Leaves at the end | Leaf splits |
|---|---|---|
| left leaf keeps 2 keys | $[1,2]\ [3]\ [4]\ [6]\ [8]\ [10]$ | 5 |
| left leaf keeps 1 key | $[1,2]\ [3,4]\ [6]\ [8,10]$ | 3 |

Trace for "left leaf keeps 2" (the usual textbook rule, splitting a full leaf of 3 keys as $2 + 1$):

| Insert | Leaves after | Split? |
|---|---|---|
| 10, 3 | $[3,10]$ | no |
| 6 | $[3,6]\ [10]$ | #1 |
| 8 | $[3,6]\ [8]\ [10]$ | #2 |
| 4 | $[3,4]\ [6]\ [8]\ [10]$ | #3 |
| 2 | $[2,3]\ [4]\ [6]\ [8]\ [10]$ | #4 |
| 1 | $[1,2]\ [3]\ [4]\ [6]\ [8]\ [10]$ | #5 |

The question asks for the **maximum** number of leaf splits, which is $5$: (D).

**What the key says.** (A) 2 or (B) 3.

- **(A) 2 is impossible under any rule.** Seven keys cannot fit in $3$ leaves of capacity $2$, so at least $3$ splits are needed.
- **(B) 3 is the minimum, not the maximum.** It is reached only with the "left keeps 1" rule above.
- (C) 4 is also possible under some choices of split, but it is not the largest.

I record the key's answer and flag the conflict rather than choosing for it.

**Code check:** a program tried every possible split choice (left keeps $1$ or $2$ keys, at every overflow) and found the number of leaf splits can be $3$, $4$ or $5$, never $2$. The two fixed rules gave $5$ (left keeps $2$) and $3$ (left keeps $1$).

**Key idea:** each leaf split adds exactly one leaf, so the number of splits is $(\text{final leaves}) - 1$; with $7$ keys and capacity $2$ that lies between $3$ and $5$.
