# 2024 CS2 Q26: File organizations that are efficient for a full scan

## Question

Which of the following file organizations is/are I/O efficient for the scan operation in DBMS?

- (A) Sorted
- (B) Heap
- (C) Unclustered tree index
- (D) Unclustered hash index

<details class="success" markdown="1">
<summary>Answer</summary>

**A and B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

A **scan** reads every record.

- **Heap file:** records are packed in pages, so a scan reads each data page once. Efficient.
- **Sorted file:** also packed in pages (in key order), so a scan reads each data page once. Efficient.
- **Unclustered tree index / unclustered hash index:** the data file is not in index order, so following the index fetches records in an order that jumps between pages. In the worst case that is **one page I/O per record**, much worse than a plain scan.

**Key idea:** a full scan is cheap when records are packed contiguously. Unclustered indexes help selective lookups, not scans.

</details>
