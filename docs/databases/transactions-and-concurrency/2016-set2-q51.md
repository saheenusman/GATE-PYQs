# 2016 CS2 Q51: Recoverability and cascading aborts in a two-transaction schedule

## Question

Consider the following database schedule with two transactions, $T_1$ and $T_2$.

$$S = r_2(X);\ r_1(X);\ r_2(Y);\ w_1(X);\ r_1(Y);\ w_2(X);\ a_1;\ a_2$$

where $r_i(Z)$ denotes a read operation by transaction $T_i$ on a variable $Z$, $w_i(Z)$ denotes a write operation by transaction $T_i$ on a variable $Z$ and $a_i$ denotes an abort by transaction $T_i$.

Which one of the following statements about the above schedule is TRUE?

- (A) S is non-recoverable
- (B) S is recoverable, but has a cascading abort
- (C) S does not have a cascading abort
- (D) S is strict

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Look for reads of data written by a transaction that has not yet finished ("dirty reads").

| Step | Operation | Reads data written by another transaction? |
|---|---|---|
| 1 | $r_2(X)$ | no, initial value |
| 2 | $r_1(X)$ | no, initial value ($T_2$ has not written yet) |
| 3 | $r_2(Y)$ | no |
| 4 | $w_1(X)$ | (write) |
| 5 | $r_1(Y)$ | no, nobody wrote $Y$ |
| 6 | $w_2(X)$ | (write after $T_1$'s uncommitted write) |

No transaction ever reads a value written by the other, so there is no "reads-from" relation.

- **Recoverable:** trivially, with no reads-from, yes. So (A) is false.
- **No cascading abort:** nobody read dirty data, so aborting $T_1$ does not force $T_2$ to abort. So **(C) is true** and (B) is false.
- **Not strict:** $w_2(X)$ overwrites $T_1$'s uncommitted write to $X$ (before $a_1$). A strict schedule forbids that, so (D) is false.

**Code check:** scanning the schedule in code found no reads-from pairs and flagged $w_2(X)$ as an overwrite of an uncommitted write.

**Key idea:** no transaction reads the other's data, so no cascading abort; the blind overwrite makes it non-strict.

</details>
