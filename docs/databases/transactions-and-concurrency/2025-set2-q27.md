# 2025 CS2 Q27: Which ACID properties a lost-update audit shows violated

## Question

An audit of a banking transactions system has found that on an earlier occasion, two joint holders of account $A$ attempted simultaneous transfers of Rs. 10000 each from account $A$ to account $B$. Both transactions read the same value, Rs. 11000, as the initial balance in $A$ and were allowed to go through. $B$ was credited Rs. 10000 twice. $A$ was debited only once and ended up with a balance of Rs. 1000.

Which of the following properties is/are certain to have been violated by the system?

- (A) Atomicity
- (B) Consistency
- (C) Isolation
- (D) Durability

<details class="success" markdown="1">
<summary>Answer</summary>

**B and C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

This is a **lost update**: both transactions read the old balance 11000 and the second write overwrote the first debit.

| Property | Violated? | Reason |
|---|---|---|
| Atomicity | Not certain | Each transfer seems to have run fully (the credit to $B$ happened). Nothing says a transaction was half done and left behind |
| **Consistency** | **Yes** | Rs. 10000 was created from nothing: the total of $A$ and $B$ increased by 10000. The database moved from a valid state to an invalid one |
| **Isolation** | **Yes** | Both transactions read the same initial value, so they interfered. The outcome is not equal to any serial execution (a serial run would end with $A$ refusing the second transfer, or at balance $-9000$) |
| Durability | No | No committed result was lost after a failure |

**Key idea:** a lost update means concurrent transactions were not isolated, and the resulting state breaks the account-total invariant (consistency).

</details>
