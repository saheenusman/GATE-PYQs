# 2010 CS Q20: Which protocols give conflict serializability and freedom from deadlock

## Question

Which of the following concurrency control protocols ensure both conflict serializability and freedom from deadlock?

- I. 2-phase locking
- II. Time-stamp ordering

- (A) I only
- (B) II only
- (C) Both I and II
- (D) Neither I nor II

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

- **Two-phase locking (I):** guarantees conflict serializability, but transactions wait for locks, so a cycle of waiting transactions (a deadlock) can occur.
- **Timestamp ordering (II):** guarantees conflict serializability because transactions are ordered by timestamp. A transaction that would break the order is aborted and restarted instead of waiting, so no transaction ever waits and no deadlock arises.

Only II has both properties: (B).

- (A) is wrong because 2PL can deadlock.
- (C) fails for the same reason.
- (D) is wrong because timestamp ordering has both.

**Key idea:** 2PL waits (so it can deadlock); timestamp ordering aborts instead of waiting (so it cannot).

</details>
