# 2014 CS2 Q29: Conflict serializability and recoverability of a 4-transaction schedule

## Question

Consider the following schedule **S** of transactions T1, T2, T3, T4, listed in time order:

| Step | Transaction | Operation |
|---|---|---|
| 1 | T2 | Reads(X) |
| 2 | T3 | Writes(X), Commit |
| 3 | T1 | Writes(X), Commit |
| 4 | T2 | Writes(Y), Reads(Z), Commit |
| 5 | T4 | Reads(X), Reads(Y), Commit |

Which one of the following statements is CORRECT?

- (A) S is conflict-serializable but not recoverable
- (B) S is not conflict-serializable but is recoverable
- (C) S is both conflict-serializable and recoverable
- (D) S is neither conflict-serializable nor is it recoverable

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Conflict serializability.** Precedence edges from conflicting operations on the same item:

| Item | Conflicts in time order | Edges |
|---|---|---|
| X | r2, w3, w1, r4 | $T_2 \to T_3$, $T_2 \to T_1$, $T_3 \to T_1$, $T_2 \to T_4$, $T_3 \to T_4$, $T_1 \to T_4$ |
| Y | w2, r4 | $T_2 \to T_4$ |

No cycle. The only topological order is $T_2, T_3, T_1, T_4$, so S is conflict-serializable.

**Recoverability.** A transaction must not commit before one it read from. $T_4$ reads X from $T_1$ and Y from $T_2$, and both have already committed before $T_4$ reads. No other transaction reads a value written by another. So S is recoverable (it even avoids cascading aborts).

**Code check:** a precedence-graph check finds the single order (2, 3, 1, 4), and a reads-from check finds only $(T_4, T_1)$ and $(T_4, T_2)$, both committed first.

Both properties hold: **C**.

**Key idea:** serializable iff the precedence graph is acyclic; recoverable iff readers commit after the writers they read from.

</details>
