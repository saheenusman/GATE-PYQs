# 2025 CS1 Q15: Which transactions roll back after T1 aborts

## Question

A schedule of three database transactions $T_1$, $T_2$, and $T_3$ is shown. $R_i(A)$ and $W_i(A)$ denote read and write of data item $A$ by transaction $T_i$, $i = 1,2,3$. The transaction $T_1$ aborts at the end. Which other transaction(s) will be required to be rolled back?

$$R_1(X)\ \ W_1(Y)\ \ R_2(X)\ \ R_2(Y)\ \ R_3(Y)\ \ ABORT(T_1)$$

- (A) Only $T_2$
- (B) Only $T_3$
- (C) Both $T_2$ and $T_3$
- (D) Neither $T_2$ nor $T_3$

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

When $T_1$ aborts, every transaction that read **uncommitted data written by $T_1$** (a *dirty read*) must also roll back: a **cascading rollback**.

| Step | What it means |
|---|---|
| $W_1(Y)$ | $T_1$ writes $Y$ and has not committed |
| $R_2(Y)$ | $T_2$ reads $Y$: a **dirty read** of $T_1$'s value |
| $R_3(Y)$ | $T_3$ reads $Y$: also a **dirty read** |
| $R_2(X)$ | $T_1$ only **read** $X$, never wrote it, so this read is harmless |

Both $T_2$ and $T_3$ depend on $T_1$'s write and must be rolled back.

| Option | Why wrong |
|---|---|
| A | Forgets that $T_3$ also read $Y$ |
| B | Forgets that $T_2$ also read $Y$ |
| D | Both transactions read a value that is now invalid |

**Key idea:** reading data written by an uncommitted transaction creates a dependency, so its abort cascades to the readers.

</details>
