# 2012 CS Q27: Interleavings of two transactions on P and Q

## Question

Consider the following transactions with data items $P$ and $Q$ initialized to zero:

```
T1: read(P);
    read(Q);
    if P = 0 then Q := Q + 1;
    write(Q).

T2: read(Q);
    read(P);
    if Q = 0 then P := P + 1;
    write(P).
```

Any **non-serial** interleaving of T1 and T2 for concurrent execution leads to

- (A) a serializable schedule
- (B) a schedule that is not conflict serializable
- (C) a conflict serializable schedule
- (D) a schedule for which a precedence graph cannot be drawn

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Why every non-serial schedule has a cycle.** "Non-serial" means neither transaction runs completely before the other starts. So:

- T2's first operation $r_2(Q)$ comes before T1's last operation $w_1(Q)$. Read then write on $Q$ gives the edge $T_2 \to T_1$.
- T1's first operation $r_1(P)$ comes before T2's last operation $w_2(P)$. Read then write on $P$ gives the edge $T_1 \to T_2$.

The precedence graph has both edges, a cycle, so the schedule is **not conflict serializable**: (B).

**Not even serializable.** Both transactions read the initial zeros, so both take the `if` branch, and the final state is $P = Q = 1$. The serial orders give $(P,Q) = (0,1)$ for T1 then T2, and $(1,0)$ for T2 then T1. The result $(1,1)$ matches neither.

- (A), (C) are false for that reason.
- (D) a precedence graph can always be drawn for a schedule.

**Code check:** of the $\binom{6}{3} = 20$ interleavings, 2 are serial. All 18 non-serial ones had a cycle in the precedence graph.

**Key idea:** if each transaction's first operation conflicts with the other's last, any overlap forms a cycle.

</details>
