# 2020 CS Q17: Regular expression for binary strings with an odd number of 1s

## Question

Which one of the following regular expressions represents the set of all binary strings with an odd number of 1's?

- (A) `((0+1)*1(0+1)*1)*10*`
- (B) `(0*10*10*)*0*1`
- (C) `10*(0*10*10*)*`
- (D) `(0*10*10*)*10*`

<details class="success" markdown="1">
<summary>Answer</summary>

**MTA (marks awarded to all; the key names no single option)**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Official key:** *MTA*, i.e. marks to all. My own check agrees that the question is faulty: **none of the four expressions is correct.**

**The idea behind the options.** The block `0*10*10*` holds exactly two 1s, so `(0*10*10*)*` is any string with an even number of 1s. Adding one more 1 gives an odd count. But the extra 1 must be allowed to have 0s on **both** sides, and every option misses that.

| Option | Counterexample | What goes wrong |
|---|---|---|
| (A) | `1111` accepted, `01` rejected | The block `(0+1)*1(0+1)*1` can hold *any* number of 1s from 2 up, so the parity is not controlled. It accepts four 1s. It also rejects `01`. |
| (B) | `10` rejected | The string must end in 1, so any odd string ending in 0 is missed. |
| (C) | `01` rejected | The string must start with 1, so leading 0s are missed. |
| (D) | `01` and `010` rejected | The lone 1 is written as `10*`, with no 0s allowed before it. Leading 0s are only allowed inside a pair of 1s. |

**Code check.** I compared each expression with the definition "number of 1s is odd" on **every** binary string up to length 12. All four disagree on many strings (A: 4028, B: 2047, C: 2047, D: 66).

**A correct expression** is `(0*10*10*)*0*10*`, with 0s allowed on both sides of the extra 1. It matches the definition on all strings up to length 12.

**Why this is marked verified.** The key says MTA, and the check shows that no option is correct, which is the reason for awarding marks to all. There is no single option to compare against.

**Key idea:** to count parity with a regular expression, pair the 1s in blocks of two, and allow arbitrary 0s around the one leftover 1.
