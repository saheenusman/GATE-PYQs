# 2020 CS Q20: Is L = {a^n} ∪ {a^n b^n} deterministic context-free, and LL(k)?

## Question

Consider the language $L = \lbrace a^n \mid n \ge 0 \rbrace \cup \lbrace a^n b^n \mid n \ge 0 \rbrace$ and the following statements.

- I. $L$ is deterministic context-free.
- II. $L$ is context-free but not deterministic context-free.
- III. $L$ is not LL($k$) for any $k$.

Which of the above statements is/are TRUE?

- (A) I only
- (B) II only
- (C) I and III only
- (D) III only

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Statement I is true: there is a deterministic PDA.** Push one symbol for each `a`. When the first `b` arrives, start popping one symbol per `b`.

- If the input ends while still reading only a's, accept. This handles $a^n$.
- If the input ends after the b's, accept only when the stack is empty. This handles $a^n b^n$.

No guessing is needed, because the machine always knows which situation it is in from the input read so far. So $L$ is deterministic context-free, and **statement II is false** (it contradicts I).

**Statement III is true: no fixed lookahead suffices.** A natural grammar is

$$S \to A \mid B,\qquad A \to aA \mid \varepsilon,\qquad B \to aBb \mid \varepsilon.$$

A top-down parser must pick $A$ or $B$ at the very start. Both alternatives begin with $a$, and the first symbol where the two kinds of string differ comes *after* all the a's. With $n$ a's, the parser needs $n+1$ symbols of lookahead, and $n$ is unbounded. So for any $k$, the strings $a^{k+1}$ and $a^{k+1}b^{k+1}$ look the same through the first $k$ symbols but need different choices. This is the standard example of a deterministic context-free language that is not LL($k$) for any $k$.

**Why the other options fail:**

- **(A) I only** misses III.
- **(B) II only** is false because I is true.
- **(D) III only** misses I.

**Note on the proof.** Statement I comes from the explicit PDA above. Statement III rests on the standard lookahead argument given here, not on a program.

**Key idea:** a language can be deterministic context-free (an LR-style parser can handle it) yet need unbounded lookahead for top-down LL parsing.

</details>
