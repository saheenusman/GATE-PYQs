# 2020 CS Q54: Maximum R-type opcodes in a 16-bit instruction format

## Question

A processor has 64 registers and uses 16-bit instruction format. It has two types of instructions: I-type and R-type. Each I-type instruction contains an opcode, a register name, and a 4-bit immediate value. Each R-type instruction contains an opcode and two register names. If there are 8 distinct I-type opcodes, then the maximum number of distinct R-type opcodes is ______.

<details class="success" markdown="1">
<summary>Answer</summary>

**14**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Field sizes.** 64 registers need 6 bits per register name.

| Type | Fields | Opcode bits left |
|---|---|---|
| I-type | opcode + 6 (register) + 4 (immediate) | $16 - 10 = 6$ |
| R-type | opcode + 6 + 6 (two registers) | $16 - 12 = 4$ |

So I-type opcodes are 6 bits and R-type opcodes are 4 bits. The decoder must tell the two types apart from the opcode bits alone (an *expanding opcode* scheme), so no 6-bit I-type opcode may begin with a 4-bit pattern that is used as an R-type opcode.

**Count the 4-bit patterns that I-type uses up.** There are $2^4 = 16$ patterns for the first 4 bits. Each such pattern is the prefix of $2^2 = 4$ different 6-bit patterns. To hold 8 I-type opcodes in as few prefixes as possible, pack them into whole groups:

$$\left\lceil \frac{8}{4} \right\rceil = 2 \text{ prefixes}.$$

**R-type opcodes** can use all the remaining prefixes:

$$16 - 2 = 14.$$

**Assumption.** The count is a maximum because the 8 I-type opcodes are packed into 2 prefixes. Spread over more prefixes, they would leave fewer for R-type.

**Key idea:** in an expanding-opcode design, a shorter opcode uses up every longer opcode that begins with it.

</details>
