# 2008 CS Q37: Memory accesses saved by overlapping register windows

## Question

The use of multiple register windows with overlap causes a reduction in the number of memory accesses for

- I. function locals and parameters
- II. register saves and restores
- III. instruction fetches

Options:

- (A) I only
- (B) II only
- (C) III only
- (D) I, II and III

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

With overlapping register windows, each procedure call moves to a new window, and the **outgoing registers of the caller are the incoming registers of the callee**.

- **I. Reduced.** Parameters are passed in the overlapping registers instead of being pushed on the stack, and local variables live in the window's registers instead of in a stack frame. Both memory traffic sources shrink.
- **II. Not the main effect.** A window change replaces the usual save and restore of registers around a call, but registers still have to be spilled to memory when the window file overflows, and reloaded when it underflows. The key does not count II.
- **III. Not affected.** Instruction fetches are the same, since the same instructions are executed.

So the key selects I only: (A).

**Caveat.** Statement II is the arguable one: avoiding a save and restore on every call is a real benefit of register windows. (A) is the key's answer and the best match among the options, since (D) wrongly includes III and there is no "I and II" option.

**Classification note:** register windows are filed under `pipelining` as in earlier years. They are an architectural feature at the edge of instruction-set design.

**Key idea:** register windows turn parameter passing and local storage into register accesses instead of memory accesses.

</details>
