# 2026 CS1 Q16: Dependency that causes a data hazard

## Question

Which one of the following dependencies among the register operands of different instructions can cause a data hazard in a pipelined processor?

- (A) Read-after-read
- (B) Read-after-write
- (C) Write-after-read
- (D) Write-after-write

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Refresher.** A data hazard happens when a later instruction needs a value an earlier one has not yet produced.

- **(A) RAR: no hazard.** Two reads never conflict.
- **(B) RAW: hazard.** This is a *true* dependency. The later instruction reads a register before the earlier one has written it. Fixed by forwarding or a stall.
- **(C) WAR and (D) WAW** are *name* dependencies. In a simple in-order pipeline where writes happen in order at the last stage, they cannot go wrong. They matter only when instructions can be reordered (out-of-order execution), and are then removed by register renaming.

So the one that causes a data hazard in a pipelined processor is RAW.

**Key idea:** RAW is the true data hazard; WAR and WAW arise only with reordering.

</details>
