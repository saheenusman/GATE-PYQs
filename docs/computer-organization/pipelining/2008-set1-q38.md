# 2008 CS Q38: Earliest point at which the data TLB can be accessed

## Question

In an instruction execution pipeline, the earliest that the data TLB (Translation Lookaside Buffer) can be accessed is

- (A) before effective address calculation has started
- (B) during effective address calculation
- (C) after effective address calculation has completed
- (D) after data cache lookup has completed

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The TLB translates a **virtual address of the data** into a physical address. That virtual address is the **effective address** of the load or store, which only exists once the address calculation (base + offset, and so on) has **finished**. So the earliest the data TLB can be accessed is right **after effective address calculation completes**: (C).

- (A) and (B) are impossible: the address to translate is not yet known.
- (D) is later than necessary: the TLB lookup does not have to wait for the data cache lookup (and a physically tagged cache needs the translation *before* its tag compare).

**Classification note:** this question is about when memory translation fits into the pipeline stages. I filed it under `pipelining`, with `cache-and-memory` as a related topic.

**Key idea:** translation needs the effective address, so the TLB access starts as soon as that address has been computed.

</details>
