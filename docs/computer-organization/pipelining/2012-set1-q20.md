# 2012 CS Q20: Why pipelined processors use register renaming

## Question

Register renaming is done in pipelined processors

- (A) as an alternative to register allocation at compile time
- (B) for efficient access to function parameters and local variables
- (C) to handle certain kinds of hazards
- (D) as part of address translation

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Register renaming maps the registers named in instructions onto a larger pool of physical registers. This removes false dependencies (write-after-read and write-after-write), so those hazards no longer stall the pipeline. It is (C).

- (A) false. Renaming happens in hardware and works alongside compile-time allocation; it does not replace it.
- (B) false. Fast access to parameters and locals is the job of register windows or the stack.
- (D) false. Address translation is done by the MMU and TLB.

**Key idea:** renaming removes WAR and WAW (false) hazards; true RAW dependencies remain.

</details>
