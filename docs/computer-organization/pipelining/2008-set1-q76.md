# 2008 CS Q76: What a delayed conditional branch always executes

## Question

Delayed branching can help in the handling of control hazards. (Common statement for Q.76 and Q.77.)

For all delayed conditional branch instructions, irrespective of whether the condition evaluates to true or false,

- (A) the instruction following the conditional branch instruction in memory is executed
- (B) the first instruction in the fall through path is executed
- (C) the first instruction in the taken path is executed
- (D) the branch takes longer to execute than any other instruction

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

In a delayed branch the instruction in the **branch delay slot**, the one **right after the branch in memory**, is always executed, whether or not the branch is taken. The branch itself takes effect one instruction later. So (A).

- (B) holds only if the slot happens to be filled with an instruction from the fall-through path. A compiler may fill it from before the branch or from the target, so this is not guaranteed.
- (C) is not guaranteed: the first instruction at the target runs only if the branch is taken, and then only after the delay slot.
- (D) is false: the whole point of the delay slot is that the branch does not slow things down.

**Key idea:** the delay-slot instruction (the one after the branch in memory) always executes.

</details>
