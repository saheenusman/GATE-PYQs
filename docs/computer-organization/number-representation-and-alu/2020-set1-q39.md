# 2020 CS Q39: IEEE-754 single precision division of 0x42200000 by 0xC1200000

## Question

Consider three registers R1, R2, and R3 that store numbers in IEEE-754 single precision floating point format. Assume that R1 and R2 contain the values (in hexadecimal notation) 0x42200000 and 0xC1200000, respectively.

If $R3 = \dfrac{R1}{R2}$, what is the value stored in R3?

- (A) 0x40800000
- (B) 0xC0800000
- (C) 0x83400000
- (D) 0xC8500000

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Format.** Single precision is 1 sign bit, 8 exponent bits (bias 127) and 23 fraction bits. The value is $(-1)^s \times 1.f \times 2^{e-127}$.

**Decode R1 = 0x42200000.** Binary: `0 10000100 01000000000000000000000`.

- sign $= 0$, exponent $= 132 \Rightarrow 132 - 127 = 5$, mantissa $= 1.01_2 = 1.25$
- value $= 1.25 \times 2^5 = 40$

**Decode R2 = 0xC1200000.** Binary: `1 10000010 01000000000000000000000`.

- sign $= 1$, exponent $= 130 \Rightarrow 3$, mantissa $= 1.25$
- value $= -1.25 \times 2^3 = -10$

**Divide:** $40 / (-10) = -4 = -1.0 \times 2^2$.

**Encode $-4$.** Sign $= 1$. Exponent $= 2 + 127 = 129 = 10000001_2$. Fraction $= 0$. So the bits are

`1 10000001 00000000000000000000000` $=$ `1100 0000 1000 0000 ...` $=$ **0xC0800000**.

I confirmed this by unpacking the two registers as floats, dividing, and repacking the result: it gives $-4.0$ and `0xC0800000`.

**Why the others fail:**

- **(A) 0x40800000** is $+4.0$: right size, wrong sign. The operands have opposite signs, so the quotient is negative.
- **(C) 0x83400000** decodes to about $-5.6 \times 10^{-37}$, and **(D) 0xC8500000** decodes to $-212992$. Neither is close to $-4$.

**Key idea:** decode each value, do the arithmetic, then re-encode. The sign of a quotient is the XOR of the operand signs.

</details>
