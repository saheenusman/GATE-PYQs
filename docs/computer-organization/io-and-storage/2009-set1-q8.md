# 2009 CS Q8: When the CPU services an interrupt

## Question

A CPU generally handles an interrupt by executing an interrupt service routine

- (A) as soon as an interrupt is raised.
- (B) by checking the interrupt register at the end of fetch cycle.
- (C) by checking the interrupt register after finishing the execution of the current instruction.
- (D) by checking the interrupt register at fixed time intervals.

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

A CPU looks at its interrupt register at the **end of each instruction**. If an interrupt is pending, it saves the context (such as the program counter) and jumps to the interrupt service routine. The current instruction is always completed first, so the machine state is consistent when the routine starts: (C).

- (A) is wrong: acting the moment the interrupt is raised could leave an instruction half executed.
- (B) is wrong: the fetch cycle is only the first part of an instruction, so the instruction would be left unfinished.
- (D) is wrong: the check is tied to instruction boundaries, not to a timer.

**Code check:** none (conceptual question).

**Key idea:** interrupts are recognised between instructions, after the current one finishes.

</details>
