# 2018 CS Q19: Order of events after a device raises an interrupt

## Question

The following are some events that occur after a device controller issues an interrupt while process L is under execution.

- (P) The processor pushes the process status of L onto the control stack.
- (Q) The processor finishes the execution of the current instruction.
- (R) The processor executes the interrupt service routine.
- (S) The processor pops the process status of L from the control stack.
- (T) The processor loads the new PC value based on the interrupt.

Which one of the following is the correct order in which the events above occur?

- (A) QPTRS
- (B) PTRSQ
- (C) TRPQS
- (D) QTPRS

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Sequence on an interrupt:**

1. **Q:** the processor finishes the current instruction. Interrupts are checked between instructions.
2. **P:** it saves the state of L (PC and status) on the control stack, so L can resume later.
3. **T:** it loads the PC with the address of the interrupt service routine (from the interrupt vector).
4. **R:** it executes the service routine.
5. **S:** on return, it pops the saved state of L and resumes it.

Order: **Q P T R S**.

**Why the others fail:**
- **B** and **C** save or load before finishing the current instruction, or finish it last.
- **D** loads the new PC (T) *before* saving the state (P), so the return address would be lost.

**Key idea:** always save the old context before switching the PC to the handler.

</details>
