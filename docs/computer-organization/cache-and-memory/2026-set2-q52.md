# 2026 CS2 Q52: Hits and misses in a direct mapped cache

## Question

Consider a system with a processor and a 4 KB direct mapped cache with block size of 16 bytes. The system has a 16 MB physical memory. Four words P, Q, R, and S are accessed by the processor in the same order 10 times, i.e. a total of 40 references in the sequence P, Q, R, S, P, Q, R, S, ...

Assume that the cache memory is initially empty. The physical addresses of the words are (1 word = 1 byte):

P: `0x845B32`  Q: `0x845B26`  R: `0x845B36`  S: `0x846B32`

Which of the following statements is/are true?

- (A) Every access to P results in a cache miss
- (B) Every access to R results in a cache hit
- (C) Every access to Q results in a cache miss
- (D) Except the first access to S, all subsequent accesses to S result in cache hits

<details class="success" markdown="1">
<summary>Answer</summary>

**A and B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Split (24-bit address):** cache has $4096/16 = 256$ lines. Offset 4 bits, index 8 bits, tag 12 bits.

| Word | Address | Tag | Index | Offset |
|---|---|---|---|---|
| P | `845B32` | `845` | `B3` | 2 |
| Q | `845B26` | `845` | `B2` | 6 |
| R | `845B36` | `845` | `B3` | 6 |
| S | `846B32` | `846` | `B3` | 2 |

- P and R are in the **same block** (`845B3x`).
- S uses the **same line** `B3` but a different tag, so it evicts that block.
- Q uses its own line `B2` and is never evicted.

**Trace (line B3 holds block X = 845B3x or Y = 846B3x):**

| Access | Line B3 before | Result |
|---|---|---|
| P | empty | miss, loads X |
| R | X | hit |
| S | X | miss, loads Y |
| P (next round) | Y | miss, loads X |
| R | X | hit |

The pattern repeats every round.

- (A) True: P always finds Y (S's block) and misses.
- (B) True: R always follows P, so X is there.
- (C) False: Q misses only on its first access, then hits 9 times.
- (D) False: S always finds X (P and R's block) and misses every time.

**Key idea:** blocks that share an index but differ in tag evict each other (conflict misses).

</details>
