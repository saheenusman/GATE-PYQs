# 2008 CS Q73: Cache hit ratio of the array initialisation loop

## Question

(Same setting as Q.71.) The cache hit ratio for this initialization loop is

- (A) 0%
- (B) 25%
- (C) 50%
- (D) 75%

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The loop writes the array in **row-major order**, one `double` (8 bytes) at a time, so the accesses are sequential. A block is 16 bytes, so it holds **2 consecutive elements**:

- the first access to a block is a **miss** (the block is brought in);
- the second access to the same block is a **hit**.

So half of the accesses hit: $50\%$. No block is reused after leaving the cache, so there are no other hits. This is (C).

- (A) 0% would be the case if each block held one element.
- (D) 75% would need 4 elements per block ($1$ miss in $4$ accesses); (B) 25% matches no block size here.

**Code check:** a 2-way LRU, write-allocate simulation of all $1{,}048{,}576$ accesses gave $524{,}288$ hits and $524{,}288$ misses: hit ratio $0.5$. (This assumes the cache allocates a block on a write miss, as the question implies by counting the stores.)

**Key idea:** with sequential access, hit ratio $= 1 - \dfrac{1}{\text{elements per block}}$.

</details>
