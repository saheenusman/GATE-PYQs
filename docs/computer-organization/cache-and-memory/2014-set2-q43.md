# 2014 CS2 Q43: Effect of cache block size

## Question

In designing a computer's cache system, the cache block (or cache line) size is an important parameter. Which one of the following statements is correct in this context?

- (A) A smaller block size implies better spatial locality
- (B) A smaller block size implies a smaller cache tag and hence lower cache tag overhead
- (C) A smaller block size implies a larger cache tag and hence lower cache hit time
- (D) A smaller block size incurs a lower cache miss penalty

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Fix the capacity and the address width. A smaller block means fewer offset bits and more blocks.

- (A) false: a bigger block brings in more neighbouring words per miss and so exploits spatial locality better. A smaller block exploits less.
- (B) false: tag bits $= $ address $-$ index $-$ offset. With fewer offset bits the tag gets **larger**, and there are more blocks, so the tag overhead goes **up**.
- (C) the tag does get larger, but a larger tag makes the comparison **slower**, not the hit time lower.
- (D) **true:** a miss fetches only one small block, so less data is moved from memory and the miss penalty is lower.

**Key idea:** block size trades spatial locality and tag overhead against miss penalty: smaller blocks cut the penalty but raise the miss rate and tag cost.

</details>
