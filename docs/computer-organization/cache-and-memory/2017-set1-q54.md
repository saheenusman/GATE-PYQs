# 2017 CS1 Q54: TAG field length when a direct-mapped cache becomes 16-way set-associative

## Question

A cache memory unit with capacity of $N$ words and block size of $B$ words is to be designed. If it is designed as a direct mapped cache, the length of the TAG field is 10 bits. If the cache unit is now designed as a 16-way set-associative cache, the length of the TAG field is ______ bits.

<details class="success" markdown="1">
<summary>Answer</summary>

**14**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Address split.** An address has three parts: TAG, SET (index), and BLOCK OFFSET.

- The block offset depends only on $B$, which is unchanged.
- The number of cache blocks is $N/B$ in both designs.

**Direct mapped.** The number of sets equals the number of blocks, $N/B$. So

$$\text{TAG}_{\text{DM}} = \text{address bits} - \log_2(N/B) - \log_2 B = 10$$

**16-way set-associative.** Each set holds 16 blocks, so the number of sets drops to $N/(16B)$. The index shrinks by $\log_2 16 = 4$ bits. Those 4 bits move into the tag:

$$\text{TAG} = 10 + 4 = 14$$

The answer is **14**.

**Key idea:** every doubling of associativity removes one index bit and adds one tag bit.

</details>
