# 2008 CS Q35: Necessary conditions for cache inclusion

## Question

For inclusion to hold between two cache levels L1 and L2 in a multi-level cache hierarchy, which of the following are necessary?

- I. L1 must be a write-through cache
- II. L2 must be a write-through cache
- III. The associativity of L2 must be greater than that of L1
- IV. The L2 cache must be at least as large as the L1 cache

Options:

- (A) IV only
- (B) I and IV only
- (C) I, III and IV only
- (D) I, II, III and IV

<details class="success" markdown="1">
<summary>Answer</summary>

**B** (official key; see the Solution: disputed)

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Status: disputed.** The official key is (B), I and IV. I get (A), IV only. Both views follow.

**What inclusion means.** Every block present in L1 must also be present in L2.

**Key's view.** The key argues that L1 must be write-through, because in a write-through cache every write goes to the next level, and so concludes that I and IV are necessary.

**My view.**

- **IV is necessary.** If L2 holds a copy of everything in L1, then L2 cannot be smaller than L1.
- **I is not necessary.** Inclusion is about which blocks are *present*, not whether their data is up to date. A write-back L1 can still be included in L2: the L2 block is simply stale until the dirty L1 block is written back. Inclusive hierarchies with write-back L1 caches exist.
- **II is not necessary** for the same reason.
- **III is not necessary.** Inclusion can always be enforced, whatever the associativities, by invalidating the L1 copy whenever L2 evicts a block.

So only IV is necessary: (A). The key's (B) mixes up inclusion (which blocks are present) with write policy (when data is propagated). I record the key and mark the question disputed.

**Key idea:** inclusion requires only that L2 can hold everything in L1; it does not fix the write policy.

</details>
