# 2018 CS Q44: Tag field length of a K-way set-associative cache

## Question

The size of the physical address space of a processor is $2^P$ bytes. The word length is $2^W$ bytes. The capacity of cache memory is $2^N$ bytes. The size of each cache block is $2^M$ words. For a $K$-way set-associative cache memory, the length (in number of bits) of the tag field is

- (A) $P - N - \log_2 K$
- (B) $P - N + \log_2 K$
- (C) $P - N - M - W - \log_2 K$
- (D) $P - N - M - W + \log_2 K$

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Split the $P$-bit address into tag, set index and block offset.**

- **Block size** $= 2^M$ words $\times 2^W$ bytes $= 2^{M+W}$ bytes, so the block offset is $M+W$ bits.
- **Number of blocks** $= 2^N / 2^{M+W} = 2^{N-M-W}$.
- **Number of sets** $= $ blocks $/K = 2^{N-M-W-\log_2K}$, so the index is $N-M-W-\log_2K$ bits.

**Tag:**

$$P - (N-M-W-\log_2K) - (M+W) = P - N + \log_2 K$$

So the answer is **B**.

**Why the others fail:** A subtracts $\log_2K$ instead of adding it (more ways means fewer sets and a *longer* tag). C and D subtract $M+W$ a second time.

**Key idea:** tag $=$ address bits $-$ index bits $-$ offset bits; the offset cancels, leaving $P - N + \log_2 K$.

</details>
