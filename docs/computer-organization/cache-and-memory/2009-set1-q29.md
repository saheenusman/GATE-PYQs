# 2009 CS Q29: Block missing from a 4-way set associative cache under LRU

## Question

Consider a 4-way set associative cache (initially empty) with total 16 cache blocks. The main memory consists of 256 blocks and the request for memory blocks is in the following order:

$0, 255, 1, 4, 3, 8, 133, 159, 216, 129, 63, 8, 48, 32, 73, 92, 155$

Which one of the following memory block will NOT be in cache if LRU replacement policy is used?

- (A) 3
- (B) 8
- (C) 129
- (D) 216

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

$16$ blocks in $4$-way sets give $16/4 = 4$ sets. Memory block $b$ goes to set $b \bmod 4$. Each set holds $4$ blocks and evicts the least recently used one.

| Set | Requests mapping to it, in order | Final contents |
|---|---|---|
| 0 | 0, 4, 8, 216, 8 (hit), 48, 32, 92 | 8, 48, 32, 92 |
| 1 | 1, 133, 129, 73 | 1, 133, 129, 73 |
| 2 | none | empty |
| 3 | 255, 3, 159, 63, 155 | 3, 159, 63, 155 |

- Set 0 is full after $0, 4, 8, 216$. Then $8$ is a hit. $48$ evicts $0$, $32$ evicts $4$, and $92$ evicts $216$ (now the least recently used).
- Set 3 is full after $255, 3, 159, 63$. Then $155$ evicts $255$.

So block $216$ has been evicted and is not in the cache: (D).

- (A) $3$ is in set 3. (B) $8$ is in set 0. (C) $129$ is in set 1. All three are still in the cache.

**Code check:** an LRU simulation with $4$ sets of $4$ ways gave final contents $\lbrace 8, 48, 32, 92 \rbrace$, $\lbrace 1, 133, 129, 73 \rbrace$, empty, $\lbrace 3, 159, 63, 155 \rbrace$. Only $216$ of the four options was missing.

**Key idea:** split the blocks by set (block mod number of sets), then apply LRU inside each set separately.

</details>
