# 2024 CS1 Q53: Write-back versus write-through caches

## Question

Consider two set-associative cache memory architectures: WBC, which uses the write back policy, and WTC, which uses the write through policy. Both of them use the LRU (Least Recently Used) block replacement policy. The cache memory is connected to the main memory. Which of the following statements is/are TRUE?

- (A) A read miss in WBC never evicts a dirty block
- (B) A read miss in WTC never triggers a write back operation of a cache block to main memory
- (C) A write hit in WBC can modify the value of the dirty bit of a cache block
- (D) A write miss in WTC always writes the victim cache block to main memory before loading the missed block to the cache

<details class="success" markdown="1">
<summary>Answer</summary>

**B and C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

- **(A) False.** A WBC read miss may pick a **dirty** block as the LRU victim, and then that block is written back before it is evicted.
- **(B) True.** In a write-through cache every write goes to memory immediately, so blocks are never dirty and there is nothing to write back on eviction.
- **(C) True.** A write hit in a write-back cache updates only the cache and sets the dirty bit (possibly from 0 to 1).
- **(D) False.** In WTC the victim is always clean (memory already has its data), so it is never written to memory on a miss.

**Key idea:** write-back keeps dirty blocks and writes them on eviction. Write-through has no dirty blocks.

</details>
