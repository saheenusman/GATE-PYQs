# 2026 CS2 Q56: Maximum direct mapped cache size from one mapping

## Question

Consider a system with 1 MB physical memory and a word length of 1 byte. The system uses a direct mapped cache, with block numbers starting from 0. The word with physical address `0xA2C28` is mapped to the cache block number $176_{10}$. The maximum possible size of the cache (in KB) for this configuration is ________. (answer in integer)

*Note:* $1\text{K} = 2^{10}$ and $1\text{M} = 2^{20}$

*(The block number is 176 in decimal. The extracted text of the PDF shows it as 17610, but the page image reads $176_{10}$.)*

<details class="success" markdown="1">
<summary>Answer</summary>

**128**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Address bits** (20 bits, bit 19 to bit 0):

`1010 0010 1100 0010 1000`

The cache **index** field is the block number, so it must equal $176 = 10110000_2$.

**Where can that pattern sit?** Look for `10110000` in the address: it appears at **bits 13 to 6**.

- The index must start at bit 6, so the offset has 6 bits and the **block size is 64 B**.
- The index can grow upward only while it still equals 176. Bits 14, 15 and 16 are `0`, so they can be added without changing the value. Bit 17 is `1`, which would change it.
- Maximum index: bits 16 to 6, which is **11 bits** (2048 lines).

**Max cache size** $= 2048 \times 64\text{ B} = 128\text{ KB}$.

Then tag $= 20 - 11 - 6 = 3$ bits.

I also checked by script: block size 64 is the only one that works, with 256 to 2048 lines.

**Key idea:** the index field is a slice of the address. The widest slice that still equals the given block number gives the biggest cache.

</details>
