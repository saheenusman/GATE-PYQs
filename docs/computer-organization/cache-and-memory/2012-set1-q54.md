# 2012 CS Q54: Tag bits in a 4-way set associative cache

## Question

**Statement for Linked Answer Questions 54 and 55.** A computer has a $256$ KByte, $4$-way set associative, write back data cache with block size of $32$ Bytes. The processor sends $32$ bit addresses to the cache controller. Each cache tag directory entry contains, in addition to address tag, $2$ valid bits, $1$ modified bit and $1$ replacement bit.

The number of bits in the tag field of an address is

- (A) 11
- (B) 14
- (C) 16
- (D) 27

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

- Number of blocks: $256\text{ KB} / 32\text{ B} = 2^{18} / 2^{5} = 2^{13} = 8192$.
- Number of sets: $8192 / 4 = 2^{11} = 2048$, so the **index** is $11$ bits.
- Block offset: $32 = 2^5$ bytes, so $5$ bits.
- Tag: $32 - 11 - 5 = 16$ bits.

This is (C).

- (A) $11$ is the index width.
- (B) $14$ would need $13$ bits of index, which belongs to a direct-mapped cache.
- (D) $27 = 32 - 5$ is the tag of a fully associative cache (no index).

**Code check:** the arithmetic gave 8192 blocks, 2048 sets, 11 index bits, 5 offset bits and a 16-bit tag.

**Key idea:** tag $=$ address bits $-$ index bits $-$ offset bits.

</details>
