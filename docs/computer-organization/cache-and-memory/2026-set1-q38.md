# 2026 CS1 Q38: Tag bits: direct mapped vs set associative

## Question

The size of the physical address space of a processor is $2^{32}$ bytes. The capacity of a cache memory unit is $2^{23}$ bytes. The cache block size is 128 bytes. The cache memory unit can be built as a direct mapped cache or as a $K$-way set-associative cache, where $K = 2^L$ and $L \in \lbrace 1, 2, 3 \rbrace$. Let the length of the TAG field be $M$ bits for the direct mapped cache, and $N$ bits for the set-associative cache.

Which one of the following options is true?

- (A) $N = M + L$
- (B) $N = M - L$
- (C) $N = M + K$
- (D) $N = M - K$

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Direct mapped:**

- Blocks in cache $= 2^{23} / 2^7 = 2^{16}$.
- Offset $= 7$ bits, index $= 16$ bits.
- Tag $M = 32 - 16 - 7 = \mathbf{9}$.

**$K$-way set associative ($K = 2^L$):**

- Sets $= 2^{16} / 2^L = 2^{16-L}$, so index $= 16 - L$ bits.
- Tag $N = 32 - (16 - L) - 7 = 9 + L$.

So $N = M + L$.

| $L$ | Index | $N$ |
|---|---|---|
| 0 (direct) | 16 | 9 |
| 1 | 15 | 10 |
| 2 | 14 | 11 |
| 3 | 13 | 12 |

**Why the others fail:** (B) and (D) subtract, but fewer sets means *more* tag bits. (C) and (D) use $K$ instead of $L$, but each doubling of $K$ adds exactly one tag bit.

**Key idea:** doubling associativity halves the sets, which removes one index bit and adds one tag bit.

</details>
