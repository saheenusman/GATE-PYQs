# 2019 CS2 Q11: Tag and index bits in a fully associative cache

## Question

A certain processor uses a fully associative cache of size 16 kB. The cache block size is 16 bytes. Assume that the main memory is byte addressable and uses a 32-bit address. How many bits are required for the *Tag* and the *Index* fields respectively in the addresses generated by the processor?

- (A) 24 bits and 0 bits
- (B) 28 bits and 4 bits
- (C) 24 bits and 4 bits
- (D) 28 bits and 0 bits

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Split the 32-bit address into tag, index and block offset.

| Field | Bits | Why |
|---|---|---|
| Block offset | 4 | block is 16 B $= 2^4$ |
| Index | **0** | fully associative: a block can go in any line, so there is no set to select |
| Tag | $32 - 4 - 0 = $ **28** | the rest |

The cache has $16\text{ kB}/16\text{ B} = 1024$ lines, but that number matters only for direct-mapped or set-associative caches.

**Why the others fail:**

- (A) and (C) use a 24-bit tag, which would need an 8-bit offset (256 B blocks).
- (B) and (C) give 4 index bits. That would mean 16 sets, not fully associative.

**Key idea:** a fully associative cache has no index field. Tag = address bits minus offset bits.

</details>
