# 2011 CS Q43: Tag storage for a direct-mapped write-back cache

## Question

An 8KB direct-mapped write-back cache is organized as multiple blocks, each of size 32-bytes. The processor generates 32-bit addresses. The cache controller maintains the tag information for each cache block comprising of the following.

- 1 Valid bit
- 1 Modified bit
- As many bits as the minimum needed to identify the memory block mapped in the cache.

What is the total size of memory needed at the cache controller to store meta-data (tags) for the cache?

- (A) 4864 bits
- (B) 6144 bits
- (C) 6656 bits
- (D) 5376 bits

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

- Number of blocks: $\dfrac{8 \text{ KB}}{32 \text{ B}} = \dfrac{2^{13}}{2^5} = 2^8 = 256$.
- Address split ($32$ bits): offset $= 5$ bits, index $= 8$ bits, so tag $= 32 - 8 - 5 = 19$ bits.
- Per block: $19 + 1 \text{ (valid)} + 1 \text{ (modified)} = 21$ bits.

$$\text{Total} = 256 \times 21 = 5376 \text{ bits}$$

So (D).

- (A) $4864 = 256 \times 19$ forgets the valid and modified bits.
- (B) $6144 = 256 \times 24$ and (C) $6656 = 256 \times 26$ would need tags of $22$ and $24$ bits. The tag is $19$ bits.

**Code check:** $256 \times (19 + 2) = 5376$.

**Key idea:** tag bits = address bits - index bits - offset bits; add the valid and modified bits per block.

</details>
