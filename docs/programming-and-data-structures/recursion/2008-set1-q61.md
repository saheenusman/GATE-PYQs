# 2008 CS Q61: Printing an input string in reverse using recursion

## Question

Choose the correct option to fill `?1` and `?2` so that the program below prints an input string in reverse order. Assume that the input string is terminated by a newline character.

```c
void reverse(void) {
    int c;
    if (?1) reverse();
    ?2
}

main() {
    printf("Enter Text"); printf("\n");
    reverse(); printf("\n");
}
```

- (A) `?1` is `(getchar() != '\n')`, `?2` is `getchar(c);`
- (B) `?1` is `((c = getchar()) != '\n')`, `?2` is `getchar(c);`
- (C) `?1` is `(c != '\n')`, `?2` is `putchar(c);`
- (D) `?1` is `((c = getchar()) != '\n')`, `?2` is `putchar(c);`

(In the paper, option (B) is printed with unbalanced parentheses; it is shown balanced here.)

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

To reverse the input, each call must **read** a character, make the recursive call for the rest, and **print** its character only after the call returns.

- Reading and testing: `(c = getchar()) != '\n'` stores the character in the local `c` and stops at the newline.
- Printing on the way back: `putchar(c)` after the recursive call. The last character read is printed first.

This is option (D). For input `hello`, the calls read `h, e, l, l, o`, then hit `\n`; the returns print `o, l, l, e, h`.

- (A) reads a character but never stores it in `c`, and `getchar(c)` is not a valid call (it takes no argument).
- (B) reads and stores correctly, but `getchar(c)` after the call reads another character instead of printing one.
- (C) tests `c` before anything has been read into it (uninitialised), and never reads.

**Code check:** compiled option (D) with `gcc -Wall` and fed it `hello`: output `olleh`.

**Key idea:** work done after the recursive call runs in reverse order, so printing after recursing reverses the input.

</details>
