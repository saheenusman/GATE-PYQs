# 2019 CS2 Q36: Recursion with an unreachable base case

## Question

Consider the following C function.

```c
void convert(int n){
    if(n<0)
        printf("%d",n);
    else {
        convert(n/2);
        printf("%d",n%2);
    }
}
```

Which one of the following will happen when the function `convert` is called with any positive integer `n` as argument?

- (A) It will print the binary representation of `n` and terminate
- (B) It will print the binary representation of `n` in the reverse order and terminate
- (C) It will print the binary representation of `n` but will not terminate
- (D) It will not print anything and will not terminate

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The only base case is `n < 0`. Dividing a non-negative number by 2 never makes it negative.

| Call | `n` |
|---|---|
| `convert(5)` | 5 |
| `convert(2)` | 2 |
| `convert(1)` | 1 |
| `convert(0)` | 0 |
| `convert(0)` | 0 again, and so on |

At `n = 0` the test `n < 0` is false, so the else branch calls `convert(0/2) = convert(0)` forever. The `printf("%d", n%2)` comes **after** the recursive call, so it is never reached. **Nothing is printed and the function never terminates.**

**Code check:** compiled with `gcc -Wall` (no warnings) and run with a 1 MB stack, at both `-O0` and `-O2`. Nothing is printed and the program dies with a segmentation fault (exit 139). That crash is the real-machine form of "never terminates": the stack overflows. The exact crash is implementation behaviour. The logical answer does not depend on it.

**Why the others fail:** (A), (B) and (C) all assume some digits get printed, but the print statement sits after a call that never returns.

**Key idea:** a recursion needs a base case it can actually reach.

</details>
