# 2024 CS1 Q19: Recursive getchar and putchar

## Question

Consider the following C program:

```c
#include <stdio.h>
void fX();
int main(){
  fX();
  return 0;
}
void fX(){
  char a;
  if((a=getchar()) != '\n')
    fX();
  if(a != '\n')
    putchar(a);
}
```

Assume that the input to the program from the command line is `1234` followed by a newline character. Which one of the following statements is CORRECT?

- (A) The program will not terminate
- (B) The program will terminate with no output
- (C) The program will terminate with 4321 as output
- (D) The program will terminate with 1234 as output

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Each call reads one character into its own local `a`, **recurses first**, and prints **after** the recursive call returns.

**Going down (reading):**

| Call | `a` read | Recurse? |
|---|---|---|
| 1 | `'1'` | yes |
| 2 | `'2'` | yes |
| 3 | `'3'` | yes |
| 4 | `'4'` | yes |
| 5 | `'\n'` | no |

**Coming back (printing):** call 5 sees `'\n'` and prints nothing. Then call 4 prints `4`, call 3 prints `3`, call 2 prints `2`, call 1 prints `1`.

Output: **4321**.

**Verified.** I compiled it with `gcc -Wall` and fed it `1234` plus newline: it printed `4321`.

**Why the others fail:** the recursion ends at the newline, so it does terminate. Printing happens on the way back up, so the order is reversed, not 1234.

**Key idea:** work done after the recursive call runs in reverse order (the call stack acts like a stack).

</details>
