# 2007 CS Q42: Recursive function with a static variable

## Question

Consider the following C function:

```c
int f(int n)
{
    static int r = 0;
    if (n <= 0) return 1;
    if (n > 3)
    {
        r = n;
        return f(n-2) + 2;
    }
    return f(n-1) + r;
}
```

What is the value of `f(5)`?

- (A) 5
- (B) 7
- (C) 9
- (D) 18

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

`r` is `static`, so it keeps its value across all calls. It is written only when `n > 3`.

Trace of `f(5)`:

| Call | What happens |
|---|---|
| `f(5)` | $n > 3$: set `r = 5`, return `f(3) + 2` |
| `f(3)` | $n \le 3$: return `f(2) + r` |
| `f(2)` | return `f(1) + r` |
| `f(1)` | return `f(0) + r` |
| `f(0)` | return 1 |

Unwinding with $r = 5$: $f(1) = 1 + 5 = 6$, $f(2) = 6 + 5 = 11$, $f(3) = 11 + 5 = 16$, $f(5) = 16 + 2 = 18$: (D).

- (A), (B) and (C) come from treating `r` as reset to 0 or as an ordinary local variable.

**Code check:** `gcc -Wall -Wextra`: prints `f(5)=18`, no warnings. **Evaluation order:** in `f(n-1) + r` the order of reading `r` and calling `f` is unspecified in C, but `r` is written only in the `n > 3` branch, which is never reached below `f(3)`, so `r` is 5 whichever way the compiler orders it. No undefined behaviour.

**Key idea:** a `static` local persists across calls; here it is set once, to 5, by the outermost call.
