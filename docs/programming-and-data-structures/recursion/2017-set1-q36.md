# 2017 CS1 Q36: Behaviour of foo(3) and bar(3) with val-- and val-1 in a loop

## Question

Consider the C functions `foo` and `bar` given below:

```c
int foo(int val) {
    int x = 0;
    while (val > 0) {
        x = x + foo(val--);
    }
    return val;
}

int bar(int val) {
    int x = 0;
    while (val > 0) {
        x = x + bar(val - 1);
    }
    return val;
}
```

Invocations of `foo(3)` and `bar(3)` will result in:

- (A) Return of 6 and 6 respectively.
- (B) Infinite loop and abnormal termination respectively.
- (C) Abnormal termination and infinite loop respectively.
- (D) Both terminating abnormally.

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**`foo(3)`.** `foo(val--)` passes the *current* value of `val` (post-decrement), then decrements the caller's copy. So `foo(3)` calls `foo(3)` again, which calls `foo(3)` again, and so on. The recursion never gets closer to the base case, the stack grows without bound and the program **terminates abnormally** (stack overflow).

**`bar(3)`.** `bar(val - 1)` gets a smaller argument, but the caller's `val` never changes. `bar(3)` calls `bar(2)`, which calls `bar(1)`, which calls `bar(0)`. That call skips the loop and returns $0$. Back in `bar(1)`, `val` is still $1$, so the `while` condition stays true and it calls `bar(0)` again, forever. The stack stays shallow, so there is no crash: an **infinite loop**.

So abnormal termination, then an infinite loop: **(C)**.

**Why the others fail.** (A) would need both to return. (B) swaps the two behaviours. (D) `bar` never overflows the stack, because each `bar(0)` call returns.

**Code check:** compiled at `-O0`, `foo(3)` died with a segmentation fault (exit status 139, stack overflow), while `bar(3)` was still running after a 5 second timeout (exit status 124).

**Note.** I used `-O0`. An optimizer is allowed to simplify code with no visible effect, so the observed behaviour at higher optimization levels may differ. The question is about the source semantics.

**Key idea:** a post-decrement argument does not shrink the argument; a loop that never changes its own counter never ends.

</details>
