# 2013 CS Q42: Return value of f(p,p) with a reference parameter

## Question

What is the return value of `f(p,p)`, if the value of `p` is initialized to 5 before the call? Note that the first parameter is passed by reference, whereas the second parameter is passed by value.

```cpp
int f(int &x, int c) {
    c = c - 1;
    if (c == 0) return 1;
    x = x + 1;
    return f(x, c) * x;
}
```

- (A) 3024
- (B) 6561
- (C) 55440
- (D) 161051

<details class="success" markdown="1">
<summary>Answer</summary>

**MTA (marks awarded to all; the key names no single option)**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Trace.** `x` is an alias of `p`; `c` is a fresh copy at each level, starting at 5.

| Level | $c$ after `c=c-1` | `x` (= `p`) after `x=x+1` |
|---|---|---|
| 1 | 4 | 6 |
| 2 | 3 | 7 |
| 3 | 2 | 8 |
| 4 | 1 | 9 |
| 5 | 0, returns 1 | 9 |

The return expression `f(x,c) * x` multiplies two operands, and **C++ does not specify which is evaluated first**:

- If `x` is read **after** the recursive call returns, every level sees `p = 9`: $1\cdot 9\cdot 9\cdot 9\cdot 9 = 9^4 = 6561$ (option B).
- If `x` is read **before** the recursive call, levels 1 to 4 read $6, 7, 8, 9$: $6\cdot7\cdot8\cdot9 = 3024$ (option A).

Both are legal results; the question depends on **unspecified evaluation order** of the operands of `*`. That is why the official key gives marks to all (MTA).

**Options C and D** ($55440$ and $161051 = 11^5$) do not arise from either order.

**Code check:** compiled with `g++ -Wall` (GCC 13.3). The program as printed gives **6561**. A variant that forces "read `x` first" gives **3024**, and "read `x` after" gives **6561**.

**Key idea:** operands of `*` are unsequenced in C/C++, and the aliasing through the reference makes the result depend on that order.

</details>
