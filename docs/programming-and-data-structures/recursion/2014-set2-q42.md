# 2014 CS2 Q42: Static variable and recursive call with the same argument

## Question

Consider the C function given below.

```c
int f(int j)
{
  static int i = 50;
  int k;
  if (i == j)
  {
     printf("something");
     k = f(i);
     return 0;
  }
  else return 0;
}
```

Which one of the following is **TRUE**?

- (A) The function returns 0 for all values of `j`.
- (B) The function prints the string `something` for all values of `j`.
- (C) The function returns 0 when `j = 50`.
- (D) The function will exhaust the runtime stack or run into an infinite loop when `j = 50`.

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

`i` is `static`, so it is initialised once to 50 and never changes (the function never assigns to it).

- **$j \ne 50$:** the test fails, the function returns 0 at once, and prints nothing.
- **$j = 50$:** the test succeeds, it prints, then calls `f(i)` = `f(50)`. That call sees the same `i` and the same argument, so it takes the same branch. There is no base case, so the recursion never ends. It runs until the stack is exhausted (or forever, if the compiler turns the tail call into a loop).

Options:

- (A) false: for $j = 50$ the function never returns.
- (B) false: nothing is printed for $j \ne 50$.
- (C) false: for $j = 50$ no call ever reaches `return 0`.
- (D) true.

**Code check:** I compiled the function with `gcc -Wall` (the only warning is that `k` is set but not used) and added a depth counter. `f(7)` returns 0. `f(50)` hits a depth cap of 100000 calls and had to be stopped by the cap. Without the cap a real run ends in a stack overflow (a crash), which is implementation behaviour.

**Note:** the paper prints `printf` with curly quotes; they are plain `"` in real C.

**Key idea:** a `static` local keeps one value across all calls; with no change to it, the recursive call repeats the same state.

</details>
