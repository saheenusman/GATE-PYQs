# 2020 CS Q56: Static variables in fun1 and fun2

## Question

Consider the following C functions.

```c
int fun1(int n) {
  static int i = 0;
  if (n > 0) {
    ++i;
    fun1(n-1);
  }
  return i;
}

int fun2(int n) {
  static int i = 0;
  if (n > 0) {
    i = i + fun1(n);
    fun2(n-1);
  }
  return i;
}
```

The return value of `fun2(5)` is ______.

<details class="success" markdown="1">
<summary>Answer</summary>

**55**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Two separate statics.** `fun1` and `fun2` each have their own `static int i`, initialised once to 0 and kept between calls.

**What `fun1(n)` does.** It makes $n$ recursive increments, so each call adds $n$ to its own `i`, then returns that `i`.

| Call | fun1's `i` before | After | Returned |
|---|---|---|---|
| `fun1(5)` | 0 | 5 | 5 |
| `fun1(4)` | 5 | 9 | 9 |
| `fun1(3)` | 9 | 12 | 12 |
| `fun1(2)` | 12 | 14 | 14 |
| `fun1(1)` | 14 | 15 | 15 |

**What `fun2` does.** `fun2(5)` runs `i = i + fun1(5)`, then calls `fun2(4)` (its result is discarded), and so on down to `fun2(1)`. `fun2`'s own `i` accumulates:

| Call | `i` before | `+ fun1(n)` | `i` after |
|---|---|---|---|
| `fun2(5)` | 0 | 5 | 5 |
| `fun2(4)` | 5 | 9 | 14 |
| `fun2(3)` | 14 | 12 | 26 |
| `fun2(2)` | 26 | 14 | 40 |
| `fun2(1)` | 40 | 15 | 55 |

`fun2(0)` changes nothing. When the recursion unwinds, the outermost `fun2(5)` executes `return i`, and `i` is now 55.

So `fun2(5)` returns **55**. I compiled and ran this with `gcc -Wall -Wextra` with no warnings, and it prints 55.

There is no undefined behaviour: `fun1` never touches `fun2`'s `i`, so `i = i + fun1(n)` has no unsequenced access.

**Key idea:** a `static` local keeps its value across all calls, including recursive ones. The return value of the outermost call is read after the whole recursion has finished updating it.

</details>
