# 2007 CS Q44: Recursive calls made by Euclid's gcd

## Question

In the following C function, let $n \ge m$.

```c
int gcd(n, m)
{
    if (n % m == 0) return m;
    n = n % m;
    return gcd(m, n);
}
```

How many recursive calls are made by this function?

- (A) $\Theta(\log_2 n)$
- (B) $\Omega(n)$
- (C) $\Theta(\log_2 \log_2 n)$
- (D) $\Theta(\sqrt{n})$

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Each recursive call replaces $(n, m)$ by $(m, n \bmod m)$. Since $n \bmod m < n/2$ whenever $n \ge m$, the larger argument at least halves every two calls, so there are at most $2\log_2 n$ calls. The worst case occurs for consecutive Fibonacci numbers and is about $\log_\varphi n = \Theta(\log n)$ calls (Lamé's theorem). So the worst-case number of recursive calls is $\Theta(\log_2 n)$: (A).

- (B) $\Omega(n)$ is far too many.
- (C) $\log\log n$ is too few: Fibonacci inputs force about $\log_\varphi n$ calls.
- (D) $\sqrt{n}$ is too many.

**Code check:** C program (`gcc -Wall -Wextra`) counting calls over all $(n, m)$ with $n \in [N/2, N]$, $m \le n$: the maximum is 3, 8, 11, 14 for $N = 10, 100, 500, 2000$, growing like $\log N$; the minimum is 0.

**Wording caveat:** "how many recursive calls" has no single value (it is 0 when $m \mid n$). I read it as the worst case, which is the only reading under which one of the options is correct.

**Status note:** `unverified`. GATE 2007 had no official answer key, so there is nothing to compare against. This is my own answer.

**Key idea:** Euclid's algorithm takes $O(\log n)$ steps, and consecutive Fibonacci numbers are the worst case.

</details>
