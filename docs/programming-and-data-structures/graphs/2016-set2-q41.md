# 2016 CS2 Q41: Time to set twin pointers in an adjacency list representation

## Question

In an adjacency list representation of an undirected simple graph $G = (V, E)$, each edge $(u, v)$ has two adjacency list entries: $[v]$ in the adjacency list of $u$, and $[u]$ in the adjacency list of $v$. These are called twins of each other. A twin pointer is a pointer from an adjacency list entry to its twin. If $|E| = m$ and $|V| = n$, and the memory size is not a constraint, what is the time complexity of the most efficient algorithm to set the twin pointer in each entry in each adjacency list?

- (A) $\Theta(n^2)$
- (B) $\Theta(n + m)$
- (C) $\Theta(m^2)$
- (D) $\Theta(n^4)$

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Lower bound.** There are $2m$ entries and each needs a pointer set, and the vertices must be visited: $\Omega(n + m)$.

**An $O(n + m)$ algorithm.** Treat each of the $2m$ entries as a pair keyed by its edge, $(\min(u,v), \max(u,v))$, and radix-sort the entries by this key with two counting-sort passes (each $O(n + m)$). The two entries of an edge become adjacent in the sorted order, so link each adjacent pair as twins.

So the time is $\Theta(n + m)$, **(B)**.

The other options are slower: (A) $\Theta(n^2)$ is a matrix scan and (C) $\Theta(m^2)$ is a pairwise comparison, and neither is needed; (D) $\Theta(n^4)$ is far larger still.

**Key idea:** radix-sort the $2m$ entries by edge key to pair twins in $\Theta(n + m)$.

</details>
