# 2007 CS Q46: What GetValue computes on a binary tree

## Question

Consider the following C program segment where `CellNode` represents a node in a binary tree:

```c
struct CellNode {
    struct CellNode *leftChild;
    int element;
    struct CellNode *rightChild;
};

int GetValue(struct CellNode *ptr) {
    int value = 0;
    if (ptr != NULL) {
        if ((ptr->leftChild == NULL) &&
            (ptr->rightChild == NULL))
            value = 1;
        else
            value = value + GetValue(ptr->leftChild)
                          + GetValue(ptr->rightChild);
    }
    return(value);
}
```

The value returned by `GetValue` when a pointer to the root of a binary tree is passed as its argument is:

- (A) the number of nodes in the tree.
- (B) the number of internal nodes in the tree.
- (C) the number of leaf nodes in the tree.
- (D) the height of the tree.

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

- A `NULL` pointer returns $0$.
- A leaf (both children `NULL`) returns $1$.
- Any other node returns the sum over its two subtrees; it adds nothing of its own.

So only leaves contribute, each exactly $1$: the function counts the **leaf nodes**: (C).

- (A) would need `1 + ...` at internal nodes as well.
- (B) would need internal nodes to contribute $1$ and leaves $0$.
- (D) would need a `max` and a `+1`, not a sum.

**Code check:** C program (`gcc -Wall -Wextra`): on 2000 random binary trees `GetValue` equalled the leaf count every time, but the node count in 486, the internal-node count in 458 and the height in 46 trees only (coincidences on small trees).

**Status note:** `unverified`. GATE 2007 had no official answer key, so there is nothing to compare against. This is my own answer.

**Key idea:** a recursion that returns 1 at leaves and sums over children counts the leaves.

</details>
