# 2012 CS Q47: Filling the boxes in a binary tree height function

## Question

The height of a tree is defined as the number of edges on the longest path in the tree. The function shown in the pseudocode below is invoked as `height(root)` to compute the height of a binary tree rooted at the tree pointer `root`.

```c
int height (treeptr n)
{ if (n == NULL) return -1;
  if (n->left == NULL)
      if (n->right == NULL) return 0;
      else return [B1];            // Box 1
  else { h1 = height (n->left);
         if (n->right == NULL) return (1+h1);
         else { h2 = height (n->right);
                return [B2];       // Box 2
              }
       }
}
```

The appropriate expressions for the two boxes B1 and B2 are

- (A) B1: `(1+height(n->right))`; B2: `(1+max(h1, h2))`
- (B) B1: `(height(n->right))`; B2: `(1+max(h1,h2))`
- (C) B1: `height(n->right)`; B2: `max(h1, h2)`
- (D) B1: `(1+ height(n->right))`; B2: `max(h1, h2)`

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Height counts **edges**, so a node adds $1$ for the edge to its tallest child.

- **Box 1:** left is `NULL` and right is not. The only child is on the right, so the height is $1 + \text{height(right)}$.
- **Box 2:** both children exist, so the height is $1 + \max(h_1, h_2)$.

That is (A).

- (B) drops the $+1$ in Box 1, losing an edge.
- (C), (D) drop the $+1$ in Box 2, losing the edge to the taller child.

**Code check:** I compiled the function in C with each option's boxes (`gcc -Wall`) and compared it with a reference height on about 15,000 random binary trees. Mismatches: (A) 0, (B) 5312, (C) 13899, (D) 13530.

**Key idea:** the height of a node is $1 + $ the height of its tallest child, with $-1$ for an empty tree.

</details>
