# 2025 CS2 Q45: Stack with an O(1) MIN operation

## Question

Consider a stack data structure into which we can PUSH and POP records. Assume that each record pushed in the stack has a positive integer key and that all keys are distinct.

We wish to augment the stack data structure with an $O(1)$ time MIN operation that returns a pointer to the record with smallest key present in the stack

1. without deleting the corresponding record, and
2. without increasing the complexities of the standard stack operations.

Which one or more of the following approach(es) can achieve it?

- (A) Keep with every record in the stack, a pointer to the record with the smallest key below it.
- (B) Keep a pointer to the record with the smallest key in the stack.
- (C) Keep an auxiliary array in which the key values of the records in the stack are maintained in sorted order.
- (D) Keep a Min-Heap in which the key values of the records in the stack are maintained.

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The standard stack operations PUSH and POP are $O(1)$, so the augmented version must keep **PUSH, POP and MIN all $O(1)$**.

**(A) Works.** Each record stores, at the moment it is pushed, a pointer to the smallest record *below* it in the stack (none for the bottom record).

- PUSH: the pointer to store is the smaller of the old top and the old top's own stored pointer: one comparison, $O(1)$.
- POP: remove the top. The record now on top still carries its own stored pointer: $O(1)$.
- MIN: compare the top record with the pointer stored in it and return the smaller: $O(1)$.

The minimum below every position is "remembered", so popping never needs a search.

**(B) Fails.** One pointer to the current minimum goes stale when that record is popped. Example: push 5, 3, 8 (the pointer is at 3), then pop 8 and pop 3. The minimum is now 5, but nothing records that, and finding it needs an $O(n)$ rescan.

**(C) Fails.** Keeping a sorted array means PUSH must insert in the middle and shift elements, $O(n)$, and POP must delete the key from the middle, also $O(n)$. This worsens the stack operations.

**(D) Fails.** A min-heap gives MIN in $O(1)$ (the root), but PUSH becomes $O(\log n)$. POP removes the *most recently pushed* key, which is not the heap's root, so deleting it costs $O(\log n)$ even with an index into the heap (and $O(n)$ if it must be searched for). This again worsens the stack operations.

| Option | PUSH | POP | MIN | Meets all three? |
|---|---|---|---|---|
| A | $O(1)$ | $O(1)$ | $O(1)$ | yes |
| B | $O(1)$ | $O(n)$ to repair | $O(1)$ | no |
| C | $O(n)$ | $O(n)$ | $O(1)$ | no |
| D | $O(\log n)$ | $O(\log n)$ | $O(1)$ | no |

**Key idea:** to get $O(1)$ MIN on a stack, store the running minimum with each element, so every pop exposes the right minimum for free.

</details>
