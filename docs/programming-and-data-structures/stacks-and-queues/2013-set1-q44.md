# 2013 CS Q44: Amortized cost of MultiDequeue

## Question

Consider the following operation along with `Enqueue` and `Dequeue` operations on queues, where $k$ is a global parameter.

```
MultiDequeue(Q) {
    m = k
    while (Q is not empty) and (m > 0) {
        Dequeue(Q)
        m = m - 1
    }
}
```

What is the worst case time complexity of a sequence of $n$ queue operations on an initially empty queue?

- (A) $\Theta(n)$
- (B) $\Theta(n + k)$
- (C) $\Theta(nk)$
- (D) $\Theta(n^2)$

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Aggregate argument.** Each element is enqueued once and can be dequeued at most once, whether by `Dequeue` or by `MultiDequeue`. In a sequence of $n$ operations there are at most $n$ enqueues, so at most $n$ element removals in total.

Each operation costs $O(1)$ plus one unit per element it removes. Total cost $\le n + n = 2n = O(n)$. Any sequence of $n$ operations costs at least $n$, so the bound is $\Theta(n)$.

**Why the others fail:**

- (B) $k$ does not add to the total: a `MultiDequeue` cannot remove more than the queue holds.
- (C) $nk$ would need every `MultiDequeue` to remove $k$ elements, but the elements must first be enqueued.
- (D) is a loose upper bound.

**Code check:** a simulation of random operation sequences never exceeded $2n$ unit costs.

**Key idea:** amortized analysis: each item leaves the queue at most once, so total dequeue work is bounded by the enqueue count.

</details>
