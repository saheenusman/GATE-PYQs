# 2017 CS2 Q13: Pointer layout for an O(1) circular queue on a singly linked list

## Question

A circular queue has been implemented using a singly linked list where each node consists of a value and a single pointer pointing to the next node. We maintain exactly two external pointers FRONT and REAR pointing to the front node and the rear node of the queue, respectively. Which of the following statements is/are CORRECT for such a circular queue, so that insertion and deletion operations can be performed in $O(1)$ time?

- I. Next pointer of front node points to the rear node.
- II. Next pointer of rear node points to the front node.

Options:

- (A) I only
- (B) II only
- (C) Both I and II
- (D) Neither I nor II

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Statement II works.** Let `rear->next == front`.

- *Insert* at the rear: `new->next = front; rear->next = new; rear = new;` takes $O(1)$.
- *Delete* from the front: `front = front->next; rear->next = front;` takes $O(1)$, because `rear` is known and `front->next` is the new front.

**Statement I fails.** If `front->next` points to the *rear*, the list structure cannot be a queue. The node after the front is lost: after deleting the front you cannot find the new front without walking the list. That makes deletion $O(n)$.

So II only: **(B)**.

**Why the others fail.** (A) and (C) include I. (D) denies II, but II is exactly how the circular link is set up.

**Status note:** data-structure reasoning on pointer layout (no program applies); the answer matches the official key.

**Key idea:** in a circular queue the rear node links back to the front node, so both ends are reachable in $O(1)$.

</details>
