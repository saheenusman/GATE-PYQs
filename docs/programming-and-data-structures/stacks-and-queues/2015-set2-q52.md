# 2015 CS2 Q52: Output of a static-variable stack program

## Question

Consider the C program below.

```c
#include <stdio.h>
int *A, stkTop;

int stkFunc(int opcode, int val)
{
    static int size=0, stkTop=0;

    switch (opcode) {
        case -1: size = val; break;
        case  0: if (stkTop < size)
                     A[stkTop++] = val;
                 break;
        default: if (stkTop)
                     return A[--stkTop];
    }
    return -1;
}

int main()
{
    int B[20]; A = B; stkTop = -1;

    stkFunc (-1, 10);
    stkFunc ( 0, 5);
    stkFunc ( 0, 10);
    printf ("%d\n", stkFunc(1, 0) + stkFunc(1, 0));
}
```

The value printed by the above program is ________

<details class="success" markdown="1">
<summary>Answer</summary>

**15**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**The trap.** `main` sets the *global* `stkTop = -1`, but inside `stkFunc` the `static int stkTop = 0` hides the global. The function only ever sees its own `stkTop`, which keeps its value between calls and is initialised once.

| Call | Effect | `size` | static `stkTop` |
|---|---|---|---|
| `stkFunc(-1,10)` | set size | 10 | 0 |
| `stkFunc(0,5)` | `A[0]=5` | 10 | 1 |
| `stkFunc(0,10)` | `A[1]=10` | 10 | 2 |
| first pop | returns `A[1]` = 10 | 10 | 1 |
| second pop | returns `A[0]` = 5 | 10 | 0 |

$$10 + 5 = 15$$

**Evaluation order.** The order of the two operands of `+` is unspecified, but the function calls do not interleave, and the two pops return 10 and 5 in some order. The sum is 15 either way. This is unspecified behaviour, not undefined.

**Code check:** compiled with `gcc -Wall` with no warnings, and it prints `15`. I also removed the `static` declaration so the global `stkTop = -1` was used: the first push then writes `A[-1]`, which is undefined behaviour, and the program crashed.

**Key idea:** a local `static` hides a global of the same name, and keeps its value across calls.

</details>
