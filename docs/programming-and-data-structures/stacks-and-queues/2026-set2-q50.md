# 2026 CS2 Q50: Splitting elements between a stack and a queue

## Question

Consider a stack $S$ and a queue $Q$. Both are initially empty and can store ten elements each. The elements 1, 2, 3, 4, 5 arrive one by one, in that order. When an element arrives, it is assigned either to $S$ (pushed) or to $Q$ (enqueued).

Once all five elements are stored, the output is generated in two steps: first, $S$ is emptied by popping all elements, then $Q$ is emptied by dequeueing all elements. The output obtained is **4 3 1 2 5**.

Which of the following options is/are possible valid assignment(s) of the elements? ($xS$ means $x$ went to $S$, $yQ$ means $y$ went to $Q$.)

- (A) 1S, 2Q, 3S, 4S, 5Q
- (B) 1Q, 2Q, 3S, 4S, 5Q
- (C) 1Q, 2Q, 3Q, 4S, 5S
- (D) 1S, 2S, 3S, 4Q, 5Q

<details class="success" markdown="1">
<summary>Answer</summary>

**A and B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Elements arrive in increasing order. So:

- the stack outputs its elements in **decreasing** order (last in, first out),
- the queue outputs its elements in **increasing** order (first in, first out).

The output is "stack part, then queue part". Split **4 3 1 2 5** into a decreasing prefix and an increasing suffix:

| Split | Stack part | Queue part | Valid? |
|---|---|---|---|
| `4 3` + `1 2 5` | 4, 3 (decreasing) | 1, 2, 5 (increasing) | yes |
| `4 3 1` + `2 5` | 4, 3, 1 (decreasing) | 2, 5 (increasing) | yes |
| `4` + `3 1 2 5` | | 3 1 2 5 is not increasing | no |
| `4 3 1 2` + `5` | 4 3 1 2 is not decreasing | | no |

So there are exactly two assignments:

- Stack $=\{3,4\}$, Queue $=\{1,2,5\}$, which is **(B)**.
- Stack $=\{1,3,4\}$, Queue $=\{2,5\}$, which is **(A)**.

Why the others fail:

- **(C)** Stack $=\{4,5\}$ pops as 5 4, not 4 3 ...
- **(D)** Stack $=\{1,2,3\}$ pops as 3 2 1, not 4 3 ...

A brute force over all $2^5$ assignments finds exactly (A) and (B).

**Key idea:** a stack reverses the arrival order and a queue preserves it, so the output must be a decreasing run followed by an increasing run.

</details>
