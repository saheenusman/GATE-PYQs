# 2012 CS Q35: Full and empty conditions of a circular queue

## Question

Suppose a circular queue of capacity $(n-1)$ elements is implemented with an array of $n$ elements. Assume that the insertion and deletion operations are carried out using REAR and FRONT as array index variables, respectively. Initially, REAR $=$ FRONT $= 0$. The conditions to detect queue full and queue empty are

- (A) full: `(REAR+1) mod n == FRONT`; empty: `REAR == FRONT`
- (B) full: `(REAR+1) mod n == FRONT`; empty: `(FRONT+1) mod n == REAR`
- (C) full: `REAR == FRONT`; empty: `(REAR+1) mod n == FRONT`
- (D) full: `(FRONT+1) mod n == REAR`; empty: `REAR == FRONT`

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Initially $\text{REAR} = \text{FRONT}$ and the queue is empty, so **empty** is `REAR == FRONT`.

With $n$ slots, one slot is always left unused, so capacity is $n-1$. If the queue were allowed to fill all $n$ slots, "full" would look the same as "empty" (REAR meets FRONT). The queue is **full** when advancing REAR by one would land on FRONT: `(REAR+1) mod n == FRONT`.

That is (A).

- (B) `(FRONT+1) mod n == REAR` is true for a queue holding exactly one element, not an empty one.
- (C) swaps the two conditions.
- (D) uses `(FRONT+1) mod n == REAR` for full, which means one element.

**Code check:** a random insert and delete simulation with $n = 5$ checked each pair of conditions against a true element count. Only (A) matched on all runs.

**Key idea:** a circular queue sacrifices one slot so that full and empty differ.

</details>
