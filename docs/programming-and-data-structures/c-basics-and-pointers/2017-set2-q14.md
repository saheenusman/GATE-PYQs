# 2017 CS2 Q14: Output of a function that changes its by-value parameter through a pointer

## Question

Consider the following function implemented in C:

```c
void printxy(int x, int y) {
    int *ptr;
    x = 0;
    ptr = &x;
    y = *ptr;
    *ptr = 1;
    printf("%d,%d", x, y);
}
```

The output of invoking `printxy(1, 1)` is

- (A) 0,0
- (B) 0,1
- (C) 1,0
- (D) 1,1

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Trace.** C passes arguments by value, so `x` and `y` are local copies that start as $1,1$.

| Statement | $x$ | $y$ | Note |
|---|---|---|---|
| (entry) | 1 | 1 | copies of the arguments |
| `x = 0;` | 0 | 1 | |
| `ptr = &x;` | 0 | 1 | `ptr` points to the local `x` |
| `y = *ptr;` | 0 | **0** | reads the current value of `x` |
| `*ptr = 1;` | **1** | 0 | writes through the pointer, so `x` changes, `y` does not |

`printf` prints `x,y` $=$ `1,0`: **(C)**.

**Why the others fail.**

- (A) forgets that `*ptr = 1` changes `x`.
- (B) takes `y` from before `x = 0` (still 1) and `x` as 0.
- (D) ignores both assignments.

**Code check:** compiled with `gcc -Wall` (no warnings; `printf` without a newline is fine here). Output: `1,0`.

**Key idea:** `y = *ptr` copies the value at that moment, so a later write through the pointer changes `x` only.

</details>
