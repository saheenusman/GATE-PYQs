# 2017 CS2 Q37: Precondition guaranteeing termination with x == y*q + r in a division loop

## Question

Consider the C program fragment below which is meant to divide $x$ by $y$ using repeated subtractions. The variables `x`, `y`, `q` and `r` are all `unsigned int`.

```c
while (r >= y) {
    r = r - y;
    q = q + 1;
}
```

Which of the following conditions on the variables `x`, `y`, `q` and `r` before the execution of the fragment will ensure that the loop terminates in a state satisfying the condition `x == (y*q + r)`?

- (A) `(q == r) && (r == 0)`
- (B) `(x > 0) && (r == x) && (y > 0)`
- (C) `(q == 0) && (r == x) && (y > 0)`
- (D) `(q == 0) && (y > 0)`

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Two things must hold.**

1. **Invariant:** `x == y*q + r` before each iteration. Each iteration does $r \to r - y$ and $q \to q + 1$, so $y\,q + r$ is unchanged. The invariant therefore holds at the end **if it holds at the start**.
2. **Termination:** `r` is unsigned and decreases by $y$ each time, so the loop ends only if $y > 0$. If $y = 0$, then `r >= y` is always true: infinite loop.

**Make the invariant true at the start:** $q = 0$ and $r = x$ give $y\cdot 0 + x = x$. With $y > 0$ the loop also terminates. That is exactly **(C)**.

**Why the others fail.**

- (A) $q = r = 0$ says nothing about $x$ (it may be non-zero), so the invariant need not hold; and $y$ may be 0 (infinite loop).
- (B) $r = x$ and $y > 0$ are fine, but $q$ is unconstrained: a non-zero $q$ breaks `x == y*q + r`.
- (D) $q = 0$ and $y > 0$ but `r` is unconstrained, so $x = y\cdot 0 + r$ need not hold.

**Code check:** a C program (`gcc -Wall`) tried every option as a precondition over all values 0 to 8 of $x, y, q, r$ and ran the loop. Only (C) never failed (72 admitted starting states, all ended with the postcondition true). (A) hit 9 infinite loops and 64 failed postconditions; (B) 512 and (D) 576 failures of the postcondition.

**Key idea:** a loop invariant plus a decreasing quantity: start with $q=0$, $r=x$, and $y>0$.

</details>
