# 2021 CS1 Q47: Short-circuit evaluation with a post-increment

## Question

Consider the following ANSI C program.

```c
#include <stdio.h>
int main()
{
    int i, j, count;
    count = 0;
    i = 0;
    for (j = -3; j <= 3; j++)
    {
        if ((j >= 0) && (i++))
            count = count + j;
    }
    count = count + i;
    printf("%d", count);
    return 0;
}
```

Which one of the following options is correct?

- (A) The program will not compile successfully.
- (B) The program will compile successfully and output 10 when executed.
- (C) The program will compile successfully and output 8 when executed.
- (D) The program will compile successfully and output 13 when executed.

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

`&&` short-circuits: `i++` runs only when `j >= 0` is true. And `i++` yields the **old** value of `i`.

| $j$ | `j>=0` | `i++` yields | $i$ after | `count` |
|---|---|---|---|---|
| -3, -2, -1 | false | not evaluated | 0 | 0 |
| 0 | true | 0 (false) | 1 | 0 |
| 1 | true | 1 (true) | 2 | 1 |
| 2 | true | 2 (true) | 3 | 3 |
| 3 | true | 3 (true) | 4 | 6 |

After the loop: `count = 6 + i = 6 + 4 = 10`. So (B).

(A) is wrong: the program is valid ANSI C (`int main()` with an empty parameter list is allowed). (C) and (D) come from forgetting the short-circuit or the old-value rule.

Compiled with `gcc -Wall` with no warnings, and it printed `10`. There is no undefined behaviour: `&&` is a sequence point, so `i++` is sequenced after `j >= 0`.

**Key idea:** `&&` does not evaluate its right side when the left is false, and post-increment yields the old value.

</details>
