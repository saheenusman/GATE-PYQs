# 2015 CS3 Q43: Output of pointer-to-pointer arithmetic on an array of pointers

## Question

Consider the following C program.

```c
#include<stdio.h>
int main( )
{
    static int a[ ] = {10, 20, 30, 40, 50};
    static int *p[ ] = {a, a+3, a+4, a+1, a+2};
    int **ptr = p;
    ptr++;
    printf("%d%d", ptr-p, **ptr);
}
```

The output of the program is ________

<details class="success" markdown="1">
<summary>Answer</summary>

**140**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

`p` is an array of pointers into `a`:

| `p[0]` | `p[1]` | `p[2]` | `p[3]` | `p[4]` |
|---|---|---|---|---|
| `a` | `a+3` | `a+4` | `a+1` | `a+2` |

- `ptr = p` points at `p[0]`. After `ptr++` it points at `p[1]`.
- `ptr - p` $= 1$ (pointer difference counts elements).
- `**ptr` $=$ `*p[1]` $=$ `*(a+3)` $= a[3] = 40$.

`printf("%d%d", 1, 40)` prints `1` then `40`: **140**.

**Code check:** it prints `140`. `gcc -Wall` warns that `%d` expects `int` but `ptr-p` is a `long int` (`ptrdiff_t`). Strictly this is undefined behaviour, but on common platforms it prints as expected.

**Key idea:** pointer subtraction gives a count of elements, and `**ptr` follows two levels of indirection.

</details>
