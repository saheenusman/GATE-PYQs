# 2020 CS Q58: Binary digits and repeated squaring in pp(3, 4)

## Question

Consider the following C functions.

```c
int tob(int b, int* arr) {
   int i;
   for (i=0; b>0; i++) {
      if (b%2) arr[i]=1;
      else     arr[i]=0;
      b = b/2;
   }
   return(i);
}
```

```c
int pp(int a, int b) {
    int arr[20];
    int i, tot = 1, ex, len;
    ex = a;
    len = tob(b, arr);
    for (i=0; i<len; i++) {
       if (arr[i]==1)
          tot = tot * ex;
       ex = ex * ex;
    }
    return(tot);
}
```

The value returned by `pp(3,4)` is ______.

<details class="success" markdown="1">
<summary>Answer</summary>

**81**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**`tob(b, arr)`** stores the binary digits of `b`, least significant first, and returns how many digits there are. For `b = 4` (binary 100):

| i | b before | b%2 | arr[i] | b after |
|---|---|---|---|---|
| 0 | 4 | 0 | 0 | 2 |
| 1 | 2 | 0 | 0 | 1 |
| 2 | 1 | 1 | 1 | 0 |

So `arr = {0, 0, 1}` and `len = 3`.

**`pp(3, 4)`** starts with `tot = 1`, `ex = 3`:

| i | arr[i] | tot after | ex after |
|---|---|---|---|
| 0 | 0 | 1 | 9 |
| 1 | 0 | 1 | 81 |
| 2 | 1 | $1 \times 81 = 81$ | 6561 |

It returns **81**.

**What it computes.** `ex` is $a^{2^i}$ at step $i$, and `tot` multiplies in `ex` for each 1-bit of $b$. This is exponentiation by repeated squaring, so `pp(a, b)` $= a^b$. Indeed $3^4 = 81$.

**Code check.** Compiled with `gcc -Wall -Wextra` and run: no warnings, output `81`. The last `ex = ex * ex` gives 6561, which fits in an `int`. For larger inputs that last squaring could overflow, which is undefined behaviour for signed ints, but it does not happen here.

**Key idea:** reading the bits of $b$ from the least significant end and squaring a running power gives $a^b$ in about $\log b$ multiplications.

</details>
