# 2017 CS2 Q2: Matching C declarations with their memory meaning

## Question

Match the following:

| | |
|---|---|
| (P) `static char var;` | (i) Sequence of memory locations to store addresses |
| (Q) `m = malloc(10);` followed by `m = NULL;` | (ii) A variable located in data section of memory |
| (R) `char *ptr[10];` | (iii) Request to allocate a CPU register to store data |
| (S) `register int var1;` | (iv) A lost memory which cannot be freed |

- (A) P $\to$ (ii), Q $\to$ (iv), R $\to$ (i), S $\to$ (iii)
- (B) P $\to$ (ii), Q $\to$ (i), R $\to$ (iv), S $\to$ (iii)
- (C) P $\to$ (ii), Q $\to$ (iv), R $\to$ (iii), S $\to$ (i)
- (D) P $\to$ (iii), Q $\to$ (iv), R $\to$ (i), S $\to$ (ii)

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Match each one.**

- **(P) `static char var;` $\to$ (ii).** A `static` variable has a fixed address for the whole run, in the data section (uninitialised statics go in the `.bss` part of it), not on the stack.
- **(Q) `m = malloc(10); m = NULL;` $\to$ (iv).** The only pointer to the 10-byte block is overwritten, so the block can never be freed: a memory leak.
- **(R) `char *ptr[10];` $\to$ (i).** An array of 10 pointers, i.e. 10 consecutive memory locations that hold addresses.
- **(S) `register int var1;` $\to$ (iii).** A request (a hint) that the compiler keep the variable in a CPU register.

That is P$\to$ii, Q$\to$iv, R$\to$i, S$\to$iii: **(A)**.

**Why the others fail.** (B) calls the leak "a sequence of locations" and the pointer array "a lost memory". (C) swaps R and S. (D) calls the static variable a register request.

**Code check:** a test program showed `sizeof(ptr) = 80` (ten 8-byte pointers) and `var` placed in `.bss` (`nm` shows a `b` symbol). AddressSanitizer reported `Direct leak of 10 byte(s)` for the `malloc` followed by `m = NULL`.

**Key idea:** `static` means static storage; losing the last pointer to a heap block is a leak; `register` is only a request.

</details>
