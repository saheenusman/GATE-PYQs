# 2010 CS Q11: Reassigning a pointer parameter before writing through it

## Question

What does the following program print?

```c
#include <stdio.h>
void f(int *p, int *q) {
    p = q;
    *p = 2;
}
int i = 0, j = 1;
int main() {
    f(&i, &j);
    printf("%d %d\n", i, j);
    return 0;
}
```

- (A) 2 2
- (B) 2 1
- (C) 0 1
- (D) 0 2

*Printed as is: the paper writes the second parameter as `int * g`, which is a typo for `int *q` (the body uses `q`). The PDF also splits `printf` as `pr int f`.*

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

`f` receives the addresses of `i` and `j` **by value**: `p` and `q` are local copies.

- `p = q;` changes only the local `p`; it now points to `j`. The caller's `i` is untouched.
- `*p = 2;` writes through the new `p`, so `j` becomes $2$.

`i` stays $0$ and `j` is $2$: output `0 2`, (D).

- (A) `2 2` would need `i` to change too.
- (B) `2 1` would need `*p = 2` to hit `i`, which only happens without the `p = q;` line.
- (C) `0 1` would mean no write happened.

**Code check:** compiled with `gcc -Wall -Wextra` after fixing `g` to `q`: no warnings, output `0 2`. As printed (`int * g`), it fails to compile: `'q' undeclared`.

**Key idea:** C passes pointers by value; reassigning the parameter does not affect the caller's pointer.

</details>
