# 2022 CS Q21: Pointer assignment and array update

## Question

What is printed by the following ANSI C program?

```c
#include<stdio.h>

int main(int argc, char *argv[])
{
    int x = 1, z[2] = {10, 11};
    int *p = NULL;
    p = &x;
    *p = 10;
    p = &z[1];
    *(&z[0] + 1) += 3;
    printf("%d, %d, %d\n", x, z[0], z[1]);
    return 0;
}
```

- (A) 1, 10, 11
- (B) 1, 10, 14
- (C) 10, 14, 11
- (D) 10, 10, 14

<details class="success" markdown="1">
<summary>Answer</summary>

**D (10, 10, 14)**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Trace the statements:**

| Step | Effect |
| --- | --- |
| `p = &x; *p = 10;` | `x` becomes 10 |
| `p = &z[1];` | `p` moves; nothing is written |
| `*(&z[0] + 1) += 3;` | `&z[0] + 1` is `&z[1]`, so `z[1]` becomes 14 |

Final values: `x = 10`, `z[0] = 10`, `z[1] = 14`. Output: `10, 10, 14`.

**Why the others fail:**
- (A) and (B) keep `x` at 1, forgetting that `*p = 10` writes through the pointer.
- (A) also leaves `z[1]` at 11, but the `+= 3` does change it.
- (C) adds 3 to `z[0]` instead of `z[1]`. `&z[0] + 1` points one element past `z[0]`, which is `z[1]`.

**Code check:** compiled with `gcc -Wall` with no warnings; the output is `10, 10, 14`.

**Key idea:** `*(&a[0] + k)` is the same as `a[k]`, and writing through a pointer changes the variable it points to.

</details>
