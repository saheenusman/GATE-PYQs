# 2012 CS Q3: Switch fall-through with a misprinted newline

## Question

What will be the output of the following C program segment?

```c
char inChar = 'A' ;
switch ( inChar ) {
case 'A' : printf ("Choice A\ n") ;
case 'B' :
case 'C' : printf ("Choice B") ;
case 'D' :
case 'E' :
default  : printf (" No Choice") ; }
```

The code is shown as printed in the paper, including the space in `\ n`. The PDF uses curly quotes; I used straight quotes.

- (A) `No Choice`
- (B) `Choice A`
- (C) `Choice A` on one line, then `Choice B No Choice` on the next line
- (D) Program gives no output as it is erroneous

<details class="success" markdown="1">
<summary>Answer</summary>

**MTA (marks awarded to all; the key names no single option)**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Fall-through.** There is no `break`, so once `case 'A'` matches, execution runs on through `case 'B'`/`'C'` and then the `default` label. Three `printf` calls run, in order.

**The misprint.** The paper prints `"Choice A\ n"` with a space between the backslash and the `n`. That is not the newline escape. The sequence `\ ` (backslash, space) is an unknown escape, so the output is:

```
Choice A nChoice B No Choice
```

None of the four options is this text. With the intended `\n` the output would be two lines, `Choice A` and `Choice B No Choice`, which is option (C).

**Why the key says MTA.** As printed, no option matches the real output, so the question was treated as faulty.

- (A) ignores the fall-through.
- (B) stops after `case 'A'`; that needs a `break`.
- (D) the code compiles (only a warning for the unknown escape).

**Code check:** compiled with `gcc -Wall`. The code as printed gives one warning (`unknown escape sequence`) and prints `Choice A nChoice B No Choice`. With `\n` it prints `Choice A`, a newline, then `Choice B No Choice`.

**Key idea:** without `break`, a `switch` falls through every following label, `default` included.

</details>
