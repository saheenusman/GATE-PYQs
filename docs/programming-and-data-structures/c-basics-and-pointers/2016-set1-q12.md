# 2016 CS1 Q12: Which call to f(int, short) type-checks

## Question

Consider the following C program.

```c
void f(int, short);
void main()
{
    int i = 100;
    short s = 12;
    short *p = &s;
    __________ ;   // call to f()
}
```

Which one of the following expressions, when placed in the blank above, will NOT result in a type checking error?

- (A) `f(s,*s)`
- (B) `i = f(i,s)`
- (C) `f(i,*s)`
- (D) `f(i,*p)`

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

`f` takes an `int` and a `short`, and returns `void`.

| Option | Problem |
|---|---|
| (A) `f(s,*s)` | `s` is a `short`, not a pointer, so `*s` is invalid |
| (B) `i = f(i,s)` | `f` returns `void`, so its value cannot be assigned to `i` |
| (C) `f(i,*s)` | `*s` is invalid again |
| (D) `f(i,*p)` | `p` is `short *`, so `*p` is a `short`; `i` is an `int`: both match |

**Code check:** each option was compiled with `gcc -Wall` (with `f` defined and `main` returning `int`). (A) and (C) fail with "invalid type argument of unary `*`", (B) fails with "void value not ignored as it ought to be", and (D) compiles cleanly.

**Note:** `void main()` is non-standard in C; it does not affect the type-checking question.

**Key idea:** argument types must match the prototype, `*` needs a pointer, and a `void` call yields no value.

</details>
