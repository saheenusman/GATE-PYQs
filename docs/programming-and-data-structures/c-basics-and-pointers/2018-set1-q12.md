# 2018 CS Q12: Output of a struct accessed through a char pointer

## Question

Consider the following C program.

```c
#include<stdio.h>
struct Ournode{
    char x,y,z;
};

int main(){
    struct Ournode p = {'1', '0', 'a'+2};
    struct Ournode *q = &p;
    printf ("%c, %c", *((char*)q+1), *((char*)q+2));
    return 0;
}
```

The output of this program is:

- (A) 0, c
- (B) 0, a+2
- (C) '0', 'a+2'
- (D) '0', 'c'

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Memory layout.** The three `char` members sit next to each other, so `x` is at offset 0, `y` at offset 1 and `z` at offset 2 (chars need no padding).

**Cast first, then add.** The cast `(char*)` binds tighter than `+`, so `(char*)q + 1` is the address of `y`, and `(char*)q + 2` is the address of `z`. The leading `*` reads those bytes.

| Expression | Member | Value |
|---|---|---|
| `*((char*)q+1)` | `y` | `'0'` |
| `*((char*)q+2)` | `z` | `'a'+2` = `'c'` |

`'a'+2` is evaluated at initialization (97 + 2 = 99), which is the code of `'c'`. `%c` prints the character with no quotes, so the output is `0, c`.

**Why the others fail:** B prints the expression text, which C never does. C and D add quote marks that `%c` does not print.

**Code check:** compiled with `gcc -Wall -Wextra`, no warnings, output `0, c`.

**Key idea:** a pointer to a struct can be viewed as a `char*` to walk its bytes; here the layout puts `y` and `z` at offsets 1 and 2.

</details>
