# 2021 CS2 Q20: Pointer arithmetic across a two-dimensional array

## Question

Consider the following ANSI C program.

```c
#include <stdio.h>
int main(){
    int arr[4][5];
    int i, j;
    for (i=0; i<4; i++){
        for (j=0; j<5; j++){
            arr[i][j] = 10*i + j;
        }
    }
    printf("%d", *(arr[1] + 9));
    return 0;
}
```

What is the output of the above program?

- (A) 14
- (B) 20
- (C) 24
- (D) 30

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

A 2D array is stored in row-major order, so `arr[i][j]` is the element at flat position $5i+j$ and holds $10i+j$.

`arr[1]` is a pointer to the first element of row 1, which is flat position 5. Adding 9 gives flat position $5+9=14$.

Flat position 14 is row $\lfloor14/5\rfloor=2$, column $14\bmod5=4$, i.e. `arr[2][4]`, which holds $10\cdot2+4=\mathbf{24}$. (C).

Compiled with `gcc -Wall` it prints `24`. With `-Wextra -O2`, GCC warns "array subscript 9 is above array bounds of `int[5]`".

**Undefined behaviour note.** Strictly, `arr[1] + 9` goes past the end of the 5-element array `arr[1]`, which the C standard does not define. In practice rows are contiguous, so every real compiler prints 24, and the official key is 24.

**Key idea:** a 2D array is one contiguous block, and `*(arr[1]+9)` is the element 9 places after the start of row 1.

</details>
