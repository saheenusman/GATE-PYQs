# 2017 CS1 Q53: Unsigned strlen subtraction inside a comparison

## Question

Consider the following C program.

```c
#include <stdio.h>
#include <string.h>

void printlength(char *s, char *t) {
    unsigned int c = 0;
    int len = ((strlen(s) - strlen(t)) > c) ? strlen(s) : strlen(t);
    printf("%d\n", len);
}

void main() {
    char *x = "abc";
    char *y = "defgh";
    printlength(x, y);
}
```

Recall that `strlen` is defined in `string.h` as returning a value of type `size_t`, which is an `unsigned int`. The output of the program is ______.

<details class="success" markdown="1">
<summary>Answer</summary>

**3**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**The key detail.** `strlen(s) - strlen(t)` is computed in **unsigned** arithmetic. There is no negative result:

$$3 - 5 \;\to\; 2^{N} - 2$$

where $N$ is the width of `size_t` (32 bits in the question's setting, giving $4294967294$).

**The comparison.** That huge value is compared with `c = 0` (promoted to the same unsigned type). $2^N - 2 > 0$ is **true**, so the conditional picks the first branch:

$$\text{len} = \text{strlen}(s) = \text{strlen("abc")} = 3$$

The output is **3**. A reader who forgets unsigned wrap-around would compute $3-5 = -2 > 0$ as false and print $5$.

**Code check:** compiled and run, the original program printed `3`. On this 64-bit machine `sizeof(size_t)` is 8, so the difference is $18446744073709551614$ and the result is still `3`. Casting the lengths to `int` first makes the comparison false, which would print `5`.

**Note on the snippet.** It uses `void main()`, which is non-standard; `gcc -Wall` warns but compiles it.

**Key idea:** subtracting unsigned values never goes negative; it wraps to a huge positive number, so "$>0$" is true whenever the operands differ.

</details>
