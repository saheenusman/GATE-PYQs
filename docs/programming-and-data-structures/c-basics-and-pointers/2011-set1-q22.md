# 2011 CS Q22: Output of a printf with pointer arithmetic on a string

## Question

What does the following fragment of C program print?

```c
Char c[] = "GATE2011";
char *p = c;
printf("%s", p + p[3] - p[1]);
```

- (A) GATE2011
- (B) E2011
- (C) 2011
- (D) 011

*Printed as is: `Char` in the first line is a typo for `char`.*

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The array is `G A T E 2 0 1 1` at indices $0$ to $7$, followed by `'\0'` at index $8$.

- `p[3]` is `'E'` (ASCII $69$) and `p[1]` is `'A'` (ASCII $65$).
- `p + p[3] - p[1]` is $p + 69 - 65 = p + 4$, so `%s` prints from index $4$.

Output: `2011`: (C).

- (A) would be `p`, (B) would be `p + 3`, (D) would be `p + 5`.

**Undefined behavior.** C evaluates `p + p[3] - p[1]` as `(p + p[3]) - p[1]`. The intermediate `p + 69` points far outside the $9$-byte array, which the C standard leaves undefined (pointer arithmetic must stay within the array or one past its end). Compilers give the intended `2011` in practice, but strictly the code is not well defined. The question assumes ordinary pointer arithmetic.

**Code check:** with `char` for `Char`, `gcc -Wall -Wextra` compiled it without warnings and the output was `2011` (offset $= 4$). As printed, `Char` is a compile error.

**Key idea:** pointer + char value - char value is plain pointer arithmetic; the net offset is the difference of the two characters (here 4).

</details>
