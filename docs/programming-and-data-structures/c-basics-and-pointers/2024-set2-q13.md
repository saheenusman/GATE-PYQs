# 2024 CS2 Q13: Output with right-to-left argument evaluation

## Question

Consider the following C program. Assume parameters to a function are evaluated from right to left.

```c
#include <stdio.h>
int g(int p) { printf("%d", p); return p; }
int h(int q) { printf("%d", q); return q; }
void f(int x, int y) {
  g(x);
  h(y);
}
int main() {
  f(g(10), h(20));
}
```

Which one of the following options is the CORRECT output of the above C program?

- (A) 20101020
- (B) 10202010
- (C) 20102010
- (D) 10201020

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Step 1: evaluate the arguments of `f(g(10), h(20))` right to left.**

- `h(20)` runs first and prints **20**.
- `g(10)` runs next and prints **10**.

**Step 2: run the body of `f(10, 20)`.**

- `g(x)` prints **10**.
- `h(y)` prints **20**.

Printed in order: `20`, `10`, `10`, `20`, i.e. **20101020**.

**Verified.** gcc on x86-64 happens to evaluate arguments right to left, and the program printed `20101020`.

**Note.** In the C standard the order of evaluation of function arguments is **unspecified**. The question fixes it by assumption.

**Why the others fail:** 10202010 and 10201020 start with the left argument. 20102010 mis-orders the body calls, which run `g(x)` before `h(y)`.

**Key idea:** evaluate arguments in the stated order first, then the called function's body.

</details>
