# 2017 CS1 Q13: Problem in a C program that allocates twice with malloc

## Question

Consider the following C code:

```c
#include <stdio.h>
int *assignval(int *x, int val) {
    *x = val;
    return x;
}

void main() {
    int *x = malloc(sizeof(int));
    if (NULL == x) return;
    x = assignval(x, 0);
    if (x) {
        x = (int *)malloc(sizeof(int));
        if (NULL == x) return;
        x = assignval(x, 10);
    }
    printf("%d\n", *x);
    free(x);
}
```

The code suffers from which one of the following problems:

- (A) compiler error as the return of `malloc` is not typecast appropriately
- (B) compiler error because the comparison should be made as `x == NULL` and not as shown
- (C) compiles successfully but execution may result in dangling pointer
- (D) compiles successfully but execution may result in memory leak

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Trace the pointer.**

1. First `malloc` returns block $B_1$; `x` points to $B_1$, and `assignval` stores 0 there.
2. `x` is non-null, so the `if` runs. A second `malloc` returns block $B_2$ and `x = B_2$. **The only pointer to $B_1$ is overwritten.**
3. `printf` prints 10, and `free(x)` frees $B_2$.

$B_1$ is never freed and is now unreachable: a **memory leak**. So **(D)**.

**Why the others fail.**

- (A) C does not require casting the result of `malloc` (the cast is allowed but unnecessary).
- (B) `NULL == x` and `x == NULL` mean the same thing.
- (C) A dangling pointer is one that refers to freed memory. `x` is freed at the very end and never used afterwards, and $B_2$ is valid when read.

**Code check:** compiled with `<stdlib.h>` added, the program printed `10`. AddressSanitizer reported `4 byte(s) leaked in 1 allocation(s)` from the first `malloc`.

**Note on the snippet.** As printed it omits `#include <stdlib.h>` and uses `void main()`. My `gcc -Wall` build warned about the implicit declaration of `malloc` and the non-`int` `main`, but compiled. Modern compilers (gcc 14 and newer) reject the implicit declaration by default. The question intends a program that compiles.

**Key idea:** reassigning a pointer that holds the only reference to a heap block, without `free`, leaks that block.

</details>
