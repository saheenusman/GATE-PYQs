# 2015 CS3 Q42: Output with a local, a static and a global variable named x

## Question

Consider the following C program.

```c
#include<stdio.h>
int f1(void);
int f2(void);
int f3(void);
int x = 10;

int main( )
{
    int x = 1;
    x += f1( ) + f2( ) + f3( ) + f2( );
    printf("%d", x);
    return 0;
}

int f1() { int x = 25; x++; return x; }
int f2() { static int x = 50; x++; return x; }
int f3() { x *= 10; return x; }
```

(The paper prints `return x};` in `f3`, a typo for `return x; }`.)

The output of the program is ________

<details class="success" markdown="1">
<summary>Answer</summary>

**230**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Three different `x` are in play:

- `main` has its own **local** `x = 1`. This hides the global one.
- `f1` has a **local** `x = 25` that is recreated on each call: it returns $26$.
- `f2` has a **static** `x = 50` that keeps its value between calls: the first call returns $51$, the second $52$.
- `f3` has no local `x`, so it uses the **global** one: $10 \times 10 = 100$, and returns $100$.

The two calls to `f2` return 51 and 52. C does not fix the order of evaluation of the operands of `+`, but the sum does not depend on it:

$$26 + 51 + 100 + 52 = 229$$

`main`'s `x` is only read and written by the `+=` itself, so there is no conflict:

$$x = 1 + 229 = 230$$

**Answer: 230.**

**Code check:** with the typo fixed, `gcc -Wall` gives no warnings and prints `230`. The program exactly as printed (`return x};`) does not compile ("expected ';' before '}'").

**Key idea:** a local hides the global, a `static` local keeps its value across calls, and a function with no local `x` changes the global.

</details>
