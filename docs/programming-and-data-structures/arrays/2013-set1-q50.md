# 2013 CS Q50: Test cases that capture the flaw (all inputs)

## Question

**Common data for Questions 50 and 51.** The procedure given below is required to find and replace certain characters inside an input character string supplied in array `A`. The characters to be replaced are supplied in array `oldc`, while their respective replacement characters are supplied in array `newc`. Array `A` has a fixed length of five characters, while arrays `oldc` and `newc` contain three characters each. However, the procedure is flawed.

```c
void find_and_replace(char *A, char *oldc, char *newc) {
    for (int i = 0; i < 5; i++)
        for (int j = 0; j < 3; j++)
            if (A[i] == oldc[j]) A[i] = newc[j];
}
```

The procedure is tested with the following four test cases.

1. `oldc = "abc"`, `newc = "dab"`
2. `oldc = "cde"`, `newc = "bcd"`
3. `oldc = "bca"`, `newc = "cda"`
4. `oldc = "abc"`, `newc = "bac"`

The tester now tests the program on all input strings of length five consisting of characters 'a', 'b', 'c', 'd' and 'e' with duplicates allowed. If the tester carries out this testing with the four test cases given above, how many test cases will be able to capture the flaw?

- (A) Only one
- (B) Only two
- (C) Only three
- (D) All four

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**The flaw.** The inner loop does not stop after a replacement. A character that was just replaced can match a **later** entry `oldc[j']` ($j' > j$) and be replaced a second time.

**Check each test.** A flaw needs `newc[j]` to equal some `oldc[j']` with $j' > j$.

| Test | Replacements | Chain? |
|---|---|---|
| 1 | a to d, b to a, c to b | No. New characters are either not in `oldc` or sit at an earlier index (a, b are `oldc[0]`, `oldc[1]`, already passed). |
| 2 | c to b, d to c, e to d | No. Same reason ($b$ is not in `cde`; $c$ is `oldc[0]`). |
| 3 | b to c, c to d, a to a | **Yes.** `b` becomes `c`, then `oldc[1] = c` matches it and it becomes `d`. |
| 4 | a to b, b to a, c to c | **Yes.** `a` becomes `b`, then `oldc[1] = b` matches and it becomes `a`. |

Only tests 3 and 4 can expose the flaw, so **two** test cases: (B).

**Code check:** compiled with `gcc -Wall` and run on all $5^5 = 3125$ strings against a reference that replaces each character once. Tests 1 and 2 differed on **0** strings; tests 3 and 4 each differed on **2101** strings.

**Why the others fail:** (A), (C), (D) count too few or too many tests.

**Flag:** this is a software-testing question; the closest topic is `arrays` (string/array processing).

**Key idea:** a test exposes a bug only if it makes the faulty path execute; here that needs a replacement character that matches a later `oldc` entry.

</details>
