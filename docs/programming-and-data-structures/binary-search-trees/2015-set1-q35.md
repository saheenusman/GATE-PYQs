# 2015 CS1 Q35: Worst-case insertion and deletion in a binary search tree

## Question

What are the worst-case complexities of insertion and deletion of a key in a binary search tree?

- (A) $\Theta(\log n)$ for both insertion and deletion
- (B) $\Theta(n)$ for both insertion and deletion
- (C) $\Theta(n)$ for insertion and $\Theta(\log n)$ for deletion
- (D) $\Theta(\log n)$ for insertion and $\Theta(n)$ for deletion

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

A plain BST has no balancing. Inserting keys in sorted order gives a skewed tree (a linked list) of height $n-1$.

- Insertion walks from the root down to a leaf position: $\Theta(h) = \Theta(n)$.
- Deletion must first search for the key (and possibly find a successor), also $\Theta(h) = \Theta(n)$.

Both are $\Theta(n)$ in the worst case: option (B). $\Theta(\log n)$ holds only for balanced trees (AVL, red-black), which the question does not assume. That rules out (A), (C) and (D).

**Key idea:** BST operations cost $\Theta(\text{height})$, and the worst-case height is $n-1$.

</details>
