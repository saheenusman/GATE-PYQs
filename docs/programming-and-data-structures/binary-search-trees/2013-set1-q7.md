# 2013 CS Q7: Insert into a BST: tightest bound

## Question

Which one of the following is the tightest upper bound that represents the time complexity of inserting an object into a binary search tree of $n$ nodes?

- (A) $O(1)$
- (B) $O(\log n)$
- (C) $O(n)$
- (D) $O(n \log n)$

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Insertion walks from the root to a leaf position, so the cost is the **height** of the tree.

A BST with no balancing can degenerate into a chain (for example, inserting sorted keys). Its height is $n-1$, so one insertion costs $O(n)$.

**Why the others fail:**

- (A) and (B) hold only for balanced trees (AVL, red-black), which the question does not assume.
- (D) is a valid but loose upper bound; one insertion never needs more than a root-to-leaf walk.

**Key idea:** BST operations cost $O(h)$, and $h$ can be as large as $n-1$ in the worst case.

</details>
