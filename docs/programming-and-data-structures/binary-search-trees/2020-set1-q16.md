# 2020 CS Q16: Inserting n² elements into an AVL tree of n elements

## Question

What is the worst case time complexity of inserting $n^2$ elements into an AVL-tree with $n$ elements initially?

- (A) $\Theta(n^4)$
- (B) $\Theta(n^2)$
- (C) $\Theta(n^2 \log n)$
- (D) $\Theta(n^3)$

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Cost of one insertion.** An AVL tree with $m$ nodes has height $\Theta(\log m)$. An insertion walks down one root-to-leaf path and then rebalances back up the same path, so it costs $O(\log m)$.

**Size during the process.** The tree starts with $n$ nodes and ends with $n + n^2$ nodes, so $n \le m \le n + n^2$. Then

$$\log m \le \log(n + n^2) \le \log(2n^2) = 2\log n + 1 = O(\log n),$$

and $\log m \ge \log n$. So every insertion costs $\Theta(\log n)$ in the worst case.

**Total:** $n^2$ insertions $\times\ \Theta(\log n)$ each $= \Theta(n^2 \log n)$.

**Why the others fail:**

- **(A) and (D)** would need each insertion to cost about $n^2$ or $n$. An AVL tree never needs that.
- **(B)** drops the $\log n$ factor, which the search path always costs.

**Key idea:** AVL keeps the height at $\Theta(\log m)$, so each insertion is logarithmic in the current size. The $n^2$ in the *count* of insertions, not in the tree size, drives the total.

</details>
