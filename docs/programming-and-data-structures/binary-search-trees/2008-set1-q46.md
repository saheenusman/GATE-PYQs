# 2008 CS Q46: Reconstructing a binary search tree from its postorder traversal

## Question

You are given the postorder traversal, $P$, of a binary search tree on the $n$ elements $1, 2, \ldots, n$. You have to determine the unique binary search tree that has $P$ as its postorder traversal. What is the time complexity of the most efficient algorithm for doing this?

- (A) $\Theta(\log n)$
- (B) $\Theta(n)$
- (C) $\Theta(n \log n)$
- (D) none of the above, as the tree cannot be uniquely determined

<summary>Answer</summary>

**D** (official key; see the Solution: disputed)

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Status: disputed.** The official key is (D), but I get (B). Both views follow.

**Key's view (D).** The key says a postorder such as $a, b, c$ can belong to more than one tree. That is true for a general binary tree.

**Why the question is different.** Here the tree is a **binary search tree** on the keys $1..n$, so its inorder traversal is $1, 2, \ldots, n$. Inorder plus postorder always determine a tree uniquely, so the tree **is** unique. Concretely:

- the **last** element of $P$ is the root;
- the elements before it split into a prefix smaller than the root (left subtree) and a suffix larger than the root (right subtree);
- repeat on each part.

**Linear time.** Scan $P$ from the right, building root, then right subtree, then left subtree, passing down open bounds $(lo, hi)$. An element is accepted as a child only if it lies inside the bounds. Each element is handled once, so the time is $\Theta(n)$. Reading the input already costs $\Omega(n)$, so $\Theta(n)$ is optimal. This is (B).

- (A) $\Theta(\log n)$ is below the input size.
- (C) $\Theta(n \log n)$ is what repeated BST insertion costs on a skewed tree, which is not needed.

**Code check:** for every $n$ from 1 to 9, I generated all BSTs on $1..n$ (Catalan numbers: 1, 2, 5, 14, 42, 132, 429, 1430, 4862). Their postorders were all distinct, and the $O(n)$ bounds-based rebuild recovered each tree exactly.

**Key idea:** for a BST the inorder is known (sorted), so the postorder fixes the tree, and it can be rebuilt in linear time.
