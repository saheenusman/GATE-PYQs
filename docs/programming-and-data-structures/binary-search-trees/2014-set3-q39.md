# 2014 CS3 Q39: Sum of the numbers in [L, H] in a balanced BST

## Question

Suppose we have a balanced binary search tree $T$ holding $n$ numbers. We are given two numbers $L$ and $H$ and wish to sum up all the numbers in $T$ that lie between $L$ and $H$. Suppose there are $m$ such numbers in $T$. If the tightest upper bound on the time to compute the sum is $O(n^a \log^b n + m^c \log^d n)$, the value of $a + 10b + 100c + 1000d$ is ______.

<details class="success" markdown="1">
<summary>Answer</summary>

**110**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Do an in-order style traversal that visits only the part of the tree that can contain values in $[L, H]$:

- go **left** only if $L <$ the current key, and go **right** only if the current key $< H$;
- add the key when it lies in $[L, H]$.

The search path down to $L$ (and to $H$) costs $O(\log n)$ in a balanced tree. Every node inside the range is visited once, which costs $O(m)$. So the total is

$$O(\log n + m).$$

Match with $O(n^a \log^b n + m^c \log^d n)$: $a = 0,\ b = 1,\ c = 1,\ d = 0$.

$$a + 10b + 100c + 1000d = 0 + 10 + 100 + 0 = 110.$$

**Code check:** on a perfectly balanced BST I counted visited nodes for range queries. For $n = 2^{18}$ and $m = 10$ about 25 nodes are visited (roughly $\log_2 n + m$), and for $m = 1000$ about 1016.

**Classification flag:** this is also a complexity question. The main topic is BST range queries, so it is filed under `binary-search-trees`.

**Key idea:** a range sum costs the search path ($\log n$) plus the output size ($m$).

</details>
