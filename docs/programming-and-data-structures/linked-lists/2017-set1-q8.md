# 2017 CS1 Q8: Behaviour of join that appends one linked list to another

## Question

Consider the C code fragment given below.

```c
typedef struct node {
  int data;
  node* next;
} node;

void join(node* m, node* n) {
  node* p = n;
  while (p->next != NULL) {
    p = p->next;
  }
  p->next = m;
}
```

Assuming that `m` and `n` point to valid NULL-terminated linked lists, invocation of `join` will

- (A) append list `m` to the end of list `n` for all inputs.
- (B) either cause a null pointer dereference or append list `m` to the end of list `n`.
- (C) cause a null pointer dereference for all inputs.
- (D) append list `n` to the end of list `m` for all inputs.

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**What the loop does.** `p` starts at `n` and walks until `p->next` is `NULL`, so `p` is the **last node of `n`**. Then `p->next = m` links `m` after it. So `m` is appended to the end of `n`, not the other way round. That rules out (D).

**When it breaks.** A *valid NULL-terminated list* can be **empty**, i.e. `n == NULL`. Then `p = NULL` and `p->next` dereferences a null pointer. So (A) ("for all inputs") is wrong.

If `n` is non-empty, `m` is appended. If `m` is `NULL` and `n` is non-empty, `n`'s last `next` is set to `NULL` again, still correct. So (C) ("for all inputs") is wrong too.

Hence either a null dereference (empty `n`) or a correct append: **(B)**.

**Code check:** with a corrected typedef (`struct node *next`), `join` on non-empty `n = 10,20` and `m = 1,2` gave `10 20 1 2`. Calling `join(m, NULL)` crashed with a segmentation fault.

**Note on the snippet.** As printed it does not compile in C: `node*` is used inside its own `typedef` before the name exists (`unknown type name 'node'`). I treated it as pseudo-C and used `struct node *next` to run it.

**Key idea:** a traversal that dereferences `p->next` must guard against an empty list, since `NULL` is a valid list.

</details>
