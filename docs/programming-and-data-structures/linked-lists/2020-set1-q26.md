# 2020 CS Q26: Building a sorted linked list by n insertions

## Question

What is the worst case time complexity of inserting $n$ elements into an empty linked list, if the linked list needs to be maintained in sorted order?

- (A) $\Theta(n)$
- (B) $\Theta(n \log n)$
- (C) $\Theta(n^2)$
- (D) $\Theta(1)$

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**One insertion.** To keep the list sorted, each new element must be placed at its correct position. A linked list has no random access, so finding that position means walking from the head, one node at a time. In the worst case the new element is the largest so far and goes at the end.

**Worst-case total.** When the $i$-th element arrives the list has $i-1$ nodes, so the walk takes up to $i-1$ steps. Inputs in increasing order force this every time:

$$\sum_{i=1}^{n} (i-1) = \frac{n(n-1)}{2} = \Theta(n^2).$$

**Why the others fail:**

- **(A) $\Theta(n)$** would need $O(1)$ per insertion. That is possible only if the input is already sorted *and* you keep a tail pointer, which is not the worst case.
- **(B) $\Theta(n \log n)$** would need binary search, but a linked list cannot be binary searched.
- **(D) $\Theta(1)$** cannot hold, since the work grows with $n$.

**Key idea:** finding the insertion point in a linked list is a linear scan, so $n$ sorted insertions cost $1+2+\dots+n = \Theta(n^2)$.

</details>
