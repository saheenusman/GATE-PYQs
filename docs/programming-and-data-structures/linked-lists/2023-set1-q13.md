# 2023 CS Q13: Delete a given node: SLL vs DLL

## Question

Let SLLdel be a function that deletes a node in a singly-linked list given a pointer to the node and a pointer to the head of the list. Similarly, let DLLdel be another function that deletes a node in a doubly-linked list given a pointer to the node and a pointer to the head of the list.

Let $n$ denote the number of nodes in each of the linked lists. Which one of the following choices is TRUE about the worst-case time complexity of SLLdel and DLLdel?

- (A) SLLdel is $O(1)$ and DLLdel is $O(n)$
- (B) Both SLLdel and DLLdel are $O(\log n)$
- (C) Both SLLdel and DLLdel are $O(1)$
- (D) SLLdel is $O(n)$ and DLLdel is $O(1)$

<details class="success" markdown="1">
<summary>Answer</summary>

**D (SLLdel is $O(n)$, DLLdel is $O(1)$)**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Singly linked list.** To unlink node $p$, you must change the `next` pointer of its **predecessor**. A singly linked node does not store its predecessor, so you walk from the head to find it. Worst case (node near the end): $O(n)$.

**Doubly linked list.** The node already holds `prev` and `next`:

```c
p->prev->next = p->next;
p->next->prev = p->prev;
```

No traversal, so $O(1)$. (Only the head and tail need a special case.)

**Why the others fail:** A has the two reversed. B: no list operation here takes $\log n$. C: SLLdel cannot be $O(1)$ without the predecessor.

**Key idea:** deleting from a linked list needs the predecessor. A DLL stores it, an SLL does not.

</details>
