# 2021 CS2 Q45: Linked list built with malloc, last next pointer never set

## Question

Consider the following ANSI C program:

```c
#include <stdio.h>
#include <stdlib.h>
struct Node{
    int value;
    struct Node *next;};
int main(){
    struct Node *boxE, *head, *boxN; int index = 0;
    boxE = head = (struct Node *) malloc(sizeof(struct Node));
    head->value = index;
    for (index = 1; index <= 3; index++){
        boxN = (struct Node *) malloc(sizeof(struct Node));
        boxE->next = boxN;
        boxN->value = index;
        boxE = boxN; }
    for (index = 0; index <= 3; index++) {
        printf("Value at index %d is %d\n", index, head->value);
        head = head->next;
        printf("Value at index %d is %d\n", index+1, head->value); } }
```

Which one of the statements below is correct about the program?

- (A) Upon execution, the program creates a linked-list of five nodes.
- (B) Upon execution, the program goes into an infinite loop.
- (C) It has a missing `return` which will be reported as an error by the compiler.
- (D) It dereferences an uninitialized pointer that may result in a run-time error.

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Build phase.** `head` is node 0. The first loop appends nodes 1, 2, 3, setting `next` of the previous node each time. The list has **4 nodes**, and the `next` of the last node (value 3) is **never assigned**. It holds whatever `malloc` left there.

**Print phase.** The loop runs for `index` = 0, 1, 2, 3.

- `index` 0, 1, 2: `head` moves 0→1→2→3, and every dereference is valid.
- `index` 3: `head` is node 3. The first `printf` is fine. Then `head = head->next` copies the uninitialized pointer, and `head->value` dereferences it.

So (D).

**Run check:** compiled with `gcc -Wall` (no warnings). It prints 7 lines (`Value at index 0 is 0` up to `Value at index 3 is 3`) and then dies with a segmentation fault (exit code 139). The same happens with `MALLOC_PERTURB_` set. The behaviour is undefined, so the outcome depends on what is in the freed or fresh heap memory, which is why the option says "may".

- (A) The list has four nodes, not five.
- (B) Both loops are bounded by `index <= 3`, so there is no infinite loop.
- (C) `main` without `return` is not a compile error. In C99 and later it implicitly returns 0, and `gcc -Wall` gave no warning.

**Key idea:** after building a list with `malloc`, the last node's `next` must be set to `NULL`. Otherwise walking past the end dereferences garbage.

</details>
