# 2010 CS Q36: Moving the last node of a singly linked list to the front

## Question

The following C function takes a simply-linked list as input argument. It modifies the list by moving the last element to the front of the list and returns the modified list. Some part of the code is left blank.

```c
typedef struct node {
    int value;
    struct node *next;
} Node;
Node *move_to_front(Node *head) {
    Node *p, *q;
    if ((head == NULL) || (head->next == NULL)) return head;
    q = NULL; p = head;
    while (p->next != NULL) {
        q = p;
        p = p->next;
    }
    _______________________________
    return head;
}
```

Choose the correct alternative to replace the blank line.

- (A) `q = NULL; p->next = head; head = p;`
- (B) `q->next = NULL; head = p; p->next = head;`
- (C) `head = p; p->next = q; q->next = NULL;`
- (D) `q->next = NULL; p->next = head; head = p;`

*Printed as is: the paper has `NULL:` for `NULL)` in the `if`, and `q=P;` for `q=p;`. Both are typos; the code above is corrected.*

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

After the loop, `p` is the **last** node and `q` is the node just before it. To move `p` to the front:

1. cut it off: `q->next = NULL;`
2. link it before the old head: `p->next = head;`
3. make it the new head: `head = p;`

The order matters: step 2 must use the old `head`, so it comes before step 3. That is (D).

Test on the list $1 \to 2 \to 3 \to 4$ (output of each option):

| Option | Result | Why wrong |
|---|---|---|
| (A) | $4 \to 1 \to 2 \to 3 \to 4 \to \dots$ | a cycle: `q->next` still points to `p` |
| (B) | $4 \to 4 \to 4 \dots$ | `head = p` first, so `p->next = head` makes `p` point to itself |
| (C) | $4 \to 3$ | `p->next = q` sends the new head backwards; $1, 2$ are lost |
| (D) | $4 \to 1 \to 2 \to 3$ | correct |

**Code check:** each option was compiled (`gcc -Wall -Wextra`) and run on the list $1,2,3,4$ with a bounded print. Results match the table.

**Key idea:** to rotate the last node to the front: detach it, point it at the old head, then update `head`, in that order.

</details>
