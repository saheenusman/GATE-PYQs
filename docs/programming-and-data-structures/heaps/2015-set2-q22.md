# 2015 CS2 Q22: Lower bound for fixing a tree whose subtrees are max-heaps

## Question

Consider a complete binary tree where the left and the right subtrees of the root are max-heaps. The lower bound for the number of operations to convert the tree to a heap is

- (A) $\Omega(\log n)$
- (B) $\Omega(n)$
- (C) $\Omega(n \log n)$
- (D) $\Omega(n^2)$

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Only the root can violate the heap property. Run **sift-down (heapify)** on the root: swap it with its larger child repeatedly. This follows one root-to-leaf path, so it costs $O(\log n)$.

In the worst case the root must travel all the way down (for example, when it is smaller than everything), which needs about $\log_2 n$ swaps. So the worst-case cost is $\Theta(\log n)$ and the lower bound is $\Omega(\log n)$.

(B), (C) and (D) claim more work than is needed, which contradicts the $O(\log n)$ algorithm.

**Key idea:** one bad root means one heapify along a single path, $\Theta(\log n)$.

</details>
