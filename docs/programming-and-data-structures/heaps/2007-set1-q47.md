# 2007 CS Q47: Comparisons for heap insertion using binary search on the path

## Question

Consider the process of inserting an element into a *Max Heap*, where the *Max Heap* is represented by an *array*. Suppose we perform a binary search on the path from the new leaf to the root to find the position for the newly inserted element, the number of *comparisons* performed is:

- (A) $\Theta(\log_2 n)$
- (B) $\Theta(\log_2\log_2 n)$
- (C) $\Theta(n)$
- (D) $\Theta(n\log_2 n)$

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

In a max heap, values along any root-to-leaf path are in non-increasing order, so the path is a sorted sequence. Its length is $\lfloor\log_2 n\rfloor + 1$.

Binary search over $m = \Theta(\log n)$ sorted items takes $\Theta(\log m) = \Theta(\log\log n)$ comparisons: (B).

- (A) $\log n$ comparisons is what the ordinary sift-up does (one per level).
- (C) and (D) are far larger than the path length.

(The data movement to make room is still $O(\log n)$ swaps or shifts; only the *comparisons* drop.)

**Code check:** not needed (path length $\log n$, binary search $\log$ of that).

**Key idea:** binary search on a sorted path of length $\log n$ costs $\log\log n$ comparisons.
