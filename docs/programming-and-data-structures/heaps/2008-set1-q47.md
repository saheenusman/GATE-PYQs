# 2008 CS Q47: Cost of inserting n more elements into a binary heap

## Question

We have a binary heap on $n$ elements and wish to insert $n$ more elements (not necessarily one after another) into this heap. The total time required for this is

- (A) $\Theta(\log n)$
- (B) $\Theta(n)$
- (C) $\Theta(n \log n)$
- (D) $\Theta(n^2)$

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The words "not necessarily one after another" allow a different strategy: put all $2n$ elements into one array and run **bottom-up heap construction** (`BUILD-HEAP`). Building a heap of $N$ elements takes $\Theta(N)$ time, so for $N = 2n$ the cost is $\Theta(n)$.

- It cannot be faster, because each of the $n$ new elements must at least be read: $\Omega(n)$.
- (A) $\Theta(\log n)$ is the cost of one insertion, not $n$ of them.
- (C) $\Theta(n \log n)$ is the cost of $n$ separate insertions, an upper bound that is not tight here.
- (D) $\Theta(n^2)$ is far too large.

**Code check:** bottom-up heapify on random arrays of $2n$ elements used 929, 15394 and 246906 comparisons for $n = 2^8, 2^{12}, 2^{16}$. That is about 1.8 to 1.9 comparisons per element, a constant, so the cost is linear.

**Key idea:** building a heap bottom-up takes linear time, so rebuilding a heap of size $2n$ costs $\Theta(n)$.

</details>
