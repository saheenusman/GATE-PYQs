# 2019 CS2 Q50: True statements about max-heaps and trees

## Question

Consider the following statements:

- I. The smallest element in a max-heap is always at a leaf node
- II. The second largest element in a max-heap is always a child of the root node
- III. A max-heap can be constructed from a binary search tree in $\Theta(n)$ time
- IV. A binary search tree can be constructed from a max-heap in $\Theta(n)$ time

Which of the above statements are TRUE?

- (A) I, II and III
- (B) I, II and IV
- (C) I, III and IV
- (D) II, III and IV

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Assume distinct keys.

**I true.** Every node of a max-heap is at least as big as its children. A node with a child cannot be the smallest, so the smallest must be a leaf.

**II true.** The root is the maximum. If the second largest were deeper than the root's children, its parent would be larger than it. The only element larger is the root, so the parent would be the root, a contradiction. So the second largest is a child of the root.

**III true.** Walk the BST in order to get a sorted array in $\Theta(n)$. A sorted array is already a heap if read in the right direction, and in any case an array can be turned into a heap by BUILD-HEAP in $\Theta(n)$.

**IV false.** If a BST could be built from a heap in $\Theta(n)$, then sorting would take $\Theta(n)$ comparisons: build a heap ($\Theta(n)$), make a BST ($\Theta(n)$), read it in order ($\Theta(n)$). That contradicts the $\Omega(n \log n)$ lower bound for comparison sorting.

**Code check:** on 2000 random max-heaps, I and II held every time.

**Key idea:** a heap holds partial order only. Turning it into a BST needs full sorted order, which costs $n \log n$.

</details>
