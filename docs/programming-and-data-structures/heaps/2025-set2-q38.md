# 2025 CS2 Q38: Cost of melding two data structures

## Question

A meld operation on two instances of a data structure combines them into one single instance of the same data structure. Consider the following data structures:

- **P:** Unsorted doubly linked list with pointers to the head node and tail node of the list.
- **Q:** Min-heap implemented using an array.
- **R:** Binary Search Tree.

Which ONE of the following options gives the worst-case time complexities for meld operation on instances of size $n$ of these data structures?

- (A) P: $\Theta(1)$, Q: $\Theta(n)$, R: $\Theta(n)$
- (B) P: $\Theta(1)$, Q: $\Theta(n \log n)$, R: $\Theta(n)$
- (C) P: $\Theta(n)$, Q: $\Theta(n \log n)$, R: $\Theta(n^2)$
- (D) P: $\Theta(1)$, Q: $\Theta(n)$, R: $\Theta(n \log n)$

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**P: unsorted doubly linked list, $\Theta(1)$.** Order does not matter, so link the tail of the first list to the head of the second:

```
tail1->next = head2;  head2->prev = tail1;  tail = tail2;
```

Constant work, thanks to the tail pointer.

**Q: array min-heap, $\Theta(n)$.**

1. Concatenate the two arrays: copy $n$ elements, $\Theta(n)$.
2. Run **Build-Heap** on the $2n$ elements. It is *linear*, not $n\log n$, because most nodes sit near the leaves and sift down only a few levels: $\sum_h \frac{2n}{2^{h+1}}\cdot h = O(n)$.

Inserting the elements one by one would cost $\Theta(n \log n)$, but that is not the best way.

**R: binary search tree, $\Theta(n)$.**

1. Inorder traversal of each tree gives a sorted array: $\Theta(n)$.
2. Merge the two sorted arrays: $\Theta(n)$.
3. Build a balanced BST from the sorted array by picking the middle as the root and recursing: $\Theta(n)$.

Inserting the $n$ keys of one tree into the other would cost $\Theta(n \log n)$ for balanced trees and $\Theta(n^2)$ for chains, but the flatten-merge-rebuild route avoids that.

**Why the other options fail**

| Option | Problem |
|---|---|
| B | Heap meld is linear via Build-Heap, not $n\log n$ |
| C | List meld is $\Theta(1)$, and the heap and BST bounds are not tight |
| D | BST meld is linear by merging sorted inorder lists, not $n\log n$ |

**Checked in code.** I implemented both melds and ran them on random data for $n = 1000, 2000, 4000, 8000$. The results were valid heaps and BSTs. Build-Heap did about $1.7n$ sift steps each time (1738, 3486, 6867, 13797): constant steps per element, so linear.

**Key idea:** meld is $\Theta(1)$ for an unsorted list with a tail pointer, and $\Theta(n)$ for an array heap (concatenate + Build-Heap) and for a BST (flatten, merge, rebuild).
