# 2011 CS Q6: Mode switch time versus process switch time

## Question

Let the time taken to switch between user and kernel modes of execution be $t_1$ while the time taken to switch between two processes be $t_2$. Which of the following is **TRUE**?

- (A) $t_1 > t_2$
- (B) $t_1 = t_2$
- (C) $t_1 < t_2$
- (D) nothing can be said about the relation between $t_1$ and $t_2$

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

A **mode switch** only changes the privilege level and saves or restores a small amount of state (program counter, a few registers) on entering or leaving the kernel.

A **process switch** always includes a mode switch (the kernel must run to do it) and then more work:

- save the registers of the old process in its PCB and load those of the new one;
- change the address space (page table base register, usually a TLB flush);
- update scheduler data structures, and later pay cache and TLB misses for the new process.

So $t_1 < t_2$: (C).

- (A) says the reverse.
- (B) would need the extra work above to be free.
- (D) is wrong because a process switch contains a mode switch, so the order is fixed.

**Key idea:** a context switch costs more than a mode switch because it contains one and adds state save/restore and address-space change.

</details>
