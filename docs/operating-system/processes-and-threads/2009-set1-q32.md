# 2009 CS Q32: Process state transitions with preemptive scheduling

## Question

In the following process state transition diagram for a uniprocessor system, assume that there are always some processes in the ready state:

![A process state diagram with five states: Start, Ready, Running, Terminated and Blocked. Arrow A goes from Start to Ready. Arrow B goes from Ready to Running. Arrow C goes from Running back to Ready. Arrow D goes from Running to Terminated. Arrow F goes from Running to Blocked. Arrow E goes from Blocked to Ready.](../../assets/2009/set1-q32.png)

Now consider the following statements:

- I. If a process makes a transition D, it would result in another process making transition A immediately.
- II. A process P2 in blocked state can make transition E while another process P1 is in running state.
- III. The OS uses preemptive scheduling.
- IV. The OS uses non-preemptive scheduling.

Which of the above statements are TRUE?

- (A) I and II
- (B) I and III
- (C) II and III
- (D) II and IV

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Reading the diagram:

| Arrow | Transition |
|---|---|
| A | Start to Ready (a new process is admitted) |
| B | Ready to Running (dispatch) |
| C | Running to Ready (the running process is taken off the CPU) |
| D | Running to Terminated |
| E | Blocked to Ready (the awaited event, such as I/O, completes) |
| F | Running to Blocked |

- **I is false.** A is the admission of a **new** process. When a process terminates (D), the CPU is given to a process that is already ready, through B. We are told some process is always ready, so nothing forces another process to start (A).
- **II is true.** E is triggered by an event such as I/O completion, not by the CPU. A blocked process can become ready while another process runs.
- **III is true.** Arrow C moves a process from Running to Ready even though it did not block or finish. That is **preemption** (time slice expired or a higher-priority process arrived).
- **IV is false.** In a non-preemptive system there would be no arrow C.

True: II and III, so (C).

- (A) and (B) contain I, which is false.
- (D) contains IV, which contradicts III.

**Code check:** none (reading a diagram, nothing to run).

**Key idea:** a Running-to-Ready transition means the OS preempts; Blocked-to-Ready is driven by events, not by the CPU.

</details>
