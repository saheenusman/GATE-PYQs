# 2025 CS1 Q29: Times a process re-enters the ready queue

## Question

Suppose in a multiprogramming environment, the following C program segment is executed. A process goes into I/O queue whenever an I/O related operation is performed. Assume that there will always be a context switch whenever a process requests for an I/O, and also whenever the process returns from an I/O. The number of times the process will enter the ready queue during its lifetime (not counting the time the process enters the ready queue when it is run initially) is _______. (Answer in integer)

```c
int main()
{
    int x=0,i=0;
    scanf("%d",&x);
    for(i=0; i<20; i++)
    {
        x = x+20;
        printf("%d\n",x);
    }
    return 0;
}
```

<details class="success" markdown="1">
<summary>Answer</summary>

**21**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The process joins the ready queue again **each time an I/O operation finishes**. So count the I/O operations:

| Statement | Executions | I/O operations |
|---|---|---|
| `scanf` | 1 | 1 |
| `printf` inside the loop ($i = 0, \dots, 19$) | 20 | 20 |

Total $1 + 20 = 21$ I/O operations. After each one the process returns from I/O and enters the ready queue, so it does so **21 times** (the very first entry, when the process is started, is not counted).

The arithmetic `x = x+20` and the loop control use only the CPU, so they never cause a trip through the I/O queue.

**Key idea:** every I/O request sends the process to the I/O queue, and its completion puts it back in the ready queue: count the I/O calls.

</details>
