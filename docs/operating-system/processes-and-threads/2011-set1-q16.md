# 2011 CS Q16: What the OS maintains on a per-thread basis

## Question

A thread is usually defined as a "light weight process" because an operating system (OS) maintains smaller data structures for a thread than for a process. In relation to this, which of the following is **TRUE**?

- (A) On per-thread basis, the OS maintains *only* CPU register state
- (B) The OS does not maintain a separate stack for each thread
- (C) On per-thread basis, the OS does not maintain virtual memory state
- (D) On per-thread basis, the OS maintains *only* scheduling and accounting information

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Threads of one process **share** the address space, so the virtual memory state (page tables, memory map) and open files are kept once per process. Each thread has its own register set, its own stack, and its own scheduling state.

- (A) false: besides registers, the OS keeps the stack pointer, scheduling state and priority.
- (B) false: every thread needs its own stack to have its own call chain and local variables.
- (C) **true:** the virtual memory state belongs to the process, not to each thread.
- (D) false: it also keeps the CPU registers and stack for each thread.

So the answer is (C).

**Key idea:** threads share the process's address space and resources; only the execution context (registers, stack, scheduling state) is per thread.

</details>
