# 2021 CS2 Q52: Two processes with two threads each sharing a global counter

## Question

Consider the following multi-threaded code segment (in a mix of C and pseudo-code), invoked by two processes P1 and P2, and each of the processes spawns two threads T1 and T2:

```c
int x = 0;   // global
Lock L1;     // global
main() {
  create a thread to execute foo();  // Thread T1
  create a thread to execute foo();  // Thread T2
  wait for the two threads to finish execution;
  print (x);}

foo() {
  int y = 0;
  Acquire L1;
  x = x + 1;
  y = y + 1;
  Release L1;
  print (y);}
```

Which of the following statement(s) is/are correct?

- (A) Both P1 and P2 will print the value of `x` as 2.
- (B) At least one of P1 and P2 will print the value of `x` as 4.
- (C) At least one of the threads will print the value of `y` as 2.
- (D) Both T1 and T2, in both the processes, will print the value of `y` as 1.

<details class="success" markdown="1">
<summary>Answer</summary>

**A and D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Two facts decide everything.

- **Processes do not share memory.** P1 and P2 each have their own copy of `x` (and of `L1`). Within one process, its two threads share `x`, and the lock makes `x = x + 1` atomic.
- **`y` is a local variable.** Each call of `foo()` has its own `y`, which starts at 0.

So in each process `x` ends at $0+1+1=2$, and every thread prints `y` = 1.

- (A) **Correct.** Each process prints 2.
- (B) Wrong. Nothing adds the two processes' counts, so 4 is impossible.
- (C) Wrong. A thread's `y` is never shared, so it is never 2.
- (D) **Correct.** All four threads print 1.

**Run check:** a C program with `fork()` and two `pthread`s per process (`gcc -Wall -pthread`) printed `y=1` four times and `x=2` for both P1 and P2.

**Key idea:** threads share globals but not locals; separate processes share nothing.

</details>
