# 2021 CS1 Q24: C library functions that always make a system call

## Question

Which of the following standard C library functions will *always* invoke a system call when executed from a single-threaded process in a UNIX/Linux operating system?

- (A) `exit`
- (B) `malloc`
- (C) `sleep`
- (D) `strlen`

<details class="success" markdown="1">
<summary>Answer</summary>

**A and C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

- (A) `exit` always ends in a system call (`exit_group`) to terminate the process. **Yes.**
- (B) `malloc` is served from the heap the library already holds. It asks the kernel (`brk` or `mmap`) only when that heap runs out. **Not always.**
- (C) `sleep` has to block the process, which needs the kernel (`nanosleep`). **Yes.**
- (D) `strlen` only reads memory in user space. **No.**

Answer: **A and C**.

**Key idea:** library functions that touch only user memory need no system call, while ones that must involve the kernel (terminate, block, I/O) always do.

</details>
