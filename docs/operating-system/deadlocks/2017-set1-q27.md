# 2017 CS1 Q27: Minimum threads and locks for a deadlock with non-reentrant locks

## Question

A multithreaded program P executes with $x$ number of threads and uses $y$ number of locks for ensuring mutual exclusion while operating on shared memory locations. All locks in the program are *non-reentrant*, i.e., if a thread holds a lock $l$, then it cannot re-acquire lock $l$ without releasing it. If a thread is unable to acquire a lock, it blocks until the lock becomes available. The *minimum* value of $x$ and the *minimum* value of $y$ together for which execution of P can result in a deadlock are:

- (A) $x = 1,\ y = 2$
- (B) $x = 2,\ y = 1$
- (C) $x = 2,\ y = 2$
- (D) $x = 1,\ y = 1$

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**The usual picture.** A deadlock between threads needs a cycle, like $T_1$ holding $l_1$ and wanting $l_2$ while $T_2$ holds $l_2$ and wants $l_1$. That takes 2 threads and 2 locks, which is option (C).

**The twist: non-reentrant locks.** A single thread can deadlock *by itself*. With $x=1$ and $y=1$:

1. The thread acquires lock $l$.
2. It tries to acquire $l$ again without releasing it. The lock is non-reentrant, so the thread blocks.
3. The only thread that could release $l$ is the blocked thread itself, so it waits forever.

That is a deadlock. Neither value can go below 1 (no threads or no locks means no blocking), so the minimum is $x = 1,\ y = 1$: **(D)**.

**Why the others fail.** (A), (B), (C) can also deadlock, but they are not minimal: a single thread and a single lock already suffice.

**Key idea:** with non-reentrant locks, re-acquiring a lock you already hold is a self-deadlock, so one thread and one lock are enough.

</details>
