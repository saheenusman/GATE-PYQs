# 2021 CS2 Q53: A resource scheme that kills the current owner

## Question

Consider a computer system with multiple shared resource types, with one instance per resource type. Each instance can be owned by only one process at a time. Owning and freeing of resources are done by holding a global lock (L). The following scheme is used to own a resource instance:

```
function OwnResource(Resource R)
    Acquire lock L // a global lock
    if R is available then
        Acquire R
        Release lock L
    else
        if R is owned by another process P then
            Terminate P, after releasing all resources owned by P
            Acquire R
            Restart P
            Release lock L
        end if
    end if
end function
```

Which of the following choice(s) about the above scheme is/are correct?

- (A) The scheme ensures that deadlocks will not occur.
- (B) The scheme may lead to live-lock.
- (C) The scheme may lead to starvation.
- (D) The scheme violates the mutual exclusion property.

<details class="success" markdown="1">
<summary>Answer</summary>

**A, B and C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The scheme never makes a requester wait. If $R$ is free it takes it. Otherwise it **kills the owner**, takes all of the owner's resources away, and takes $R$.

- (A) **Correct.** Deadlock needs hold-and-wait with a circular wait. Here nobody waits for a resource while holding others, because a request either succeeds at once or preempts the owner. So deadlock cannot occur.
- (B) **Correct.** The restarted process $P$ may immediately request a resource held by the process that just killed it, and kill that process in turn. Two processes can keep killing and restarting each other, so everyone is busy and nobody finishes.
- (C) **Correct.** A process can be terminated again and again by others before it completes, so it may starve.
- (D) Wrong. $P$ is terminated and its resources released **before** $R$ is acquired, and all of this happens under lock $L$. So $R$ always has at most one owner, and mutual exclusion holds.

**Key idea:** preempting resources removes deadlock, but it can introduce live-lock and starvation.

</details>
