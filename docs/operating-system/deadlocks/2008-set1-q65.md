# 2008 CS Q65: Deadlock prevention versus deadlock avoidance

## Question

Which of the following is NOT true of deadlock prevention and deadlock avoidance schemes?

- (A) In deadlock prevention, the request for resources is always granted if the resulting state is safe
- (B) In deadlock avoidance, the request for resources is always granted if the resulting state is safe
- (C) Deadlock avoidance is less restrictive than deadlock prevention
- (D) Deadlock avoidance requires knowledge of resource requirements a priori

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

- **Prevention** works by making at least one of the four necessary conditions impossible (for example forbidding hold-and-wait). A request can be refused because of that rule **even when the resulting state would be safe**. So (A) is **not true**.
- **Avoidance** (for example the Banker's algorithm) grants a request exactly when the resulting state is safe: (B) is true.
- Because avoidance refuses only requests that lead to unsafe states, it is less restrictive than prevention: (C) is true.
- To decide whether a state is safe, avoidance needs each process's maximum resource needs in advance: (D) is true.

**Key idea:** prevention is the more restrictive scheme and may deny a request even if the resulting state is safe.

</details>
