# 2009 CS Q30: Deadlock with a non-preemptive allocation policy

## Question

Consider a system with 4 types of resources R1 (3 units), R2 (2 units), R3 (3 units), R4 (2 units). A non-preemptive resource allocation policy is used. At any given instance, a request is not entertained if it cannot be completely satisfied. Three processes P1, P2, P3 request the resources as follows if executed independently.

**Process P1:**

- t=0: requests 2 units of R2
- t=1: requests 1 unit of R3
- t=3: requests 2 units of R1
- t=5: releases 1 unit of R2 and 1 unit of R1
- t=7: releases 1 unit of R3
- t=8: requests 2 units of R4
- t=10: Finishes

**Process P2:**

- t=0: requests 2 units of R3
- t=2: requests 1 unit of R4
- t=4: requests 1 unit of R1
- t=6: releases 1 unit of R3
- t=8: Finishes

**Process P3:**

- t=0: requests 1 unit of R4
- t=2: requests 2 units of R1
- t=5: releases 2 units of R1
- t=7: requests 1 unit of R2
- t=8: requests 1 unit of R3
- t=9: Finishes

Which one of the following statements is TRUE if all three processes run concurrently starting at time $t = 0$ ?

- (A) All processes will finish without any deadlock.
- (B) Only P1 and P2 will be in deadlock.
- (C) Only P1 and P3 will be in deadlock.
- (D) All three processes will be in deadlock.

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Track the free units as (R1, R2, R3, R4). Start: $(3, 2, 3, 2)$. A request that cannot be fully met makes the process **wait** (it keeps what it holds). A finishing process releases everything it holds.

| Time | Event | Free after |
|---|---|---|
| 0 | P1 takes 2 R2; P2 takes 2 R3; P3 takes 1 R4 | (3,0,1,1) |
| 1 | P1 takes 1 R3 | (3,0,0,1) |
| 2 | P2 takes 1 R4; P3 takes 2 R1 | (1,0,0,0) |
| 3 | P1 wants 2 R1, only 1 free: **P1 waits** | (1,0,0,0) |
| 4 | P2 takes 1 R1 | (0,0,0,0) |
| 5 | P3 releases 2 R1; P1 gets its 2 R1, then releases 1 R2 and 1 R1 | (1,1,0,0) |
| 6 | P2 releases 1 R3 | (1,1,1,0) |
| 7 | P1 releases 1 R3; P3 takes 1 R2 | (1,0,2,0) |
| 8 | P1 wants 2 R4, none free: **P1 waits**. P2 finishes and frees its units. P3 takes 1 R3 | (2,0,2,1) |
| 9 | P3 finishes and frees its units; P1 gets 2 R4 | (2,1,3,0) |
| 10 | P1 finishes | all free |

Each wait ends: at $t = 5$ P1's wait is ended by P3's release, and at $t = 9$ its second wait is ended by P3 finishing. At no time are all unfinished processes waiting on each other. So **all three finish and there is no deadlock**: (A).

- (B), (C) and (D) each say some processes stay blocked forever. P1 is blocked twice, but in both cases a process that is not blocked (P3) holds the needed units and then releases them.

**Code check:** a small simulation of this policy (a waiting process continues only when its request can be met, later steps never earlier than their stated times) was run with six different orders of handling processes within a time step. In all six, no process was left unfinished; the finish times were P2 at $8$, P3 at $9$, P1 at $10$.

**Key idea:** a wait is a deadlock only if the resources it needs are held by processes that are themselves waiting; here the holder (P3) keeps running and releases them.

</details>
