# 2012 CS Q41: Maximum file size with direct, indirect and double indirect blocks

## Question

A file system with $300$ GByte disk uses a file descriptor with $8$ direct block addresses, $1$ indirect block address and $1$ doubly indirect block address. The size of each disk block is $128$ Bytes and the size of each disk block address is $8$ Bytes. The maximum possible file size in this file system is

- (A) 3 KBytes
- (B) 35 KBytes
- (C) 280 KBytes
- (D) dependent on the size of the disk

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Pointers per block: $128 / 8 = 16$.

| Part | Data blocks |
|---|---|
| 8 direct | 8 |
| 1 indirect (16 pointers) | 16 |
| 1 double indirect ($16 \times 16$) | 256 |
| **Total** | **280** |

$$280 \times 128 \text{ B} = 35840 \text{ B} = 35 \text{ KB}.$$

This is (B).

- (A) counts too few blocks.
- (C) is the number of blocks, $280$, read as KB; each block is only $128$ B.
- (D) the disk is $300$ GB, about $2.5 \times 10^9$ blocks, which an 8-byte address can name easily. The limit comes from the descriptor layout, not the disk.

**Key idea:** max file size $=$ (direct + indirect + double indirect data blocks) $\times$ block size.

</details>
