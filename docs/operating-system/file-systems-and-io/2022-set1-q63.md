# 2022 CS Q63: Inserting a block in the middle of a file

## Question

Consider two files systems $A$ and $B$, that use contiguous allocation and linked allocation, respectively. A file of size 100 blocks is already stored in $A$ and also in $B$. Now, consider inserting a new block in the middle of the file (between 50th and 51st block), whose data is already available in the memory. Assume that there are enough free blocks at the end of the file and that the file control blocks are already in memory. Let the number of disk accesses required to insert a block in the middle of the file in $A$ and $B$ are $n_A$ and $n_B$, respectively, then the value of $n_A + n_B$ is ______.

<details class="success" markdown="1">
<summary>Answer</summary>

**153**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**File system A (contiguous).** To open a gap after block 50, blocks 51 to 100 (50 blocks) must each move one position towards the end. Each move is one read and one write, so $50 \times 2 = 100$ accesses. Then one write for the new block:

$$n_A = 100 + 1 = 101$$

**File system B (linked).** Reach block 50 by following pointers from the start: 50 block reads (the file control block is in memory, so there is no extra read for the head pointer). Then write the new block with its pointer set to the old block 51 (1 write), and update block 50's pointer to the new block (1 write):

$$n_B = 50 + 1 + 1 = 52$$

$$n_A + n_B = 101 + 52 = 153$$

**Key idea:** contiguous files pay to shift data; linked files pay to traverse to the insertion point.

**Counting convention:** this matches the official answer (153). It counts reading block 50 as part of the 50 traversal reads and counts both writes.

</details>
