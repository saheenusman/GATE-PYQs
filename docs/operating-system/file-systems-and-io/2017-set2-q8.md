# 2017 CS2 Q8: File allocation schemes that avoid external fragmentation

## Question

In a file allocation system, which of the following allocation scheme(s) can be used if no external fragmentation is allowed?

- I. Contiguous
- II. Linked
- III. Indexed

Options:

- (A) I and III only
- (B) II only
- (C) III only
- (D) II and III only

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Why contiguous fails.** Contiguous allocation needs a single run of free blocks. As files are created and deleted, free space breaks into small holes that are individually too small, which is **external fragmentation**.

**Linked allocation (II).** A file's blocks can be anywhere on the disk, joined by pointers. Any free block can be used, so there is no external fragmentation.

**Indexed allocation (III).** An index block lists the file's blocks, which can be anywhere. Again any free block can be used, so no external fragmentation.

So II and III: **(D)**.

**Why the others fail.** (A) includes contiguous, which does suffer. (B) and (C) each drop one of the two schemes that work.

**Status note:** file-allocation theory (no program applies); the answer matches the official key.

**Key idea:** only contiguous allocation needs contiguous free space; linked and indexed use scattered blocks.

</details>
