# 2008 CS Q64: Synchronous and asynchronous I/O and interrupts

## Question

Which of the following statements about synchronous and asynchronous I/O is NOT true?

- (A) An ISR is invoked on completion of I/O in synchronous I/O but not in asynchronous I/O
- (B) In both synchronous and asynchronous I/O, an ISR (Interrupt Service Routine) is invoked after completion of the I/O
- (C) A process making a synchronous I/O call waits until I/O is complete, but a process making an asynchronous I/O call does not wait for completion of the I/O
- (D) In the case of synchronous I/O, the process waiting for the completion of I/O is woken up by the ISR that is invoked after the completion of I/O

<details class="success" markdown="1">
<summary>Answer</summary>

**A** (my answer; the supplied key leaves Q64 blank)

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Official key:** the key table in the supplied PDF has no entry for Q64, so I cannot check against it. The answer below is my own derivation.

In **both** kinds of I/O the device raises an interrupt when the transfer completes, and the ISR runs. The difference is what the calling process does meanwhile:

- **Synchronous:** the process blocks until the I/O finishes; the ISR wakes it up.
- **Asynchronous:** the process keeps running; the ISR still runs on completion and marks the operation complete (or notifies the process).

So:

- (A) is **not true**: it says no ISR runs for asynchronous I/O, but one does.
- (B) is true.
- (C) is true.
- (D) is true.

The statement that is NOT true is (A).

**Classification note:** this is an I/O-handling question, so I filed it under `file-systems-and-io`.

**Key idea:** both synchronous and asynchronous I/O complete through an interrupt; they differ only in whether the caller waits.
