# 2008 CS Q20: Allocation of data blocks of a large file in Unix

## Question

The data blocks of a very large file in the Unix file system are allocated using

- (A) contiguous allocation
- (B) linked allocation
- (C) indexed allocation
- (D) an extension of indexed allocation

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Unix keeps a file's block pointers in its **inode**: a few **direct** pointers, then a **single indirect**, a **double indirect** and a **triple indirect** pointer. Indirect pointers point to blocks that are themselves tables of block pointers. For a very large file the data blocks are reached through these multi-level index blocks, which is an **extension of indexed allocation**: (D).

- (A) Contiguous allocation would need one big free region and suffers from external fragmentation.
- (B) Linked allocation makes random access slow (chains of pointers) and is not what Unix uses.
- (C) Plain single-level indexed allocation would limit the file size to what one index block can address. The multi-level scheme removes that limit, so "extension of" is the better description.

**Key idea:** the Unix inode combines direct, single, double and triple indirect pointers: a multi-level indexed allocation.

</details>
