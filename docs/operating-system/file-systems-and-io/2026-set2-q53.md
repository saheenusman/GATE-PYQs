# 2026 CS2 Q53: Disk blocks needed to hold a free-block list

## Question

To keep track of free blocks, a file system can use bitmaps or linked lists. Suppose a **linked list** is used. The disk is 16 GB, the block size is 2 KB, and block numbers are 32 bits long. Each block of the list also holds one 4-byte pointer to the next block of the list.

The number of blocks required to hold the free disk block numbers is _____. (answer in integer) (Note: 1K $= 2^{10}$, 1G $= 2^{30}$)

<details class="success" markdown="1">
<summary>Answer</summary>

**16417**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Step 1: number of disk blocks.**

$$\frac{16\ \text{GB}}{2\ \text{KB}} = \frac{2^{34}}{2^{11}} = 2^{23} = 8{,}388{,}608.$$

In the worst case all of them are free, so we must store $2^{23}$ block numbers.

**Step 2: block numbers per list block.** A block has $2048$ bytes. One 4-byte pointer is taken by the "next" link, leaving $2044$ bytes. Each block number is 4 bytes, so

$$\frac{2044}{4} = 511 \text{ numbers per block}.$$

**Step 3: blocks needed.**

$$\left\lceil \frac{8{,}388{,}608}{511} \right\rceil = \lceil 16416.06\ldots \rceil = 16417.$$

(Check: $511 \times 16416 = 8{,}388{,}576$, which leaves 32 numbers over, so one more block is needed.)

**Verified** by computing the numbers in Python.

**Key idea:** subtract the next-pointer from the block size before dividing, and round up.

</details>
