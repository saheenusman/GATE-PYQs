# 2019 CS2 Q52: Maximum file size with direct, single and double indirect blocks

## Question

The index node (inode) of a Unix-like file system has 12 direct, one single-indirect and one double-indirect pointers. The disk block size is 4 kB, and the disk block address is 32-bits long. The maximum possible file size is (rounded off to 1 decimal place) ________ GB.

<details class="success" markdown="1">
<summary>Answer</summary>

**4.0**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

A 4 kB block holds $4096 / 4 = 1024$ addresses (32 bits $=$ 4 bytes).

| Pointers | Data blocks reached |
|---|---|
| 12 direct | $12$ |
| 1 single-indirect | $1024$ |
| 1 double-indirect | $1024^2 = 1{,}048{,}576$ |
| Total | $1{,}049{,}612$ |

$$\text{size} = 1{,}049{,}612 \times 4096 \text{ B} = 4{,}299{,}210{,}752 \text{ B} \approx 4.004 \text{ GB}.$$

With binary units ($1\text{ GB} = 2^{30}$ B) this is **4.0 GB**.

**Why the key has two ranges.** The key accepts **4.0 to 4.1** and **3.7 to 3.8**. Those match different unit readings:

| Reading | Size | Result |
|---|---|---|
| Binary kB and GB ($4096$ B blocks, $2^{30}$) | $4{,}299{,}210{,}752$ B | $4.004$ GB |
| Decimal kB and GB ($4000$ B blocks, 1000 pointers, $10^9$) | $4{,}004{,}048{,}000$ B | $4.004$ GB |
| Decimal kB, binary GB ($4000$ B blocks, $2^{30}$) | $4{,}004{,}048{,}000$ B | $3.729$ GB |

So 3.7 to 3.8 comes from mixing 4000-byte blocks with a binary GB. The reading that mixes binary blocks with a decimal GB would give $4.3$, which the key does not accept.

**Code check:** the arithmetic above was computed in code for both unit systems.

**Key idea:** size $=$ (direct $+$ $P$ $+$ $P^2$) $\times$ block size, where $P$ is pointers per block.

</details>
