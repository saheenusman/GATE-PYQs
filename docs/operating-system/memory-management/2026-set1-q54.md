# 2026 CS1 Q54: Impossible sequence of TLB, page table and cache events

## Question

A system has a cache and a memory management unit (MMU). The cache takes **physical** addresses. The MMU has a translation lookaside buffer (TLB). When a page is evicted from main memory, the corresponding cache blocks are marked invalid.

For a given memory reference, which of the following sequences of events can **NEVER** happen?

- (A) TLB miss, Page table hit, Cache hit
- (B) TLB hit, Page table miss, Cache hit
- (C) TLB miss, Page table miss, Cache hit
- (D) TLB miss, Page table miss, Cache miss

<details class="success" markdown="1">
<summary>Answer</summary>

**B and C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Order of events.** Virtual address, then TLB lookup. On a TLB miss, look in the page table. A page table *miss* means the page is not in memory (page fault). Only then is the physical address known and the cache searched.

**(A) TLB miss, page table hit, cache hit: possible.** The mapping was not in the TLB, but the page is in memory and its block is in the cache.

**(B) TLB hit, page table miss, cache hit: impossible.** A TLB hit means the translation is valid, so the page is in memory. A page table miss (page not in memory) contradicts that. (Also, a page table lookup is not even done after a TLB hit.)

**(C) TLB miss, page table miss, cache hit: impossible.** A page table miss means a page fault: the page is not in memory. When pages leave memory, their cache blocks are marked invalid. So the cache cannot hold a valid block for that page.

**(D) TLB miss, page table miss, cache miss: possible.** After the page fault, the page is loaded, and its cache blocks are not there yet, so the cache misses.

**Key idea:** a TLB hit implies the page is in memory, and a page fault implies the cache holds nothing valid for that page.

</details>
