# 2010 CS Q24: Page faults with FIFO replacement and 4 frames on a sequence followed by its reverse

## Question

A system uses FIFO policy for page replacement. It has $4$ page frames with no pages loaded to begin with. The system first accesses $100$ distinct pages in some order and then accesses the same $100$ pages but now in the reverse order. How many page faults will occur?

- (A) $196$
- (B) $192$
- (C) $197$
- (D) $195$

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**First pass.** All $100$ pages are distinct, so every access faults: $100$ faults. The frames end up holding the last four pages accessed, pages $97, 98, 99, 100$.

**Second pass (reverse).** The order is $100, 99, 98, 97, 96, 95, \dots, 1$.

- The first $4$ accesses ($100, 99, 98, 97$) are all in the frames: $0$ faults.
- Page $96$ is not in memory and faults. FIFO evicts the oldest page, which is $97$ (the oldest of those still held). From here on every remaining page ($96$ down to $1$) is absent when requested, because each page evicted is one that has already been used and is not asked for again.

That is $96$ more faults.

Total: $100 + 96 = 196$: (A).

- (B), (C) and (D) do not match the count above; the simulation gives exactly $196$.

**Code check:** a Python FIFO simulation (4 frames, pages $0$ to $99$ and then $99$ to $0$) gave $196$ faults.

**Key idea:** FIFO keeps the last 4 loaded pages, so exactly those 4 pages hit when the sequence is reversed.

</details>
