# 2009 CS Q9: Page replacement policy with Belady's anomaly

## Question

In which one of the following page replacement policies, Belady's anomaly may occur?

- (A) FIFO
- (B) Optimal
- (C) LRU
- (D) MRU

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Belady's anomaly** means that giving a process **more** frames can cause **more** page faults.

It happens with FIFO. The classic reference string is $1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5$:

| Frames | FIFO page faults |
|---|---|
| 3 | 9 |
| 4 | 10 |

Optimal, LRU and MRU never show it. They are **stack algorithms**: at every moment the pages held with $k$ frames are a subset of those held with $k+1$ frames, so extra frames can only remove faults. FIFO has no such property, because it evicts by arrival time rather than by a ranking that does not depend on the memory size.

- (B) Optimal: it has the fewest faults of any policy, and a memory with $k+1$ frames can simply ignore one frame to behave like one with $k$. So its faults cannot rise.
- (C) LRU: stack algorithm.
- (D) MRU: stack algorithm.

**Code check:** on the string above, FIFO gave $9$ faults with $3$ frames and $10$ with $4$. (LRU gave $10$ and $8$, MRU and Optimal gave $7$ and $6$.) On $20000$ random strings over $6$ pages, the resident set with $k$ frames was a subset of the one with $k+1$ frames every time for LRU and for MRU ($0$ violations), but FIFO broke this on $12495$ of the strings.

**Key idea:** only non-stack policies such as FIFO can suffer Belady's anomaly.

</details>
