# 2023 CS Q57: Page faults with LRU in column-major access

## Question

Consider the following two-dimensional array $D$ in the C programming language, which is stored in row-major order:

```c
int D[128][128];
```

Demand paging is used for allocating memory and each physical page frame holds 512 elements of the array $D$. The Least Recently Used (LRU) page-replacement policy is used by the operating system. A total of 30 physical page frames are allocated to a process which executes the following code snippet:

```c
for (int i = 0; i < 128; i++)
  for (int j = 0; j < 128; j++)
    D[j][i] *= 10;
```

The number of page faults generated during the execution of this code snippet is ______.

<details class="success" markdown="1">
<summary>Answer</summary>

**4096**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Layout.** One row has 128 ints, so a page (512 ints) holds **4 rows**. The array is $128 / 4 = 32$ pages.

**Access pattern.** The inner loop goes down a *column*: rows $0, 1, \ldots, 127$. For a fixed $i$ it touches pages $0, 0, 0, 0, 1, 1, 1, 1, \ldots, 31$, which is $32$ distinct pages in order.

**Why LRU fails.** Each pass over a column cycles through 32 pages but only 30 frames exist. When page 30 is needed, the least recently used page is page 0, so page 0 is thrown out. Then page 31 evicts page 1, and so on. By the next column, the page needed next is always the one just evicted. Every new page access is a fault:

$$128 \text{ columns} \times 32 \text{ pages} = 4096$$

**Code check:** an LRU simulation in C (30 frames, `gcc -Wall`) printed `4096`.

**Key idea:** a cyclic access pattern over more pages than frames makes LRU fault on every page.

</details>
