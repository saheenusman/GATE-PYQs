# 2020 CS Q21: Hole left by first fit, next fit, best fit and worst fit

## Question

Consider allocation of memory to a new process. Assume that none of the existing holes in the memory will exactly fit the process's memory requirement. Hence, a new hole of smaller size will be created if allocation is made in any of the existing holes. Which one of the following statements is TRUE?

- (A) The hole created by first fit is always larger than the hole created by next fit.
- (B) The hole created by worst fit is always larger than the hole created by first fit.
- (C) The hole created by best fit is never larger than the hole created by first fit.
- (D) The hole created by next fit is never larger than the hole created by best fit.

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**What each strategy picks** (among holes big enough for the request):

- **First fit:** the first big-enough hole, scanning from the start of memory.
- **Next fit:** the first big-enough hole, scanning from where the last allocation was made.
- **Best fit:** the *smallest* big-enough hole.
- **Worst fit:** the *largest* big-enough hole.

The hole left behind is the chosen hole's size minus the request. Best fit chooses the smallest big-enough hole, so its leftover is the **smallest possible**. First fit picks *some* big-enough hole, so its leftover is at least as big. That makes **(C)** always true.

**Counterexamples for the others.** Request = 5, holes in memory order:

- **(A)** holes $[10, 20]$, and the last allocation was in the first hole, so next fit scans from the second. First fit picks 10 (leftover 5). Next fit picks 20 (leftover 15). First fit's hole is *not* larger.
- **(B)** holes $[20, 10]$. First fit picks 20, and worst fit also picks 20, so the holes are equal, not "always larger".
- **(D)** holes $[10, 20]$ with next fit starting at 20. Next fit leaves 15, and best fit leaves 5. Next fit's hole *is* larger.

**Code check.** I simulated about 140,000 random hole lists and requests (with no exact fits). Statement (C) had no counterexample. (A), (B) and (D) each failed many times.

**Key idea:** best fit minimises the leftover, so no other strategy can leave a smaller hole than it does. Every other "always" claim breaks when two strategies pick the same hole or different ones.

</details>
