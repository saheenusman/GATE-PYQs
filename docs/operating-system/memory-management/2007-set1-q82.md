# 2007 CS Q82: Page faults under optimal page replacement

## Question

**Statement for Linked Answer Questions 82 & 83.** A process has been allocated 3 page frames. Assume that none of the pages of the process are available in the memory initially. The process makes the following sequence of page references (reference string): 1, 2, 1, 3, 7, 4, 5, 6, 3, 1.

**Q.82** If optimal page replacement policy is used, how many page faults occur for the above reference string?

- (A) 7
- (B) 8
- (C) 9
- (D) 10

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Optimal replacement evicts the page whose next use is farthest in the future (or never).

| Ref | Frames after | Fault? |
|---|---|---|
| 1 | 1 | yes |
| 2 | 1 2 | yes |
| 1 | 1 2 | no |
| 3 | 1 2 3 | yes |
| 7 | 1 3 7 (evict 2, never used again) | yes |
| 4 | 1 3 4 (evict 7, never again) | yes |
| 5 | 1 3 5 (evict 4) | yes |
| 6 | 1 3 6 (evict 5) | yes |
| 3 | 1 3 6 | no |
| 1 | 1 3 6 | no |

Faults: references $1, 2, 3, 7, 4, 5, 6$ = **7**: (A).

- (B), (C) and (D) count extra faults (LRU gives 9; 10 would mean every reference faults).

**Code check:** Python simulation of optimal replacement with 3 frames: 7 faults.

**Status note:** `unverified`. GATE 2007 had no official answer key, so there is nothing to compare against. This is my own answer.

**Key idea:** optimal replacement keeps the pages that will be used soonest; pages 1 and 3 are reused at the end, so they are never evicted.

</details>
