# 2009 CS Q34: Why multilevel page tables are preferred

## Question

A multilevel page table is preferred in comparison to a single level page table for translating virtual address to physical address because

- (A) it reduces the memory access time to read or write a memory location.
- (B) it helps to reduce the size of page table needed to implement the virtual address space of a process.
- (C) it is required by the translation look aside buffer.
- (D) it helps to reduce the number of page faults in page replacement algorithms.

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

A single-level page table needs one entry for **every** page of the virtual address space, even if most of it is unused, and the whole table must sit in contiguous memory. A multilevel table only creates the lower-level tables for the parts of the address space actually in use, so the table that must be kept in memory is much smaller: (B).

- (A) is false: a multilevel walk needs **more** memory accesses (one per level) when the translation is not in the TLB.
- (C) is false: the TLB caches translations and works with any page table structure.
- (D) is false: page-fault counts depend on the replacement policy and the number of frames, not on how the page table is organised.

**Code check:** none (conceptual question).

**Key idea:** multilevel paging saves memory by allocating page-table pieces only for address ranges in use.

</details>
