# 2007 CS Q83: Extra page faults of LRU over optimal

## Question

(Linked with Q.82: the same process and reference string.)

**Q.83** Least Recently Used (LRU) page replacement policy is a practical approximation to optimal page replacement. For the above reference string, how many more page faults occur with LRU than with the optimal page replacement policy?

- (A) 0
- (B) 1
- (C) 2
- (D) 3

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

LRU evicts the page unused for the longest time.

| Ref | Frames (least to most recently used) | Fault? |
|---|---|---|
| 1 | 1 | yes |
| 2 | 1 2 | yes |
| 1 | 2 1 | no |
| 3 | 2 1 3 | yes |
| 7 | 1 3 7 (evict 2) | yes |
| 4 | 3 7 4 (evict 1) | yes |
| 5 | 7 4 5 (evict 3) | yes |
| 6 | 4 5 6 (evict 7) | yes |
| 3 | 5 6 3 (evict 4) | yes |
| 1 | 6 3 1 (evict 5) | yes |

LRU faults: $9$. Optimal (Q.82): $7$. The difference is $9 - 7 = 2$: (C).

- (A) 0, (B) 1 and (D) 3 do not match the two fault counts.

**Code check:** Python simulation: LRU 9 faults, optimal 7 faults, difference 2.

**Status note:** `unverified`. GATE 2007 had no official answer key, so there is nothing to compare against. This is my own answer.

**Key idea:** LRU discards pages 1 and 3 because they are old, but optimal keeps them since they are reused at the end.

</details>
