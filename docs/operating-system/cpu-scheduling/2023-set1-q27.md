# 2023 CS Q27: Scheduling algorithms that can starve a process

## Question

Which one or more of the following CPU scheduling algorithms can potentially cause starvation?

- (A) First-in First-Out
- (B) Round Robin
- (C) Priority Scheduling
- (D) Shortest Job First

<details class="success" markdown="1">
<summary>Answer</summary>

**C and D (the official key also accepts A, C and D)**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Official key:** both "A, C, D" and "C, D" are accepted.

**C, Priority scheduling:** a steady stream of higher-priority processes can keep a low-priority one waiting forever.

**D, Shortest Job First:** a steady stream of short jobs can keep a long job waiting forever.

**B, Round Robin:** every process gets a time slice in turn, so nobody starves.

**A, FIFO:** a process is served in arrival order, so normally every process eventually runs. The one catch: if a process ahead of you never finishes (for example an infinite loop), everything behind it waits forever. That is why the key also accepts the answer that includes A.

**Key idea:** starvation comes from algorithms that keep letting new arrivals jump the queue (priority, SJF).

</details>
