# 2014 CS2 Q32: Round robin: when does process C complete its first I/O

## Question

Three processes A, B and C each execute a loop of 100 iterations. In each iteration of the loop, a process performs a single computation that requires $t_c$ CPU milliseconds and then initiates a single I/O operation that lasts for $t_{io}$ milliseconds. It is assumed that the computer where the processes execute has sufficient number of I/O devices and the OS of the computer assigns different I/O devices to each process. Also, the scheduling overhead of the OS is negligible. The processes have the following characteristics:

| Process id | $t_c$ | $t_{io}$ |
|---|---|---|
| A | 100 ms | 500 ms |
| B | 350 ms | 500 ms |
| C | 200 ms | 500 ms |

The processes A, B, and C are started at times 0, 5 and 10 milliseconds respectively, in a pure time sharing system (round robin scheduling) that uses a time slice of 50 milliseconds. The time in milliseconds at which process C would *complete* its first I/O operation is ___________.

<details class="success" markdown="1">
<summary>Answer</summary>

**1000**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Run round robin with a 50 ms slice. A arrives at 0, B at 5, C at 10, so the queue order is A, B, C.

| Time | Runs | Remaining after |
|---|---|---|
| 0-50 | A | A 50 |
| 50-100 | B | B 300 |
| 100-150 | C | C 150 |
| 150-200 | A | A 0 (A starts its I/O at 200) |
| 200-250 | B | B 250 |
| 250-300 | C | C 100 |
| 300-350 | B | B 200 |
| 350-400 | C | C 50 |
| 400-450 | B | B 150 |
| 450-500 | C | C 0 |

C finishes its first 200 ms CPU burst at $t = 500$ and then does its I/O for 500 ms:

$$500 + 500 = 1000 \text{ ms}$$

A's early return from I/O (at 700) does not matter, since C's burst ends first.

**Code check:** a round-robin simulation gives the same schedule and C's CPU burst ending at 500.

**Key idea:** the I/O starts only when the whole CPU burst is done, and the I/O devices are not shared.

</details>
