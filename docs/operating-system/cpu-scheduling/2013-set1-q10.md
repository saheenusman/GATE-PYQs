# 2013 CS Q10: Priority proportional to waiting time

## Question

A scheduling algorithm assigns priority proportional to the waiting time of a process. Every process starts with priority zero (the lowest priority). The scheduler re-evaluates the process priorities every $T$ time units and decides the next process to schedule.
Which one of the following is TRUE if the processes have no I/O operations and all arrive at time zero?

- (A) This algorithm is equivalent to the first-come-first-serve algorithm.
- (B) This algorithm is equivalent to the round-robin algorithm.
- (C) This algorithm is equivalent to the shortest-job-first algorithm.
- (D) This algorithm is equivalent to the shortest-remaining-time-first algorithm.

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Trace.** Priority grows with time spent *waiting*, and the running process does not wait.

1. At $t=0$ all priorities are 0; the scheduler picks some process, say $P_1$.
2. During $[0,T)$ the others wait, so their priorities rise to $T$ while $P_1$ stays at 0.
3. At $t=T$ the scheduler picks a waiting process, $P_2$. Now $P_1$ starts to wait again.
4. The process that has waited longest (equivalently, the one that ran longest ago) always has the highest priority.

So each process gets a slice of $T$ in turn, cyclically. That is **round robin** with quantum $T$.

**Why the others fail:**

- (A) FCFS would let a process run to completion; here the CPU is taken away every $T$ units.
- (C), (D) SJF and SRTF depend on burst lengths; this rule never looks at them.

**Key idea:** "longest waiting goes next, with a fixed re-evaluation period" is round robin.

</details>
