# 2026 CS2 Q23: Which scheduling algorithm cannot be preemptive

## Question

Which one of the following CPU scheduling algorithms **cannot** be preemptive?

- (A) Shortest Remaining Time First (SRTF) Scheduling
- (B) First Come First Serve (FCFS) Scheduling
- (C) Round Robin Scheduling
- (D) Priority Scheduling

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Refresher.** A *preemptive* scheduler can take the CPU away from a running process. A *non-preemptive* one lets it run until it finishes or blocks.

| Algorithm | Preemptive? |
|---|---|
| SRTF | **always** preemptive (it is the preemptive version of SJF) |
| FCFS | **never**: a later arrival does not change the order, so there is nothing to preempt with |
| Round Robin | **always** preemptive: the time quantum forces a switch |
| Priority | can be **either**: preemptive or non-preemptive |

So only **FCFS** cannot be preemptive. Priority scheduling *can* be non-preemptive, but it can also be preemptive, so it does not fit "cannot".

**Key idea:** FCFS has no rule that ever interrupts the running process, so it is inherently non-preemptive.

</details>
