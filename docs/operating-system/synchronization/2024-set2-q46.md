# 2024 CS2 Q46: Possible outcomes with two semaphores

## Question

Consider a multi-threaded program with two threads T1 and T2. The threads share two semaphores: `s1` (initialized to 1) and `s2` (initialized to 0). The threads also share a global variable `x` (initialized to 0). The threads execute the code shown below.

| T1 | T2 |
|---|---|
| `wait(s1);` | `wait(s1);` |
| `x = x+1;` | `x = x+1;` |
| `print(x);` | `print(x);` |
| `wait(s2);` | `signal(s2);` |
| `signal(s1);` | `signal(s1);` |

Which of the following outcomes is/are possible when threads T1 and T2 execute concurrently?

- (A) T1 runs first and prints 1, T2 runs next and prints 2
- (B) T2 runs first and prints 1, T1 runs next and prints 2
- (C) T1 runs first and prints 1, T2 does not print anything (deadlock)
- (D) T2 runs first and prints 1, T1 does not print anything (deadlock)

<details class="success" markdown="1">
<summary>Answer</summary>

**B and C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

`s1` is a mutex (initially 1). `s2` starts at 0, so `wait(s2)` in T1 blocks until T2 signals it.

**Case 1: T1 gets `s1` first.** T1 prints 1, then blocks at `wait(s2)` **still holding `s1`**. T2 cannot even pass `wait(s1)`. Nobody can `signal(s2)`, so both are stuck: **deadlock**, with only "1" printed.

- (A) fails: in this case T2 can never print 2.
- **(C) is possible.**

**Case 2: T2 gets `s1` first.** T2 prints 1, signals `s2` (now 1), and releases `s1`. T1 then gets `s1`, prints 2, passes `wait(s2)` immediately, and releases `s1`: **no deadlock**.

- **(B) is possible.**
- (D) fails: T1 does not get stuck because `s2` was already signalled.

(A state-space search over all interleavings found exactly these two outcomes.)

**Key idea:** blocking on one semaphore while holding another lock invites deadlock. Who takes the mutex first decides the outcome.

</details>
