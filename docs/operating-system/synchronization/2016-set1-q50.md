# 2016 CS1 Q50: Properties of a bakery-style critical section solution

## Question

Consider the following proposed solution for the critical section problem. There are $n$ processes: $P_0 \dots P_{n-1}$. In the code, function `pmax` returns an integer not smaller than any of its arguments. For all $i$, `t[i]` is initialized to zero.

Code for $P_i$:

```c
do {
    c[i]=1; t[i] = pmax(t[0],...,t[n-1])+1; c[i]=0;
    for every j != i in {0,...,n-1} {
        while (c[j]);
        while (t[j] != 0 && t[j]<=t[i]);
    }
    Critical Section;
    t[i]=0;
    Remainder Section;
} while (true);
```

Which one of the following is TRUE about the above solution?

- (A) At most one process can be in the critical section at any time
- (B) The bounded wait condition is satisfied
- (C) The progress condition is satisfied
- (D) It cannot cause a deadlock

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**(A) Mutual exclusion holds (sketch).** Suppose $P_i$ and $P_j$ are both in the critical section with non-zero tickets. $P_i$ passed its test on $j$, so $t[j] > t[i]$. By symmetry $P_j$ passed its test on $i$, so $t[i] > t[j]$. Both cannot hold. The `while (c[j])` loop keeps $P_i$ from reading $t[j]$ while $P_j$ is still choosing its ticket, so a ticket chosen after $P_i$'s check is always larger than $t[i]$. This agrees with the official key; I did not model-check the protocol.

**(D) is false: deadlock is possible.** Two processes can read all the `t[]` values before either writes its own, so both compute the same ticket. Then for each, `t[j] != 0 && t[j] <= t[i]` is true (equal tickets), so each waits for the other forever. The classic bakery algorithm breaks ties by process id; this code does not.

**(B) and (C) are false for the same reason.** A deadlocked pair means a process can wait indefinitely (no bounded waiting), and no process can enter even though the critical section is empty (no progress).

**Key idea:** mutual exclusion follows from comparing tickets; missing tie-break allows deadlock.

</details>
