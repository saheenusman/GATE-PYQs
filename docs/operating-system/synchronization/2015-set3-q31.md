# 2015 CS3 Q31: Two flag variables guarding a critical section

## Question

Two processes $X$ and $Y$ need to access a critical section. Consider the following synchronization construct used by both the processes.

Process $X$:

```c
/* other code for process X */
while (true)
{
    varP = true;
    while (varQ == true)
    {
        /* Critical Section */
        varP = false;
    }
}
/* other code for process X */
```

Process $Y$:

```c
/* other code for process Y */
while (true)
{
    varQ = true;
    while (varP == true)
    {
        /* Critical Section */
        varQ = false;
    }
}
/* other code for process Y */
```

Here, `varP` and `varQ` are shared variables and both are initialized to false. Which one of the following statements is true?

- (A) The proposed solution prevents deadlock but fails to guarantee mutual exclusion
- (B) The proposed solution guarantees mutual exclusion but fails to prevent deadlock
- (C) The proposed solution guarantees mutual exclusion and prevents deadlock
- (D) The proposed solution fails to prevent deadlock and fails to guarantee mutual exclusion

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Notice the critical section is **inside** the `while` loop: a process enters it when the *other* flag is true.

**Mutual exclusion fails.** Interleave:

1. $X$: `varP = true`
2. $Y$: `varQ = true`
3. $X$ tests `varQ == true`: true, so $X$ enters its critical section.
4. $Y$ tests `varP == true`: true, so $Y$ enters its critical section too.

Both are inside at once.

**Deadlock does not occur.** No process waits for something only the other can release. Each step is always able to run, and from every reachable state at least one process can still reach its critical section. (One process can be starved, but that is not deadlock.)

So: no deadlock, but no mutual exclusion. Option (A).

**Code check:** a model of the two processes' steps (55 reachable states) shows the state "both in critical section" is reachable, every state has an enabled move, and there is no state from which neither process can ever enter its critical section.

**Key idea:** the correct flag protocol makes a process *wait while the other is interested*. This code does the reverse, so it cannot guarantee mutual exclusion.

</details>
