# 2009 CS Q33: Test-and-set critical section: deadlock, starvation, order

## Question

The `enter_CS()` and `leave_CS()` functions to implement critical section of a process are realized using test-and-set instruction as follows:

```c
void enter_CS(X)
{
    while (test-and-set(X));
}

void leave_CS(X)
{
    X = 0;
}
```

In the above solution, `X` is a memory location associated with the CS and is initialized to 0. Now consider the following statements:

- I. The above solution to CS problem is deadlock-free.
- II. The solution is starvation free.
- III. The processes enter CS in FIFO order.
- IV. More than one process can enter CS at the same time.

Which of the above statements are TRUE?

- (A) I only
- (B) I and II
- (C) II and III
- (D) IV only

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

`test-and-set(X)` atomically returns the old value of `X` and sets it to $1$. A process enters when it gets back $0$. Everyone else spins.

- **I is true.** If the CS is free ($X = 0$), the next `test-and-set` to run returns $0$ and that process enters. If it is occupied, the holder will call `leave_CS` and reset $X$. So the system always makes progress.
- **II is false.** Nothing orders the waiting processes. Whenever $X$ becomes $0$, any spinning process may win the race, so one unlucky process can lose every time (starvation).
- **III is false.** For the same reason there is no queue: the winner is whoever executes `test-and-set` first after $X$ becomes $0$, not the one that waited longest.
- **IV is false.** The instruction is atomic, so only one process can see $0$. Mutual exclusion holds.

True: I only, so (A).

- (B) and (C) contain II, which is false.
- (D) says mutual exclusion fails, which is false.

**Code check:** none (the argument is about the semantics of an atomic instruction).

**Key idea:** a test-and-set spin lock gives mutual exclusion and progress, but no fairness: no bound on waiting and no FIFO order.

</details>
