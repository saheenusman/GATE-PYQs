# 2014 CS2 Q31: Producer-consumer semaphores: deadlock when the buffer is empty

## Question

Consider the procedure below for the *Producer-Consumer* problem which uses semaphores:

```c
semaphore n = 0;
semaphore s = 1;

void producer()
{
    while(true)
    {
        produce();
        semWait(s);
        addToBuffer();
        semSignal(s);
        semSignal(n);
    }
}

void consumer()
{
    while(true)
    {
        semWait(s);
        semWait(n);
        removeFromBuffer();
        semSignal(s);
        consume();
    }
}
```

Which one of the following is **TRUE**?

- (A) The producer will be able to add an item to the buffer, but the consumer can never consume it.
- (B) The consumer will remove no more than one item from the buffer.
- (C) Deadlock occurs if the consumer succeeds in acquiring semaphore `s` when the buffer is empty.
- (D) The starting value for the semaphore `n` must be 1 and not 0 for deadlock-free operation.

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The consumer takes the mutex `s` **before** waiting on `n`. If the buffer is empty, `n = 0`, so the consumer blocks on `semWait(n)` while still holding `s`. The producer then blocks on `semWait(s)` and can never reach `semSignal(n)`. Neither can proceed: **deadlock**.

**Code check:** an exhaustive state search of the two processes (with `n = 0`, `s = 1`) found 61 reachable states and exactly one deadlock: consumer holds `s` and waits on `n`, producer waits on `s`. It is reached after one step, `C: wait(s)`.

- (A) false: if the producer runs first, `n` becomes 1 and the consumer can consume.
- (B) false: the consumer loops forever and can remove any number of items.
- (D) false: starting with `n = 1` makes the consumer remove an item that was never produced (the search finds a buffer underflow), and the deadlock is still reachable.

The fix is to swap the consumer's two waits: `semWait(n)` first, then `semWait(s)`.

**Key idea:** acquire the counting semaphore before the mutex, or a consumer can hold the mutex while it sleeps.

</details>
