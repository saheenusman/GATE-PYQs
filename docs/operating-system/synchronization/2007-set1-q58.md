# 2007 CS Q58: Two-flag mutual exclusion construct

## Question

Two processes, P1 and P2, need to access a critical section of code. Consider the following synchronization construct used by the processes:

```c
/* P1 */
while (true) {
    wants1 = true;
    while (wants2 == true);
    /* Critical Section */
    wants1 = false;
}
/* Remainder section */
```

```c
/* P2 */
while (true) {
    wants2 = true;
    while (wants1 == true);
    /* Critical Section */
    wants2 = false;
}
/* Remainder section */
```

Here, `wants1` and `wants2` are shared variables, which are initialized to `false`. Which one of the following statements is **TRUE** about the above construct?

- (A) It does not ensure mutual exclusion.
- (B) It does not ensure bounded waiting.
- (C) It requires that processes enter the critical section in strict alternation.
- (D) It does not prevent deadlocks, but ensures mutual exclusion.

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Mutual exclusion holds.** A process enters only after seeing the other's flag false, and it set its own flag true *before* looking. If both were in the critical section, each would have seen the other's flag false after setting its own, which is impossible.

**Deadlock is possible.** If both processes set their flag true before either tests the other's, each then spins forever on `while (wants_other == true)`. Both flags stay true and neither can proceed.

So the construct ensures mutual exclusion but does not prevent deadlock: (D).

- (A) is false for the reason above.
- (C) is false: nothing forces alternation; P1 can re-enter the critical section repeatedly if P2 does not run.
- (B) is also defensible (a process stuck in the deadlock waits unboundedly), but (D) states the primary, precise property; see the caveat below.

**Code check:** Python breadth-first search of the 12 reachable states of the two-process model: no state has both processes in the critical section (mutual exclusion holds), and the state `wants1 = wants2 = true`, both spinning, is a reachable deadlock.

**Judgement call:** (B) "does not ensure bounded waiting" is also true of this construct (the deadlock is the extreme case). I chose (D) because it names the deadlock and the mutual-exclusion guarantee together. Without an official key I cannot confirm that the examiners chose (D) rather than (B).

**Key idea:** setting your own flag first and then waiting guarantees mutual exclusion, but two simultaneous requests deadlock.

</details>
