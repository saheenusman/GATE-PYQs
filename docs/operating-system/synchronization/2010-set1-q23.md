# 2010 CS Q23: Two processes using shared flags S1 and S2 to enter critical sections

## Question

Consider the methods used by processes P1 and P2 for accessing their critical sections whenever needed, as given below. The initial values of shared boolean variables S1 and S2 are randomly assigned.

```
Method used by P1        Method used by P2
while (S1 == S2);        while (S1 != S2);
Critical Section         Critical Section
S1 = S2;                 S2 = not(S1);
```

Which one of the following statements describes the properties achieved?

- (A) Mutual exclusion but not progress
- (B) Progress but not mutual exclusion
- (C) Neither mutual exclusion nor progress
- (D) Both mutual exclusion and progress

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Mutual exclusion holds.** P1 leaves its loop only when $S1 \ne S2$. P2 leaves its loop only when $S1 = S2$. These two conditions cannot both be true, so the processes are never in their critical sections together. A critical section does not change $S1$ or $S2$, so the condition that let a process in stays true while it is inside.

**Progress fails.** The two flags force strict alternation:

- P1 exits with `S1 = S2`, so now $S1 = S2$. P1 itself is blocked until P2 changes something.
- P2 exits with `S2 = not(S1)`, so now $S1 \ne S2$. P2 is blocked until P1 changes something.

Suppose P2 never wants to enter again. After P1's critical section, $S1 = S2$ and P1 spins forever, although nobody is in a critical section and P1 wants in. A process outside its critical section is blocking another, which breaks progress.

So (A).

- (B) and (C) deny mutual exclusion, which holds as shown above.
- (D) ignores the strict alternation: a process that wants to enter twice in a row cannot.

**Key idea:** strict alternation through shared flags gives mutual exclusion but violates progress.

</details>
