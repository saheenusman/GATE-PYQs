# 2016 CS2 Q48: Property violated by a strict-alternation two-process solution

## Question

Consider the following two-process synchronization solution.

| Process 0 | Process 1 |
|---|---|
| Entry: `loop while (turn == 1);` | Entry: `loop while (turn == 0);` |
| (critical section) | (critical section) |
| Exit: `turn = 1;` | Exit: `turn = 0;` |

The shared variable `turn` is initialized to zero. Which one of the following is TRUE?

- (A) This is a correct two-process synchronization solution.
- (B) This solution violates mutual exclusion requirement.
- (C) This solution violates progress requirement.
- (D) This solution violates bounded wait requirement.

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

This is **strict alternation**: the two processes must take turns.

- **Mutual exclusion holds.** `turn` has one value, so only the process whose number matches it can enter.
- **Progress is violated.** Process 0 can enter only when `turn == 0`. After it leaves, `turn = 1`. If Process 1 never wants to enter again (it stays in its remainder section), Process 0 waits forever even though the critical section is free.

So (C) is true. (A) is false because progress fails, and (B) is false because mutual exclusion holds. (D) is false: whenever the other process does want to enter, the waiting one gets in after at most one entry of the other.

**Key idea:** strict alternation blocks a process while the other is idle: progress is violated.

</details>
