# 2021 CS1 Q56: Two waits on a semaphore of five, with an unsafe increment

## Question

Consider the following pseudocode, where `S` is a semaphore initialized to 5 in line#2 and `counter` is a shared variable initialized to 0 in line#1. Assume that the increment operation in line#7 is *not* atomic.

```
1.  int counter = 0;
2.  Semaphore S = init(5);
3.  void parop(void)
4.  {
5.      wait(S);
6.      wait(S);
7.      counter++;
8.      signal(S);
9.      signal(S);
10. }
```

If five threads execute the function `parop` concurrently, which of the following program behavior(s) is/are possible?

- (A) The value of `counter` is 5 after all the threads successfully complete the execution of `parop`.
- (B) The value of `counter` is 1 after all the threads successfully complete the execution of `parop`.
- (C) The value of `counter` is 0 after all the threads successfully complete the execution of `parop`.
- (D) There is a deadlock involving all the threads.

<details class="success" markdown="1">
<summary>Answer</summary>

**A, B and D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Each thread needs 2 permits at once. With 5 permits, at most 2 threads can be inside lines 7 to 9 together.

- (A) **Possible.** If the threads run one after another, each increment is complete, so the value is 5.
- (B) **Possible.** Let thread 1 read `counter` (0) and pause before writing, while holding 2 permits. Three permits remain, so the other four threads can finish one or two at a time and bring `counter` to 4. Then thread 1 writes $0+1=1$.
- (C) Not possible. Every thread that finishes has written at least 1, so the final value is at least 1.
- (D) **Possible.** All five threads do their first `wait(S)`: $S$ drops to 0. Every thread is now stuck at the second `wait(S)`, so all five are deadlocked.

I model-checked this: a small program explored every interleaving of 5 threads (each with a private register for the non-atomic increment). The reachable final values of `counter` are 1, 2, 3, 4 and 5 (never 0), and the deadlock state is reachable.

Answer: **A, B and D**.

**Key idea:** a lost update can undo many increments, and holding one resource while waiting for another can deadlock.

</details>
