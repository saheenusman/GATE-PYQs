# 2008 CS Q63: Initial values of the binary semaphores implementing a counting semaphore

## Question

The P and V operations on counting semaphores, where $s$ is a counting semaphore, are defined as follows:

```
P(s): s = s - 1;
      if s < 0 then wait;
V(s): s = s + 1;
      if s <= 0 then wakeup a process waiting on s;
```

Assume that $P_b$ and $V_b$, the wait and signal operations on binary semaphores, are provided. Two binary semaphores $X_b$ and $Y_b$ are used to implement the semaphore operations $P(s)$ and $V(s)$ as follows:

```
P(s): Pb(Xb);
      s = s - 1;
      if (s < 0) {
          Vb(Xb);
          Pb(Yb);
      }
      else Vb(Xb);

V(s): Pb(Xb);
      s = s + 1;
      if (s <= 0) Vb(Yb);
      Vb(Xb);
```

The initial values of $X_b$ and $Y_b$ are respectively

- (A) 0 and 0
- (B) 0 and 1
- (C) 1 and 0
- (D) 1 and 1

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The two semaphores have different jobs:

- $X_b$ is a **mutex** protecting the shared counter `s`. Every `P` and `V` begins with $P_b(X_b)$ and ends by releasing it.
- $Y_b$ is the **waiting queue**: a process that finds `s < 0` blocks on $P_b(Y_b)$, and a `V` operation wakes it with $V_b(Y_b)$.

**$X_b$ must start at 1.** If it started at 0, the very first $P_b(X_b)$ would block forever and no operation could ever run. This rules out (A) and (B).

**$Y_b$ must start at 0.** If it started at 1, a process that found `s < 0` would pass $P_b(Y_b)$ immediately instead of waiting. A `P(s)` that should block would not block, so the counting-semaphore behaviour would be broken. With $Y_b = 0$ it blocks until a `V` signals it. This rules out (D).

So the initial values are $X_b = 1$ and $Y_b = 0$: (C).

**Key idea:** a mutex starts at 1 (free); a semaphore used only for blocking and waking starts at 0.

</details>
