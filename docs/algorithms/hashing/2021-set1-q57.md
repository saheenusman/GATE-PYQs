# 2021 CS1 Q57: Which insertion sequence builds the given dynamic hash table

## Question

Consider a *dynamic* hashing approach for 4-bit integer keys:

1. There is a main hash table of size 4.
2. The 2 least significant bits of a key is used to index into the main hash table.
3. Initially, the main hash table entries are empty.
4. Thereafter, when more keys are hashed into it, to resolve collisions, the set of all keys corresponding to a main hash table entry is organized as a binary tree that grows on demand.
5. First, the 3rd least significant bit is used to divide the keys into left and right subtrees.
6. To resolve more collisions, each node of the binary tree is further sub-divided into left and right subtrees based on the 4th least significant bit.
7. A split is done only if it is needed, i.e., only when there is a collision.

Consider the following state of the hash table.

![A main hash table with four entries 00, 01, 10, 11. Entry 00 is empty. Entry 01 is a tree: the root has a left child that is a single key and a right child that is split again into two single keys. Entry 10 is a tree: the root has two single-key children. Entry 11 is a single key with no tree.](../../assets/2021/set1-q57.png)

Which of the following sequences of key insertions can cause the above state of the hash table (assume the keys are in decimal notation)?

- (A) 5, 9, 4, 13, 10, 7
- (B) 9, 5, 10, 6, 7, 1
- (C) 10, 9, 6, 7, 5, 13
- (D) 9, 5, 13, 6, 10, 14

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**What the picture says.** Write each key as 4 bits, index $=$ the 2 low bits.

| Entry | Shape | Meaning |
|---|---|---|
| 00 | empty | no key ends in 00 (no 0, 4, 8, 12) |
| 01 | left leaf; right node with two leaves | 3 keys: one with 3rd bit 0, and two with 3rd bit 1 that differ in the 4th bit |
| 10 | two leaves | 2 keys: one with 3rd bit 0, one with 3rd bit 1 |
| 11 | one leaf | exactly 1 key |

Keys ending in 01 are 1, 5, 9, 13. Their 3rd bit is 0 for 1 and 9, and 1 for 5 and 13. So the two keys on the right must be **5 and 13**, and the left one is **1 or 9**.

- (A) `4` ends in 00, so entry 00 is not empty. No.
- (B) Entry 01 gets 9, 5, 1. Both 9 and 1 have 3rd bit 0, so the **left** side would split and the right would be a single leaf. That is the mirror image. No.
- (C) Entry 01 gets 9, 5, 13. Inserting 5 collides with 9 and splits on the 3rd bit (9 left, 5 right). Inserting 13 collides with 5 and splits on the 4th bit. Entry 10 gets 10 and 6 (3rd bits 0 and 1), entry 11 gets just 7, and entry 00 stays empty. **Yes.**
- (D) Entry 10 would get 6, 10, 14. Then 6 and 14 collide again and split further, so the tree is deeper than shown. Entry 11 would also be empty. No.

I coded the insertion rule (split only on collision) and ran all four sequences. Only (C) produces the shown shape.

Answer: **C**.

**Key idea:** in this trie, the low bits pick the bucket and later bits split a leaf only when two keys collide.

</details>
