# 2021 CS2 Q36: Minimum encoded length with prefix-free codes and a tie rule

## Question

Consider the string abbccddeee. Each letter in the string must be assigned a binary code satisfying the following properties:

1. For any two letters, the code assigned to one letter must not be a prefix of the code assigned to the other letter.
2. For any two letters of the same frequency, the letter which occurs earlier in the dictionary order is assigned a code whose length is at most the length of the code assigned to the other letter.

Among the set of all binary code assignments which satisfy the above two properties, what is the minimum length of the encoded string?

- (A) 21
- (B) 23
- (C) 25
- (D) 30

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Frequencies: a = 1, b = 2, c = 2, d = 2, e = 3 (10 letters).

**Huffman merging:**

1. a(1) + b(2) = 3
2. c(2) + d(2) = 4
3. (ab)(3) + e(3) = 6
4. 4 + 6 = 10

Code lengths: a = 3, b = 3, c = 2, d = 2, e = 2. Cost $=3+6+4+4+6=23$.

Property 2 needs $\ell_b\le\ell_c\le\ell_d$. This assignment breaks it ($\ell_b=3>\ell_c=2$), but a different tie-break fixes that:

$$\ell_a=3,\ \ell_b=2,\ \ell_c=2,\ \ell_d=3,\ \ell_e=2.$$

- Kraft sum: $\tfrac18+\tfrac14+\tfrac14+\tfrac18+\tfrac14=1$, so a prefix-free code with these lengths exists.
- Cost $=3\cdot1+2\cdot2+2\cdot2+3\cdot2+2\cdot3=23$.

I also searched all length vectors with Kraft sum $\le1$ and property 2: the minimum is 23. No prefix code can beat Huffman's 23, so the tie rule costs nothing here.

- (A) 21 is below the Huffman optimum, so impossible.
- (C) 25 is achievable but not minimal.
- (D) 30 is the fixed 3-bit code.

**Key idea:** Huffman gives the minimum; ties can be broken so the extra ordering rule is still met at the same cost.

</details>
