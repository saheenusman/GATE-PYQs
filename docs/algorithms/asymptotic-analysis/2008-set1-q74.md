# 2008 CS Q74: Running time of a recursive and an iterative recurrence

## Question

Consider the following C functions (common data for Q.74 and Q.75):

```c
int f1(int n)
{
    if (n == 0 || n == 1)
        return n;
    else
        return (2 * f1(n-1) + 3 * f1(n-2));
}

int f2(int n)
{
    int i;
    int X[N], Y[N], Z[N];
    X[0] = Y[0] = Z[0] = 0;
    X[1] = 1; Y[1] = 2; Z[1] = 3;
    for (i = 2; i <= n; i++) {
        X[i] = Y[i-1] + Z[i-2];
        Y[i] = 2 * X[i];
        Z[i] = 3 * X[i];
    }
    return X[n];
}
```

The running time of `f1(n)` and `f2(n)` are

- (A) $\Theta(n)$ and $\Theta(n)$
- (B) $\Theta(2^n)$ and $\Theta(n)$
- (C) $\Theta(n)$ and $\Theta(2^n)$
- (D) $\Theta(2^n)$ and $\Theta(2^n)$

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**`f2`** has one loop of $n - 1$ iterations with constant work in each, so it runs in $\Theta(n)$.

**`f1`** makes two recursive calls, on $n-1$ and $n-2$, like the naive Fibonacci recursion. The number of calls $C(n)$ satisfies $C(n) = C(n-1) + C(n-2) + 1$, which grows exponentially. This is the exponential option (B).

- (A) is wrong: the recursion does not take linear time.
- (C) and (D) are wrong for `f2`: it never recomputes anything.

**Caveat on the wording.** Strictly, $C(n)$ grows like $\varphi^n$ with $\varphi \approx 1.618$, so `f1` is $O(2^n)$ and $\Omega(\varphi^n)$ but **not** $\Theta(2^n)$. (B) is the only option with an exponential `f1` and a linear `f2`, so it is the intended answer, and it matches the key.

**Code check:** counting the calls of `f1` gave 15, 177, 1973, 21891 and 242785 for $n = 5, 10, 15, 20, 25$. The ratio per step settles at about $1.618$, not $2$.

**Key idea:** a recursion with two overlapping recursive calls is exponential, while the iterative table version is linear.

</details>
