# 2009 CS Q54: Filling the LCS table L[M, N] by dynamic programming

## Question

**Common data for Questions 53 and 54.** (The statement is the same as for Question 53: `X[m]`, `Y[n]`, and the recursive definition of the LCS length $l(i, j)$ with `expr1` and `expr2` as in Q53.)

The values of $l(i, j)$ could be obtained by dynamic programming based on the correct recursive definition of $l(i, j)$ of the form given above, using an array `L[M, N]`, where $M = m + 1$ and $N = n + 1$, such that `L[i, j]` $= l(i, j)$.

Which one of the following statements would be TRUE regarding the dynamic programming solution for the recursive definition of $l(i, j)$?

- (A) All elements of `L` should be initialized to 0 for the values of $l(i, j)$ to be properly computed.
- (B) The values of $l(i, j)$ may be computed in a row major order or column major order of `L[M, N]`.
- (C) The values of $l(i, j)$ cannot be computed in either row major order or column major order of `L[M, N]`.
- (D) `L[p, q]` needs to be computed before `L[r, s]` if either $p < r$ or $q < s$.

<summary>Solution</summary>

**Official key:** the key table in the supplied PDF has no entry for Q54, so I cannot check against it. The answer below is my own derivation.

Each cell $l(i, j)$ depends only on $l(i-1, j-1)$, $l(i-1, j)$ and $l(i, j-1)$.

- In **row-major** order (row by row, left to right) all three of those cells come earlier.
- In **column-major** order (column by column, top to bottom) all three come earlier too.

So either order works: (B).

- (A) is not needed. Only the first row and first column (the cases $i = 0$ or $j = 0$) must be $0$. Every interior cell is **assigned** from earlier cells before it is read, never added to an old value.
- (C) contradicts (B).
- (D) is too strong, and in fact impossible to satisfy. Take $(p, q) = (2, 1)$ and $(r, s) = (1, 5)$: the rule says `L[2,1]` must come before `L[1,5]` (since $q < s$). Swap the roles and it says `L[1,5]` must come before `L[2,1]` (since $p < r$). The real requirement is $p \le r$ **and** $q \le s$.

**Status note:** marked `unverified` because the key gives no answer to compare with. The reasoning was checked by program: filling the table in row-major order and in column-major order gave the same LCS length as the recursion on $500$ random pairs of strings (no mismatches).

**Key idea:** a DP cell needs only its up, left and up-left neighbours, so any fill order that respects those dependencies, such as row-major or column-major, works.
