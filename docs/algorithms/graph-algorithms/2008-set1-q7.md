# 2008 CS Q7: Finding connected components of an undirected graph

## Question

The most efficient algorithm for finding the number of connected components in an undirected graph on $n$ vertices and $m$ edges has time complexity

- (A) $\Theta(n)$
- (B) $\Theta(m)$
- (C) $\Theta(m + n)$
- (D) $\Theta(mn)$

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Run **DFS (or BFS)** from every unvisited vertex. Each run discovers one component. Every vertex is visited once and every edge is examined a constant number of times (twice, once from each end), so the total time is $\Theta(n + m)$. This is also optimal, since the input has to be read.

- (A) $\Theta(n)$ ignores the edges. A graph can have $m \gg n$ edges to read.
- (B) $\Theta(m)$ ignores isolated vertices. With $m = 0$ there are still $n$ components to count.
- (D) $\Theta(mn)$ is far slower than needed.

**Key idea:** traversal-based component counting is linear in the size of the graph, $\Theta(n + m)$.

</details>
