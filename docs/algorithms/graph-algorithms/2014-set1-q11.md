# 2014 CS1 Q11: DFS running time with an adjacency matrix

## Question

Let $G$ be a graph with $n$ vertices and $m$ edges. What is the tightest upper bound on the running time of Depth First Search on $G$, when $G$ is represented as an adjacency matrix?

- (A) $\Theta(n)$
- (B) $\Theta(n+m)$
- (C) $\Theta(n^2)$
- (D) $\Theta(m^2)$

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

DFS visits each vertex once. For a vertex $u$ it must find all its neighbours, which means scanning the whole row $u$ of the matrix, $n$ entries. Over $n$ vertices that is

$$n \times n = \Theta(n^2)$$

regardless of $m$.

- (A) ignores the row scans.
- (B) $\Theta(n+m)$ is the bound for an **adjacency list**, where only real edges are visited.
- (D) $m \le n^2$, so $m^2$ can be as large as $n^4$ and is not tight.

**Key idea:** adjacency matrix makes neighbour lookup $\Theta(n)$ per vertex.

</details>
