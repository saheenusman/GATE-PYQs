# 2008 CS Q43: Quicksort with a pivot that splits at least one-fifth

## Question

Consider the Quicksort algorithm. Suppose there is a procedure for finding a pivot element which splits the list into two sub-lists each of which contains at least one-fifth of the elements. Let $T(n)$ be the number of comparisons required to sort $n$ elements. Then

- (A) $T(n) \le 2T(n/5) + n$
- (B) $T(n) \le T(n/5) + T(4n/5) + n$
- (C) $T(n) \le 2T(4n/5) + n$
- (D) $T(n) \le 2T(n/2) + n$

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Partitioning costs $n$ comparisons and leaves two sublists of sizes $a$ and $b$ with $a + b \approx n$ and $a, b \ge n/5$. Then each of them is at most $n - n/5 = 4n/5$. So

$$T(n) = T(a) + T(b) + n \le 2\,T(4n/5) + n,$$

because $T$ is non-decreasing. This is (C).

- (A) $2T(n/5)$ only covers the *smaller* parts, but the larger part can be as big as $4n/5$.
- (B) is the worst split, and it is the right *worst-case* recurrence only if $T$ is convex. That has to be proved, while (C) follows from monotonicity alone, so (C) is the safe bound.
- (D) assumes a perfectly balanced split.

**Key idea:** if both parts are at least $n/5$, each is at most $4n/5$, so bound both recursive calls by $T(4n/5)$.

</details>
