# 2013 CS Q6: Swaps in selection sort

## Question

Which one of the following is the tightest upper bound that represents the number of swaps required to sort $n$ numbers using selection sort?

- (A) $O(\log n)$
- (B) $O(n)$
- (C) $O(n \log n)$
- (D) $O(n^2)$

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Selection sort scans for the minimum of the unsorted part and swaps it into place **once per pass**.

There are $n-1$ passes, so at most $n-1$ swaps: $O(n)$. This bound is attained, for example on a cyclic shift of a sorted array, so it is tight.

(The number of *comparisons* is $\Theta(n^2)$, which is why (D) is a tempting wrong answer.)

**Why the others fail:**

- (A) $O(\log n)$ is below the true worst case of about $n-1$ swaps.
- (C), (D) are valid upper bounds but not the tightest.

**Key idea:** selection sort does $\Theta(n^2)$ comparisons but only $O(n)$ swaps.

</details>
