# 2008 CS Q40: Checking for a majority element in a sorted array

## Question

The minimum number of comparisons required to determine if an integer appears more than $n/2$ times in a sorted array of $n$ integers is

- (A) $\Theta(n)$
- (B) $\Theta(\log n)$
- (C) $\Theta(\log^{*} n)$
- (D) $\Theta(1)$

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

In a sorted array equal values sit together. If a value occurs more than $n/2$ times, its block of equal entries must contain the **middle** position, so the only candidate is $A[\lfloor n/2 \rfloor]$.

To count that candidate, use **binary search** for the first and the last position of the value: $O(\log n)$ comparisons. Compare the block length with $n/2$.

It cannot be done in less: deciding whether the block is longer than $n/2$ requires locating its boundaries, and each boundary search is a binary search over a sorted array (lower bound $\Omega(\log n)$).

- (A) $\Theta(n)$ is what an unsorted scan would cost.
- (C) $\Theta(\log^* n)$ and (D) $\Theta(1)$ are below the binary-search lower bound.

**Key idea:** sortedness turns "count the occurrences" into two binary searches, so the cost is $\Theta(\log n)$.

</details>
