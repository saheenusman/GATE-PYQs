# 2009 CS Q39: Quick sort with the (n/4)th smallest element as pivot

## Question

In quick sort, for sorting $n$ elements, the $(n/4)^{\text{th}}$ smallest element is selected as pivot using an $O(n)$ time algorithm. What is the worst case time complexity of the quick sort?

- (A) $\Theta(n)$
- (B) $\Theta(n \log n)$
- (C) $\Theta(n^2)$
- (D) $\Theta(n^2 \log n)$

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

With the $(n/4)^{\text{th}}$ smallest element as pivot, every partition splits the array into parts of size exactly about $n/4$ and $3n/4$. This holds in **every** case, so there is no bad input.

Finding the pivot costs $O(n)$ and partitioning costs $O(n)$, so

$$T(n) = T\!\left(\tfrac{n}{4}\right) + T\!\left(\tfrac{3n}{4}\right) + \Theta(n).$$

In the recursion tree each level does at most $cn$ work, and the deepest path (always the $3n/4$ side) has $\log_{4/3} n$ levels. So $T(n) = O(n \log n)$. The shallowest path and the level sums give $\Omega(n \log n)$ as well:

$$T(n) = \Theta(n \log n).$$

- (A) ignores the $\Theta(\log n)$ levels.
- (C) is the usual quick sort worst case, which needs lopsided splits; the pivot rule rules them out.
- (D) is larger than the tree allows.

**Code check:** evaluating $T(n) = T(n/4) + T(3n/4) + n$ numerically gave $T(n)/(n \log_2 n) = 1.356,\ 1.323,\ 1.306,\ 1.295$ for $n = 10^3, 10^4, 10^5, 10^6$. The ratio levels off at a constant (it does not grow with $n$), as $\Theta(n \log n)$ predicts.

**Key idea:** a guaranteed constant-fraction split, even an unbalanced one, keeps quick sort at $\Theta(n \log n)$ in the worst case.

</details>
