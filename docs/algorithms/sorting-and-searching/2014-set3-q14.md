# 2014 CS3 Q14: Worst-case bound of quicksort with the central pivot

## Question

You have an array of $n$ elements. Suppose you implement quicksort by always choosing the central element of the array as the pivot. Then the tightest upper bound for the worst case performance is

- (A) $O(n^2)$
- (B) $O(n \log n)$
- (C) $\Theta(n \log n)$
- (D) $O(n^3)$

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Choosing the middle element does not guarantee a balanced split. Some inputs are arranged so that the middle element is always the smallest or largest of its sub-array, giving splits of sizes $n-1$ and $0$ at every level:

$$T(n) = T(n-1) + O(n) \Rightarrow O(n^2).$$

So the worst case is $\Theta(n^2)$, and the tightest upper bound is $O(n^2)$.

- (B) and (C) are the average-case behaviour (or the best case); the worst case is larger.
- (D) $O(n^3)$ is a valid upper bound, but not the tightest.

**Key idea:** a fixed pivot rule (first, last, middle) has some adversarial input with $O(n^2)$ time.

</details>
