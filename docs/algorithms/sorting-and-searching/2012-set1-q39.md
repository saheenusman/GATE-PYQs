# 2012 CS Q39: Merge sort on n strings of length n

## Question

A list of $n$ strings, each of length $n$, is sorted into lexicographic order using the merge-sort algorithm. The worst case running time of this computation is

- (A) $O(n \log n)$
- (B) $O(n^2 \log n)$
- (C) $O(n^2 + \log n)$
- (D) $O(n^2)$

<details class="info" markdown="1">
<summary>Solution</summary>

**Status: disputed.** The official key is MTA. My own working gives a single answer, (B). Both follow.

**My derivation.** Merge sort on $n$ items makes $\Theta(n \log n)$ comparisons in the worst case. Here each comparison is between two strings of length $n$, and comparing them lexicographically can take $\Theta(n)$ character comparisons (equal prefixes). So

$$O(n \log n) \times O(n) = O(n^2 \log n).$$

That is (B).

- (A) ignores the cost of one string comparison.
- (C) $O(n^2 + \log n) = O(n^2)$, and (D) $O(n^2)$ are smaller than the work needed in the worst case, so they are not valid upper bounds.

**What the key says.** MTA, with no reason given on the key page. I could not find a flaw in the question or in option (B), so I record the key and flag the mismatch.

**Key idea:** total time $=$ number of comparisons $\times$ cost per comparison; string comparison costs the string length.
