# 2025 CS2 Q20: Fewest comparisons to find a non-maximum element

## Question

Consider an unordered list of $N$ distinct integers.

What is the minimum number of element comparisons required to find an integer in the list that is NOT the largest in the list?

- (A) 1
- (B) $N-1$
- (C) $N$
- (D) $2N-1$

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

We do not need the maximum. We only need *some* element that is not the largest.

Compare any **two** elements $x$ and $y$ (this needs $N \ge 2$). The **smaller** of them cannot be the largest of the whole list, because the other one is bigger. So **one comparison** is enough.

| Option | Why wrong |
|---|---|
| B, $N-1$ | This is the cost of *finding the maximum*, which is a different problem |
| C, $N$ | More than needed |
| D, $2N-1$ | More than needed |

Zero comparisons cannot work: without comparing, any chosen element might be the maximum.

**Key idea:** the loser of any single comparison is certainly not the maximum.

</details>
