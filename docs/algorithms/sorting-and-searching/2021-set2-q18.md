# 2021 CS2 Q18: Worst-case arithmetic operations in recursive binary search

## Question

What is the worst-case number of arithmetic operations performed by recursive binary search on a sorted array of size $n$?

- (A) $\Theta(\sqrt n)$
- (B) $\Theta(\log_2 n)$
- (C) $\Theta(n^2)$
- (D) $\Theta(n)$

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Each call computes the middle index (a constant number of additions and a division) and then recurses on one half. So

$$T(n)=T(n/2)+c,$$

which gives $T(n)=\Theta(\log_2 n)$.

(B). The other options correspond to scanning (linear) or to something worse than examining each element.

**Key idea:** binary search halves the range with constant work per step, so the cost is logarithmic.

</details>
