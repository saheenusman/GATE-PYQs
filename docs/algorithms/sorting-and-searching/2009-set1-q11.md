# 2009 CS Q11: Number of swaps in selection sort, worst case

## Question

What is the number of swaps required to sort $n$ elements using selection sort, in the worst case?

- (A) $\Theta(n)$
- (B) $\Theta(n \log n)$
- (C) $\Theta(n^2)$
- (D) $\Theta(n^2 \log n)$

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Status: disputed.** The official key in the supplied PDF is (C) $\Theta(n^2)$. My own analysis gives (A) $\Theta(n)$. Both follow.

**What I get (A).** Selection sort makes one pass per position $i = 0, \dots, n-2$. In each pass it **scans** the unsorted part to find the minimum, then does **one** swap to put it at position $i$. So there is at most one swap per pass:

$$\text{swaps} \le n - 1 = \Theta(n).$$

The $\Theta(n^2)$ cost of selection sort is the number of **comparisons** ($n(n-1)/2$ in every case), not the number of swaps. Selection sort is the standard example of an algorithm that does few swaps.

**What the key says.** (C). The key's PDF gives no working for this question. The only way I can reach $\Theta(n^2)$ is by counting comparisons, or by counting element moves in an insertion-style shifting version, but the question asks for swaps. I record the key and flag the conflict.

- (B) and (D) are larger than the number of passes, so they cannot bound the swaps.

**Code check:** selection sort run on every permutation of $n = 2, \dots, 8$ elements. The worst-case swap count was exactly $n - 1$ each time, both when a no-op swap is counted and when it is skipped.

**Key idea:** selection sort does $\Theta(n^2)$ comparisons but only $\Theta(n)$ swaps, at most one per pass.
