# 2008 CS Q85: Correcting the binary search program

## Question

(Continuing Q.84, the same program.) The correction needed in the program to make it work properly is

- (A) change line 6 to: `if (Y[k] < x) i = k + 1; else j = k - 1;`
- (B) change line 6 to: `if (Y[k] < x) i = k - 1; else j = k + 1;`
- (C) change line 6 to: `if (Y[k] <= x) i = k; else j = k;`
- (D) change line 7 to: `} while ((Y[k] == x) && (i < j));`

<details class="info" markdown="1">
<summary>Solution</summary>

**Status: disputed.** The official key is (A). It is the best of the four options, but I found that it does not make the program fully correct.

**Why (A) is the intended answer.** Moving `i` to `k + 1` and `j` to `k - 1` always shrinks the range, which removes the infinite loop of Q.84. The other options do not:

- (B) moves the bounds the wrong way (`i = k - 1` on a too-small element), so the range can grow and search the wrong half.
- (C) still sets `i = k` or `j = k`, so the loops of Q.84 remain.
- (D) stops the loop when `Y[k] != x`, which is backwards.

**Why (A) alone is not enough.** After the change the loop still ends on `i < j`, so when the range shrinks to a single position (`i == j`) the loop stops **before that position is tested**. Example: `Y` is $[1,\ldots,10]$ and $x = 1$. The search goes $k = 4$ ($j = 3$), $k = 1$ ($j = 0$), then `i == j` ends the loop with `k = 1` and `Y[1] = 2`, so it prints "x is not in the array" although $x = 1$ is present. A full fix also needs the loop condition to be `i <= j`.

**Code check:** I simulated the program on four 10-element arrays (the four arrays of Q.84) with every relevant $x$, using an iteration cap to detect infinite loops:

- as printed: infinite loops on all four arrays;
- option (A): no infinite loops, but 4 wrong answers on each of $[1..10]$, the odd-number array and the even-number array (the first failures are $x = 1$, $x = 1$ and $x = 2$);
- options (B) and (C): still loop on every array;
- option (D): no loops, but 10 wrong answers on each of those three arrays.

So (A) is the only option that removes the non-termination, and it is the key's choice, but strictly the program still needs `i <= j`.

**Key idea:** binary search must move the bounds past `k` (`k + 1`, `k - 1`) and test every position, so the loop needs `i <= j`.
