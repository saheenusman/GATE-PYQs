# 2015 CS2 Q49: Missing arguments in a quickselect using partition

## Question

Suppose you are provided with the following function declaration in the C programming language.

```c
int partition(int a[], int n);
```

The function treats the first element of `a[]` as a pivot, and rearranges the array so that all elements less than or equal to the pivot is in the left part of the array, and all elements greater than the pivot is in the right part. In addition, it moves the pivot so that the pivot is the last element of the left part. The return value is the number of elements in the left part.

The following partially given function in the C programming language is used to find the $k^{th}$ smallest element in an array `a[]` of size `n` using the partition function. We assume $k \le n$.

```c
int kth_smallest(int a[], int n, int k)
{
    int left_end = partition(a,n);

    if ( left_end+1 == k ) {
        return a[left_end];
    }

    if ( left_end+1 > k ) {
        return kth_smallest( ________ );
    } else {
        return kth_smallest( ________ );
    }
}
```

The missing argument lists are respectively

- (A) (a, left_end, k) and (a+left_end+1, n-left_end-1, k-left_end-1)
- (B) (a, left_end, k) and (a, n-left_end-1, k-left_end-1)
- (C) (a+left_end+1, n-left_end-1, k-left_end-1) and (a, left_end, k)
- (D) (a, n-left_end-1, k-left_end-1) and (a, left_end, k)

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Reading the code.** The first test, `left_end+1 == k`, returns `a[left_end]` as the $k^{th}$ smallest. That is correct only if `a[left_end]` is the **pivot** and has rank `left_end+1`. So the code treats `left_end` as the pivot's 0-based index.

With that reading, let $p$ = `left_end`:

- Elements before the pivot are `a[0..p-1]`. There are $p$ of them.
- Elements after the pivot start at `a+p+1`. There are $n-p-1$ of them.

**Case `left_end+1 > k`.** The target is smaller than the pivot, so it is in the left part: `(a, left_end, k)`.

**Otherwise** $k > p+1$. The target is in the right part, and the $p+1$ smaller elements are skipped, so the rank drops by $p+1$:

`(a+left_end+1, n-left_end-1, k-left_end-1)`

That is option (A).

- (B) searches the *left* part again with the shifted rank.
- (C) and (D) swap the two calls: the left part would be searched when $k$ is large.

**Code check:** about 26,000 random (array, $k$) cases, with and without duplicates:

| Option | Wrong answers |
|---|---|
| A | 0 |
| B | about 15,000 |
| C | about 22,000 |
| D | about 22,000 |

**Wording problem.** The text says `partition` returns the *number* of elements in the left part, which is the pivot's index plus 1. Taken literally, `a[left_end]` would be the first element of the right part, not the $k^{th}$ smallest. I ran that reading too: option A then fails about 17,600 of 26,000 cases, and so do the others. So the official key (A) only works if `left_end` is the pivot's index, as above.

**Key idea:** quickselect recurses into one side of the pivot. On the right side, shift the base pointer past the pivot and reduce $k$ by the number of elements skipped.

</details>
