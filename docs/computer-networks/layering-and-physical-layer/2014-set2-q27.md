# 2014 CS2 Q27: What can an intruder learn by sniffing at R2

## Question

An IP machine Q has a path to another IP machine H via three IP routers R1, R2, and R3.

Q-R1-R2-R3-H

H acts as an HTTP server, and Q connects to H via HTTP and downloads a file. Session layer encryption is used, with DES as the shared key encryption protocol. Consider the following four pieces of information:

- [I1] The URL of the file downloaded by Q
- [I2] The TCP port numbers at Q and H
- [I3] The IP addresses of Q and H
- [I4] The link layer addresses of Q and H

Which of I1, I2, I3, and I4 can an intruder learn through sniffing at R2 alone?

- (A) Only I1 and I2
- (B) Only I1
- (C) Only I2 and I3
- (D) Only I3 and I4

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Session-layer encryption protects what is **above** the session layer: the HTTP request and its URL. The headers added below it stay in clear text.

| Item | Visible at R2? | Why |
|---|---|---|
| I1 URL | No | inside the encrypted HTTP data |
| I2 TCP ports | **Yes** | TCP header sits below the session layer |
| I3 IP addresses | **Yes** | the IP header is needed for routing and stays end to end |
| I4 link-layer addresses | No | they change at every hop, and R2 only sees the addresses of R1/R2 and R2/R3 |

So I2 and I3: **C**.

- (A), (B) assume the URL is visible; it is encrypted.
- (D) the MAC addresses of Q and H never reach R2.

**Classification flag:** this mixes layering and security. It is filed under `layering-and-physical-layer`.

**Key idea:** encryption hides data above its layer; lower-layer headers stay visible, and link addresses are rewritten at each hop.

</details>
