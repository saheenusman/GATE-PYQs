# 2024 CS1 Q36: Store-and-forward delay along two links

## Question

Consider a network path P—Q—R between nodes P and R via router Q. Node P sends a file of size $10^6$ bytes to R via this path by splitting the file into chunks of $10^3$ bytes each. Node P sends these chunks one after the other without any wait time between the successive chunk transmissions. Assume that the size of extra headers added to these chunks is negligible, and that the chunk size is less than the MTU. Each of the links P—Q and Q—R has a bandwidth of $10^6$ bits/sec, and negligible propagation latency. Router Q immediately transmits every packet it receives from P to R, with negligible processing and queueing delays. Router Q can simultaneously receive on link P—Q and transmit on link Q—R. Assume P starts transmitting the chunks at time $t = 0$.

Which one of the following options gives the time (in seconds, rounded off to 3 decimal places) at which R receives all the chunks of the file?

- (A) 8.000
- (B) 8.008
- (C) 15.992
- (D) 16.000

<details class="success" markdown="1">
<summary>Answer</summary>

**B (8.008)**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Chunk transmission time.** One chunk is $10^3 \times 8 = 8000$ bits. At $10^6$ bits/s this takes $8$ ms on each link.

**Number of chunks:** $10^6 / 10^3 = 1000$.

**Pipeline.** Q can receive on one link while sending on the other, so the two links work in parallel.

- P sends chunks back to back. The last chunk (number 1000) **finishes arriving at Q** at $1000 \times 8\text{ ms} = 8.000$ s.
- Q must receive a whole chunk before forwarding it (store and forward), so the last chunk then takes another $8$ ms on Q–R.

Total $= 8.000 + 0.008 = 8.008$ s. The earlier chunks do not delay it, because Q finishes forwarding each one before the next arrives.

**Why the others fail:** 8.000 forgets the final hop. 15.992 and 16.000 treat the two links as sequential, i.e. no pipelining.

**Key idea:** with pipelining, total time = (number of chunks × chunk time) + one extra chunk time per additional hop.

</details>
