# 2014 CS2 Q26: Store-and-forward: compare transfer times for 1, 10 and 20 packets

## Question

Consider the store and forward packet switched network given below. Assume that the bandwidth of each link is $10^6$ bytes/sec. A user on host A sends a file of size $10^3$ bytes to host B through routers R1 and R2 in three different ways. In the first case a single packet containing the complete file is transmitted from A to B. In the second case, the file is split into 10 equal parts, and these packets are transmitted from A to B. In the third case, the file is split into 20 equal parts and these packets are sent from A to B. Each packet contains 100 bytes of header information along with the user data. Consider only transmission time and ignore processing, queuing and propagation delays. Also assume that there are no errors during transmission. Let T1, T2 and T3 be the times taken to transmit the file in the first, second and third case respectively. Which one of the following is CORRECT?

Network: A, R1, R2, B in a line (3 links).

- (A) T1 < T2 < T3
- (B) T1 > T2 > T3
- (C) T2 = T3, T3 < T1
- (D) T1 = T3, T3 > T2

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The path A, R1, R2, B has 3 links. With store-and-forward, $k$ packets of $t$ seconds each take $(k + 2)\,t$ in total: $k$ for the last packet to leave A, plus 2 more hops.

| Case | Packets | Size (data + header) | $t$ | Total |
|---|---|---|---|---|
| 1 | 1 | $1000 + 100 = 1100$ B | 1100 $\mu$s | $3 \times 1100 = 3300\ \mu$s |
| 2 | 10 | $100 + 100 = 200$ B | 200 $\mu$s | $12 \times 200 = 2400\ \mu$s |
| 3 | 20 | $50 + 100 = 150$ B | 150 $\mu$s | $22 \times 150 = 3300\ \mu$s |

So $T_1 = T_3 = 3.3$ ms and $T_2 = 2.4$ ms: $T_1 = T_3 > T_2$, **D**.

**Code check:** a pipeline simulation of the three links gives 3300, 2400 and 3300 $\mu$s.

- (A), (B) assume the times are strictly ordered, but $T_1 = T_3$.
- (C) says $T_2 = T_3$, but $2400 \ne 3300$.

**Key idea:** more packets pipeline better, but each adds 100 bytes of header, so the gain stops at some point.

</details>
