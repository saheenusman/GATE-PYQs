# 2011 CS Q2: What a layer-4 firewall cannot do

## Question

A layer-4 firewall (a device that can look at all protocol headers up to the transport layer) **CANNOT**

- (A) block entire HTTP traffic during 9:00PM and 5:00AM
- (B) block all ICMP traffic
- (C) stop incoming traffic from a specific IP address but allow outgoing traffic to the same IP address
- (D) block TCP traffic from a specific user on a multi-user system during 9:00PM and 5:00AM

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

A layer-4 firewall sees the IP header (addresses, protocol number) and the TCP/UDP header (ports, flags). Rules can also depend on the time of day, which the device knows from its own clock.

- (A) HTTP is TCP traffic to port $80$ (or $443$), so it can be matched by port and blocked in a time window.
- (B) ICMP is its own IP protocol number ($1$), visible in the IP header, so it can be blocked.
- (C) the rule depends only on source and destination address and the direction of the packet, both visible at layer 3.
- (D) a **user** is not a field in any header up to layer 4. Packets from different users of one host carry the same IP address and can use the same ports. Telling users apart needs host-level or application-level information, so the firewall cannot do this: (D).

**Classification note.** Firewalls are listed with network security and the application layer in the syllabus; the question is about what header fields a transport-level filter can use, so `transport-layer` is added as a second topic.

**Key idea:** a packet filter can match on address, protocol, port and time, but it cannot know which user or process sent the packet.

</details>
