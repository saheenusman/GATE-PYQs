# 2017 CS1 Q15: Who can mount a birthday attack on a digitally signed message

## Question

A sender S sends a message $m$ to receiver R, which is digitally signed by S with its private key. In this scenario, one or more of the following security violations can take place.

- (I) S can launch a birthday attack to replace $m$ with a fraudulent message.
- (II) A third party attacker can launch a birthday attack to replace $m$ with a fraudulent message.
- (III) R can launch a birthday attack to replace $m$ with a fraudulent message.

Which of the following are possible security violations?

- (A) (I) and (II) only
- (B) (I) only
- (C) (II) only
- (D) (II) and (III) only

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Setup.** The signature is computed on a hash $H(m)$, so two messages with the same hash share one signature.

**Birthday attack.** To find *some* pair $(m, m')$ with $H(m)=H(m')$, you generate many harmless-looking variants of a good message and many variants of a fraudulent one. A collision between the two groups appears after about $2^{k/2}$ tries for a $k$-bit hash. The catch: **the attacker must choose both messages before the signature is made.**

- **(I) Possible.** S picks both messages. S signs the harmless one, and later claims the signed message was the fraudulent one. The signature verifies for both, so S can repudiate.
- **(II) Not possible.** A third party cannot make S sign a message of the attacker's choosing, and cannot change the message S really signs. Given a fixed $m$, finding a different message with the same hash needs a second-preimage attack, about $2^{k}$ work, not the $2^{k/2}$ birthday bound.
- **(III) Not possible.** R only sees the finished $m$ and its signature. R has the same second-preimage problem and cannot prepare the colliding pair in advance.

Only (I): **(B)**.

**Status note:** this is a conceptual question, so there is no code to run. My reasoning matches the official key.

**Key idea:** a birthday attack works only for whoever creates both colliding messages before signing, so only the signer S can use it here.

</details>
