# 2020 CS Q48: CIDR blocks for 1500 hosts inside 202.61.0.0/17

## Question

An organization requires a range of IP addresses to assign one to each of its 1500 computers. The organization has approached an Internet Service Provider (ISP) for this task. The ISP uses CIDR and serves the requests from the available IP address space 202.61.0.0/17. The ISP wants to assign an address space to the organization which will minimize the number of routing entries in the ISP's router using route aggregation. Which of the following address spaces are potential candidates from which the ISP can allot any one to the organization?

- I. 202.61.84.0/21
- II. 202.61.104.0/21
- III. 202.61.64.0/21
- IV. 202.61.144.0/21

Options:

- (A) I and II only
- (B) II and III only
- (C) III and IV only
- (D) I and IV only

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Block size.** 1500 hosts need $2^{h} - 2 \ge 1500$ host addresses.

- $h = 10$ gives $1022$, too few.
- $h = 11$ gives $2046$, enough.

So 11 host bits, and the prefix is $32 - 11 = 21$: a **/21** block. All four candidates are /21, so the size is fine. What differs is whether each is a valid block inside the ISP's space.

**Two conditions for a candidate:**

1. **Aligned.** A /21 block starts at a multiple of 8 in the third octet (8 third-octet values per block).
2. **Inside 202.61.0.0/17.** That space covers third octets $0$ to $127$.

If the block lies inside the ISP's /17, the ISP's single aggregate route for the /17 still covers it, so no extra routing entry is needed.

| Candidate | Third octet | Multiple of 8? | Inside $0$ to $127$? | Valid? |
|---|---|---|---|---|
| I. 202.61.84.0/21 | 84 ($= 8 \times 10 + 4$) | **no** | yes | no |
| II. 202.61.104.0/21 | 104 ($= 8 \times 13$) | yes | yes | **yes** |
| III. 202.61.64.0/21 | 64 ($= 8 \times 8$) | yes | yes | **yes** |
| IV. 202.61.144.0/21 | 144 ($= 8 \times 18$) | yes | **no** | no |

I checked this with Python's `ipaddress` module: I is rejected as having host bits set, II and III are valid and inside the /17, and IV is valid but outside it.

**Why the other options fail:** (A) and (D) include I (misaligned), and (C) and (D) include IV (outside the ISP's space).

**Key idea:** a CIDR block must start on a boundary that is a multiple of its own size, and it must lie inside the address space the ISP actually owns.

</details>
