# 2012 CS Q34: CIDR sub-allocation of 245.248.128.0/20

## Question

An Internet Service Provider (ISP) has the following chunk of CIDR-based IP addresses available with it: `245.248.128.0/20`. The ISP wants to give half of this chunk of addresses to Organization A, and a quarter to Organization B, while retaining the remaining with itself. Which of the following is a valid allocation of addresses to A and B?

- (A) `245.248.136.0/21` and `245.248.128.0/22`
- (B) `245.248.128.0/21` and `245.248.128.0/22`
- (C) `245.248.132.0/22` and `245.248.132.0/21`
- (D) `245.248.136.0/24` and `245.248.132.0/21`

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The /20 chunk has $2^{12} = 4096$ addresses and spans third octet $128$ to $143$.

- **Half** = $2048$ addresses = a **/21**. A /21 block spans 8 values of the third octet and must start at a multiple of 8: `128.0/21` or `136.0/21`.
- **Quarter** = $1024$ addresses = a **/22**. A /22 spans 4 values and starts at a multiple of 4: `128`, `132`, `136` or `140`.

The two blocks must not overlap. (A) uses `136.0/21` (third octet $136$-$143$) and `128.0/22` (third octet $128$-$131$): disjoint, right sizes. Valid.

- (B) `128.0/21` ($128$-$135$) overlaps `128.0/22` ($128$-$131$).
- (C) `132.0/21` is not aligned (132 is not a multiple of 8), so it is not a valid block. Also the sizes are swapped.
- (D) `136.0/24` is only 256 addresses, not half; and `132.0/21` is not aligned.

**Code check:** Python's `ipaddress` accepted the blocks in (A), found (B) overlapping, and rejected `132.0/21` in (C) and (D) as having host bits set.

**Key idea:** a CIDR block of size $2^k$ must start at an address divisible by $2^k$.

</details>
