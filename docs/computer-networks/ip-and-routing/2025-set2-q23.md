# 2025 CS2 Q23: IP fragmentation of a UDP segment over Ethernet

## Question

Consider a network that uses Ethernet and IPv4. Assume that IPv4 headers do not use any options field. Each Ethernet frame can carry a maximum of 1500 bytes in its data field. A UDP segment is transmitted. The payload (data) in the UDP segment is 7488 bytes.

Which ONE of the following choices has the CORRECT total number of fragments transmitted and the size of the last fragment including IPv4 header?

- (A) 5 fragments, 1488 bytes
- (B) 6 fragments, 88 bytes
- (C) 6 fragments, 108 bytes
- (D) 6 fragments, 116 bytes

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Data to be carried by IP.** UDP adds an 8-byte header to its payload:

$$7488 + 8 = 7496 \text{ bytes}.$$

**Per fragment.** The Ethernet data field of 1500 bytes holds the IP header (20 bytes) and the IP data, so at most $1500 - 20 = 1480$ data bytes per fragment. That is a multiple of 8 ($1480 = 185 \times 8$), so it is allowed.

$$\left\lceil \frac{7496}{1480} \right\rceil = \lceil 5.065 \rceil = 6 \text{ fragments.}$$

Five full fragments carry $5 \times 1480 = 7400$ bytes. The last one carries $7496 - 7400 = 96$ bytes of data, and with its 20-byte IP header it is $96 + 20 = 116$ bytes.

| Option | Mistake |
|---|---|
| A | Only 5 fragments: ignores the 8-byte UDP header and rounds down |
| B | 88 = 68 + 20 or similar: miscounts the data |
| C | 108 = 88 + 20: leaves out part of the 8-byte UDP header |

**Key idea:** the UDP header is IP data, so count it. The last fragment's size is its leftover data plus the 20-byte IP header.

</details>
