# 2025 CS1 Q57: Fragments delivered after two routers with different MTUs

## Question

Suppose a message of size 15000 bytes is transmitted from a source to a destination using IPv4 protocol via two routers as shown in the figure. Each router has a defined maximum transmission unit (MTU) as shown in the figure, including IP header. The number of fragments that will be delivered to the destination is ________ . (Answer in integer)

The figure shows: Source $\to$ Router-1 (MTU = 5000 bytes) $\to$ Router-2 (MTU = 3000 bytes) $\to$ Destination.

<details class="success" markdown="1">
<summary>Answer</summary>

**7**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The IPv4 header is 20 bytes, and the data in every fragment except the last must be a **multiple of 8 bytes** (offsets are counted in 8-byte units). I take the 15000 bytes as the data to be carried.

**At Router-1 (MTU 5000).** Maximum data per fragment $= 5000 - 20 = 4980$, rounded down to a multiple of 8: **4976**.

$$15000 = 3 \times 4976 + 72,$$

so Router-1 sends **4 fragments** with data sizes $4976, 4976, 4976, 72$.

**At Router-2 (MTU 3000).** Maximum data per fragment $= 3000 - 20 = 2980$, rounded down to a multiple of 8: **2976**. Router-2 does not reassemble. It fragments each piece it receives:

| Incoming fragment data | Split into | Fragments |
|---|---|---|
| 4976 | $2976 + 2000$ | 2 |
| 4976 | $2976 + 2000$ | 2 |
| 4976 | $2976 + 2000$ | 2 |
| 72 | fits (72 + 20 = 92 < 3000) | 1 |

Total delivered to the destination: $2 + 2 + 2 + 1 = 7$.

(A program applying the same two-step fragmentation also gives 7.)

**Key idea:** a fragment is never merged on the way. A router can split an already-fragmented packet again, and the data size in each non-final fragment is a multiple of 8.

</details>
