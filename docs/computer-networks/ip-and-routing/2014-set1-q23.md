# 2014 CS1 Q23: Link state vs distance vector routing statements

## Question

Consider the following three statements about link state and distance vector routing protocols, for a large network with 500 network nodes and 4000 links.

- [S1] The computational overhead in link state protocols is higher than in distance vector protocols.
- [S2] A distance vector protocol (with split horizon) avoids persistent routing loops, but not a link state protocol.
- [S3] After a topology change, a link state protocol will converge faster than a distance vector protocol.

Which one of the following is correct about S1, S2, and S3 ?

- (A) S1, S2, and S3 are all true.
- (B) S1, S2, and S3 are all false.
- (C) S1 and S2 are true, but S3 is false.
- (D) S1 and S3 are true, but S2 is false.

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**S1 true.** Each link state router runs Dijkstra on the whole map ($O(E \log V)$ here), while distance vector only merges neighbours' tables.

**S2 false.** Distance vector protocols are the ones prone to routing loops (count-to-infinity). Split horizon reduces them but does not remove them in all topologies. Link state routers hold the full topology, so loops are only brief.

**S3 true.** Link state floods the change and each router recomputes at once. Distance vector spreads it one hop per exchange.

So S1 and S3 are true, S2 is false: **D**.

**Key idea:** link state costs more CPU but converges faster and avoids persistent loops.

</details>
