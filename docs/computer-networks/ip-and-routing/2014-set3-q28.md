# 2014 CS3 Q28: Third IP fragment of a 4404-byte packet

## Question

An IP router with a Maximum Transmission Unit (MTU) of 1500 bytes has received an IP packet of size 4404 bytes with an IP header of length 20 bytes. The values of the relevant fields in the header of the third IP fragment generated by the router for this packet are

- (A) MF bit: 0, Datagram Length: 1444; Offset: 370
- (B) MF bit: 1, Datagram Length: 1424; Offset: 185
- (C) MF bit: 1, Datagram Length: 1500; Offset: 370
- (D) MF bit: 0, Datagram Length: 1424; Offset: 2960

<details class="success" markdown="1">
<summary>Answer</summary>

**A**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Payload:** $4404 - 20 = 4384$ bytes.

**Largest data per fragment:** $1500 - 20 = 1480$ bytes. This is a multiple of 8 (the fragment offset counts in 8-byte units), so 1480 is usable.

| Fragment | Data bytes | Offset (units of 8 B) | Length | MF |
|---|---|---|---|---|
| 1 | 1480 | 0 | 1500 | 1 |
| 2 | 1480 | $1480/8 = 185$ | 1500 | 1 |
| 3 | $4384 - 2960 = 1424$ | $2960/8 = 370$ | $1424 + 20 = 1444$ | 0 |

The third fragment has MF = 0 (it is the last), length 1444 and offset 370: **A**.

- (B) combines the second fragment's offset (185) with the third fragment's data size, and MF = 1 is wrong for the last fragment.
- (C) uses length 1500 and MF = 1, which would mean more fragments follow.
- (D) gives the offset in bytes (2960), not in 8-byte units, and the length without the header.

**Code check:** a fragmentation script gives (0, 1500, MF 1), (185, 1500, MF 1), (370, 1444, MF 0).

**Key idea:** the offset is in units of 8 bytes, the length includes the 20-byte header, and MF is 0 only on the last fragment.

</details>
