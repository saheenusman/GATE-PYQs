# 2015 CS2 Q37: IP fragments of a large UDP datagram and the last offset

## Question

Host A sends a UDP datagram containing 8880 bytes of user data to host B over an Ethernet LAN. Ethernet frames may carry data up to 1500 bytes (i.e. MTU = 1500 bytes). Size of UDP header is 8 bytes and size of IP header is 20 bytes. There is no option field in IP header. How many total number of IP fragments will be transmitted and what will be the contents of offset field in the last fragment?

- (A) 6 and 925
- (B) 6 and 7400
- (C) 7 and 1110
- (D) 7 and 8880

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

- IP payload $= 8880 + 8\text{ (UDP header)} = 8888$ bytes.
- Each fragment carries at most $1500 - 20 = 1480$ bytes of data (a multiple of 8, as required).
- Fragments: $\lceil 8888 / 1480 \rceil = 7$. Six carry $1480$ bytes ($6 \times 1480 = 8880$) and the last carries the remaining $8$ bytes.

The fragment offset field counts in units of **8 bytes**. The last fragment starts at byte $6 \times 1480 = 8880$:

$$\text{offset} = \frac{8880}{8} = 1110$$

7 fragments and offset 1110: option (C). (A) and (B) use 6 fragments, ignoring the UDP header's 8 bytes. (D) gives the offset in bytes, not in 8-byte units.

**Key idea:** count the UDP header as payload, and give the fragment offset in 8-byte units.

</details>
