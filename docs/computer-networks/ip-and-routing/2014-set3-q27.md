# 2014 CS3 Q27: Wrap-around period of a 50-bit unique ID

## Question

Every host in an IPv4 network has a 1-second resolution real-time clock with battery backup. Each host needs to generate up to 1000 unique identifiers per second. Assume that each host has a globally unique IPv4 address. Design a 50-bit globally unique ID for this purpose. After what period (in seconds) will the identifiers generated by a host wrap around?

<details class="success" markdown="1">
<summary>Answer</summary>

**256**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

Split the 50 bits into three fields:

| Field | Purpose | Bits |
|---|---|---|
| IPv4 address | makes IDs unique across hosts | 32 |
| Counter | up to 1000 IDs in the same second; $2^{10} = 1024 \ge 1000$ | 10 |
| Clock | seconds from the real-time clock | $50 - 32 - 10 = 8$ |

The clock field has 8 bits, so it repeats after $2^8 = 256$ seconds. After that the same (address, clock, counter) can occur again, so the IDs wrap around after **256 s**.

A smaller counter would not hold 1000 values ($2^9 = 512 < 1000$), and a larger one would leave fewer than 8 bits for the clock, shortening the period. So 10 bits is the choice that gives the longest period.

**Classification flag:** this is an identifier-design puzzle that uses IPv4 addresses. Filed under `ip-and-routing`, as there is no better networking topic.

**Key idea:** allocate the minimum bits needed for the host part (32) and the counter (10); the rest is the time field, which decides the wrap-around.

</details>
