# 2013 CS Q37: IPv4 fragment payload range

## Question

In an IPv4 datagram, the $M$ bit is 0, the value of HLEN is 10, the value of total length is 400 and the fragment offset value is 300. The position of the datagram, the sequence numbers of the first and the last bytes of the payload, respectively are

- (A) Last fragment, 2400 and 2789
- (B) First fragment, 2400 and 2759
- (C) Last fragment, 2400 and 2759
- (D) Middle fragment, 300 and 689

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

- **Position.** $M = 0$ means no more fragments follow, so this is the **last** fragment. (A fragment offset of 300 also means it is not the first.)
- **Header.** HLEN is in 4-byte words: $10 \times 4 = 40$ bytes.
- **Payload.** $400 - 40 = 360$ bytes.
- **First byte.** The offset counts 8-byte units: $300 \times 8 = 2400$.
- **Last byte.** $2400 + 360 - 1 = 2759$.

**Why the others fail:**

- (A) 2789 assumes the header is only 10 bytes.
- (B) a first fragment has offset 0 (and usually $M=1$).
- (D) forgets the factor 8 for the offset, and $M=0$ rules out a middle fragment.

**Code check:** arithmetic gave 2400 to 2759.

**Key idea:** HLEN is in 4-byte words, the fragment offset in 8-byte units, and $M=0$ marks the last fragment.

</details>
