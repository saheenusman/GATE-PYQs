# 2026 CS1 Q56: Which CIDR block can the ISP assign

## Question

An ISP has the address block 202.16.0.0/15. It assigns a block of **6000** IP addresses to a client using CIDR super-netting. Which of the following address blocks can be assigned by the ISP?

- (A) 202.16.0.0/19
- (B) 202.17.64.0/19
- (C) 202.16.32.0/19
- (D) 202.17.24.0/19

<details class="success" markdown="1">
<summary>Answer</summary>

**A, B and C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Step 1: block size.** 6000 addresses needs the next power of two: $2^{13} = 8192$. A block of $2^{13}$ addresses has $13$ host bits, so its prefix is $/(32 - 13) = /19$. All four options are /19, so size is fine.

**Step 2: inside the ISP block.** 202.16.0.0/15 covers 202.16.0.0 to 202.17.255.255 (the third octet runs over two values of the second octet).

**Step 3: alignment.** A /19 block has host bits across the last 13 bits, so its third octet must be a multiple of 32 (0, 32, 64, 96, ...).

| Block | Third octet | Multiple of 32? | Inside 202.16.0.0/15? |
|---|---|---|---|
| 202.16.0.0/19 | 0 | yes | yes |
| 202.17.64.0/19 | 64 | yes | yes |
| 202.16.32.0/19 | 32 | yes | yes |
| 202.17.24.0/19 | 24 | **no** | not a valid /19 |

Only the first three are valid.

**Verified** with Python's `ipaddress` module: 202.17.24.0/19 is rejected because it has host bits set.

**Key idea:** a /n block must start at an address divisible by its size, and it must sit inside the ISP's block.

</details>
