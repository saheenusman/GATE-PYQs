# 2015 CS1 Q36: Minimum frame size for 50% utilization in stop-and-wait

## Question

Suppose that the stop-and-wait protocol is used on a link with a bit rate of 64 kilobits per second and 20 milliseconds propagation delay. Assume that the transmission time for the acknowledgement and the processing time at nodes are negligible. Then the minimum frame size in bytes to achieve a link utilization of at least 50% is ______.

<details class="success" markdown="1">
<summary>Answer</summary>

**160**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Status: disputed.** The official key is 160. Using the standard stop-and-wait model I get 320, so I could not derive the key. Both readings follow.

**Reading 1: standard model (one-way delay $T_p = 20$ ms).** One cycle is: send the frame ($T_t$), wait for it to travel there, and for the ack to travel back.

$$U = \frac{T_t}{T_t + 2T_p} \ge 0.5 \;\Rightarrow\; T_t \ge 2T_p = 40\text{ ms}$$

Frame size $= 64000 \times 0.040 = 2560$ bits $= \mathbf{320}$ bytes.

**Reading 2: the key's 160.** It follows if the cycle is taken as $T_t + T_p$, i.e. only **one** propagation delay per cycle:

$$\frac{T_t}{T_t + T_p} \ge 0.5 \;\Rightarrow\; T_t \ge 20\text{ ms} \;\Rightarrow\; 64000 \times 0.020 = 1280\text{ bits} = 160\text{ bytes}$$

This is equivalent to reading the 20 ms as the *round-trip* delay, but the question says "propagation delay", which is normally one way.

**Conclusion.** I record the official key (160) but the question as worded gives 320 in the standard model. That is why this is marked `disputed`.

**Cross-check.** In the 2015 CS2 paper, Q34 uses $T_t/(T_t + 2T_p)$ for its key. The CS1 key here is not consistent with that model.

**Key idea:** stop-and-wait utilisation is $T_t/(T_t + 2T_p)$ when $T_p$ is the one-way delay.

</details>
