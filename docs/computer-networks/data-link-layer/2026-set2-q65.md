# 2026 CS2 Q65: Sequence number bits for a long fat link

## Question

A link-layer protocol must be designed between two hosts directly connected over a lossless link of length 3000 km. The bandwidth is $10^8$ bits per second and the propagation delay is 5 nanoseconds per meter. Every transmitted data **byte** gets a unique sequence number.

Let $N$ be the minimum number of bits needed in the sequence number field so that (i) sequence numbers do not wrap around before 60 seconds, and (ii) maximum utilisation of the link is achieved. The value of $N$ is _____. (answer in integer)

<details class="success" markdown="1">
<summary>Answer</summary>

**30**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Condition (ii): maximum utilisation.**

- One-way delay: $3{,}000{,}000\ \text{m} \times 5\ \text{ns/m} = 15\ \text{ms}$. Round trip: $30$ ms.
- Bytes in flight to fill the pipe: $10^8\ \text{bits/s} \times 0.030\ \text{s} / 8 = 375{,}000$ bytes.
- To number that many bytes, even a selective-repeat window (which needs $2 \times$ the window) needs about $2^{20}$ numbers. So condition (ii) alone needs about 20 bits.

**Condition (i): no wrap-around for 60 seconds.**

- Bytes sent in 60 s: $10^8 \times 60 / 8 = 7.5 \times 10^8$ bytes.
- Each byte has a unique number, so we need $2^N \ge 7.5 \times 10^8$.
- $2^{29} \approx 5.4 \times 10^8$ is too small. $2^{30} \approx 1.07 \times 10^9$ is enough.

So $N = 30$. Condition (i) is the stricter one, and it also satisfies (ii).

**Verified** by computing: bytes in 60 s $= 750{,}000{,}000$, which needs 30 bits.

**Key idea:** with byte-level numbering, the wrap-around rule ($2^N \ge$ bytes sent in the time limit) usually dominates the window-size rule.

</details>
