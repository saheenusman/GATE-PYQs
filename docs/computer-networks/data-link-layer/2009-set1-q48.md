# 2009 CS Q48: CRC generator condition to detect an odd number of bit errors

## Question

Let $G(x)$ be the generator polynomial used for CRC checking. What is the condition that should be satisfied by $G(x)$ to detect odd number of bits in error?

- (A) $G(x)$ contains more than two terms.
- (B) $G(x)$ does not divide $1 + x^k$, for any $k$ not exceeding the frame length.
- (C) $1 + x$ is a factor of $G(x)$.
- (D) $G(x)$ has an odd number of terms.

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

An error is detected unless the error polynomial $E(x)$ is divisible by $G(x)$. All arithmetic is over $\mathrm{GF}(2)$.

An error with an **odd** number of bit errors has an odd number of terms. So $E(1) = 1 \pmod 2$, and therefore $(1 + x)$ does **not** divide $E(x)$ (a multiple of $1 + x$ has value $0$ at $x = 1$).

If $(1 + x)$ is a factor of $G(x)$, then $G(x)$ dividing $E(x)$ would force $(1+x)$ to divide $E(x)$, which is impossible. So **no odd-weight error can slip through**: (C).

- (A) is not enough: $G = x^2 + x + 1$ has more than two terms, but the $3$-bit error $E = x^2 + x + 1$ is divisible by it and goes undetected.
- (B) is the condition for catching all **double**-bit errors, not odd ones. For $G = x^3 + x + 1$ it holds for $k \le 6$, yet in a $7$-bit frame some $3$-bit errors are still missed.
- (D) is the wrong way round: a polynomial with an odd number of terms has value $1$ at $x = 1$, so $(1+x)$ is **not** a factor of it. $x^2 + x + 1$ has $3$ terms and misses $3$-bit errors, as above.

**Code check:** over all error patterns in a $12$-bit frame:

- $G = (x+1)(x^3+x+1) = x^4 + x^3 + x^2 + 1$ missed $0$ odd-weight errors.
- $G = x^2 + x + 1$ (3 terms) missed $512$ odd-weight errors.
- $G = x^3 + x + 1$ (3 terms) does not divide $1 + x^k$ for $k = 1, \dots, 6$, but in a $7$-bit frame it still missed $8$ odd-weight errors.
- All $16$ generators of degree at most $5$ with a constant term and a factor $(1 + x)$ caught every odd-weight error in the $12$-bit frame.

**Key idea:** $(1+x)$ as a factor of $G(x)$ guarantees detection of every odd number of bit errors.

</details>
