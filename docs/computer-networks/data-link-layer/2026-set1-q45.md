# 2026 CS1 Q45: Window size for 100% utilisation of a sliding window link

## Question

A sliding window protocol runs over a lossless link with a window of $W$ frames. Each frame is 1000 bits (including header). The link bandwidth is 100 kbps ($1\text{k} = 10^3$) and the one-way propagation delay is 100 ms. Processing times and the transmission time of acknowledgements are zero.

Which option gives the minimum $W$ (number of frames) for **100% link utilisation**?

- (A) 10
- (B) 21
- (C) 20
- (D) 11

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Refresher.** The sender can stay busy only if the window is big enough to keep sending until the first ACK returns.

**Frame transmission time:**

$$T_t = \frac{1000\ \text{bits}}{100{,}000\ \text{bits/s}} = 10\ \text{ms}.$$

**Time before the first ACK returns:** transmit the first frame, wait for it to travel there, and the ACK to travel back:

$$T_t + 2 T_p = 10 + 2 \times 100 = 210\ \text{ms}.$$

**Frames sent in that time:**

$$W \ge \frac{T_t + 2T_p}{T_t} = \frac{210}{10} = 21.$$

So the minimum window is **21 frames** (equivalently $1 + 2T_p / T_t = 1 + 20$).

**Why the others fail:** 20 and 10 are too small (the link idles waiting for the ACK). 11 forgets the round trip (counts only one propagation delay).

**Key idea:** $W \ge 1 + 2T_p/T_t$ for full utilisation.

</details>
