# 2015 CS2 Q38: RTT threshold and maximum window with the TCP window scale option

## Question

Assume that the bandwidth for a TCP connection is 1048560 bits/sec. Let $\alpha$ be the value of RTT in milliseconds (rounded off to the nearest integer) after which the TCP window scale option is needed. Let $\beta$ be the maximum possible window size with window scale option. Then the values of $\alpha$ and $\beta$ are

- (A) 63 milliseconds, $65535 \times 2^{14}$
- (B) 63 milliseconds, $65535 \times 2^{16}$
- (C) 500 milliseconds, $65535 \times 2^{14}$
- (D) 500 milliseconds, $65535 \times 2^{16}$

<details class="success" markdown="1">
<summary>Answer</summary>

**C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

The TCP window field is 16 bits, so without scaling the window is at most $65535$ bytes.

**$\alpha$.** The window scale option is needed when the bandwidth-delay product exceeds 65535 bytes:

$$\text{RTT} > \frac{65535 \times 8\text{ bits}}{1048560\text{ bits/s}} \approx 0.49999\text{ s} \approx 500\text{ ms}$$

**$\beta$.** The scale factor is a shift of at most 14 bits, so the maximum window is $65535 \times 2^{14}$ bytes.

500 ms and $65535 \times 2^{14}$: option (C).

(A) and (B) use 63 ms. That comes from treating 65535 as *bits* instead of bytes: $65535/1048560 \approx 0.0625$ s. (B) and (D) use a shift of 16, but the window scale shift is capped at 14.

**Key idea:** window $= 65535$ bytes unscaled, scale shift at most $14$, so the maximum is $65535 \times 2^{14}$.

</details>
