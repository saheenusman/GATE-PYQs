# 2017 CS1 Q14: TCP state in which the client waits for the server's FIN

## Question

Consider a TCP client and a TCP server running on two different machines. After completing data transfer, the TCP client calls `close` to terminate the connection and a FIN segment is sent to the TCP server. Server-side TCP responds by sending an ACK, which is received by the client-side TCP. As per the TCP connection state diagram (RFC 793), in which state does the client-side TCP connection wait for the FIN from the server-side TCP?

- (A) LAST-ACK
- (B) TIME-WAIT
- (C) FIN-WAIT-1
- (D) FIN-WAIT-2

<details class="success" markdown="1">
<summary>Answer</summary>

**D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Active close, step by step (client side).**

| Event | Client state |
|---|---|
| `close()` called, FIN sent | ESTABLISHED $\to$ **FIN-WAIT-1** (waits for the ACK of its FIN) |
| ACK of its FIN received | FIN-WAIT-1 $\to$ **FIN-WAIT-2** (waits for the server's FIN) |
| Server's FIN received, ACK sent | FIN-WAIT-2 $\to$ TIME-WAIT |
| After $2\times$MSL | TIME-WAIT $\to$ CLOSED |

The ACK has already arrived, so the client is in **FIN-WAIT-2**: **(D)**.

**Why the others fail.**

- (A) LAST-ACK is a state of the side that closes *second* (the server), while it waits for the final ACK.
- (B) TIME-WAIT comes after the server's FIN has been received.
- (C) FIN-WAIT-1 is before the ACK of the client's FIN arrives.

**Key idea:** FIN-WAIT-1 waits for the ACK; FIN-WAIT-2 waits for the peer's FIN.

</details>
