# 2023 CS Q50: Valid sequence number lengths for myTCP

## Question

Suppose you are asked to design a new reliable byte-stream transport protocol like TCP. This protocol, named myTCP, runs over a 100 Mbps network with Round Trip Time of 150 milliseconds and the maximum segment lifetime of 2 minutes.

Which of the following is/are valid lengths of the Sequence Number field in the myTCP header?

- (A) 30 bits
- (B) 32 bits
- (C) 34 bits
- (D) 36 bits

<details class="success" markdown="1">
<summary>Answer</summary>

**B, C and D**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**The wrap-around rule.** The sequence space must not wrap while old copies of a segment may still be alive in the network. So the number of bytes that can be sent in one maximum segment lifetime (MSL) must fit in the sequence space.

**Bytes in one MSL.**

$$\frac{100 \times 10^6}{8}\ \text{B/s} \times 120\ \text{s} = 1.5 \times 10^9\ \text{bytes}$$

**Bits needed.**

$$\log_2(1.5 \times 10^9) \approx 30.5 \;\Rightarrow\; \text{at least } 31 \text{ bits}$$

- **30 bits** ($2^{30} \approx 1.07 \times 10^9$) is too small. **Invalid.**
- **32, 34, 36 bits** are all larger than the minimum. **Valid.** (Even the stricter rule using $2 \times$ MSL, $3 \times 10^9 < 2^{32}$, is met by 32 bits.)

The window needed to fill the pipe is only $12.5\text{ MB/s} \times 0.15\text{ s} \approx 1.9\text{ MB}$, far below $2^{31}$, so it does not add a stricter limit.

**Key idea:** the sequence space must outlast the data sent in one segment lifetime. Any length at least the minimum works.

</details>
