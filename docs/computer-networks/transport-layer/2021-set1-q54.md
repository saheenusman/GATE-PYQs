# 2021 CS1 Q54: TCP behaviour after the server crashes and reboots

## Question

A TCP server application is programmed to listen on port number $P$ on host $S$. A TCP client is connected to the TCP server over the network.

Consider that while the TCP connection was active, the server machine $S$ crashed and rebooted. Assume that the client does not use the TCP keepalive timer.

Which of the following behaviors is/are possible?

- (A) If the client was waiting to receive a packet, it may wait indefinitely.
- (B) The TCP server application on $S$ can listen on $P$ after reboot.
- (C) If the client sends a packet after the server reboot, it will receive a RST segment.
- (D) If the client sends a packet after the server reboot, it will receive a FIN segment.

<details class="success" markdown="1">
<summary>Answer</summary>

**A, B and C**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

- (A) **Possible.** With no keepalive and nothing to send, the client has no way to learn that the server is gone. It can wait forever.
- (B) **Possible.** After the reboot the server application can be started again and listen on $P$ (the old connection state is lost with the crash).
- (C) **Possible.** The rebooted host has no record of the connection. When the client sends a segment, the server's TCP replies with **RST**, which tells the client the connection no longer exists.
- (D) Not possible. A FIN is part of an orderly close that a live connection initiates. A host with no connection state answers with RST, not FIN.

Answer: **A, B and C**.

**Key idea:** a segment for an unknown connection draws an RST, and without keepalive a silent peer is never detected.

</details>
