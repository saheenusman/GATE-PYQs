# 2017 CS2 Q18: Connected UDP sockets: multiple peers and repeated connect

## Question

Consider socket API on a Linux machine that supports connected UDP sockets. A connected UDP socket is a UDP socket on which `connect` function has already been called. Which of the following statements is/are CORRECT?

- I. A connected UDP socket can be used to communicate with multiple peers simultaneously.
- II. A process can successfully call `connect` function again for an already connected UDP socket.

Options:

- (A) I only
- (B) II only
- (C) Both I and II
- (D) Neither I nor II

<details class="success" markdown="1">
<summary>Answer</summary>

**B**

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**What `connect` does on UDP.** There is no handshake. The kernel only records the peer's address and port. From then on:

- `send`/`write` go to that peer;
- the socket **receives only datagrams from that peer**; datagrams from anyone else are dropped.

**I. False.** Since the socket accepts datagrams from only one peer, it cannot be used to talk to several peers at the same time.

**II. True.** Unlike TCP, a UDP socket may call `connect` again, either to **change** the peer or to **dissolve** the association (by connecting to an address with family `AF_UNSPEC`).

So II only: **(B)**.

**Why the others fail.** (A) and (C) include I; (D) denies II, but repeated `connect` is allowed.

**Code check:** a loopback test in Python on Linux. Socket A was connected to B. A datagram from C was never delivered, while one from B was. A second `connect` to C succeeded, `getpeername()` then returned C, a datagram from C was delivered, and one from B was no longer delivered.

**Key idea:** a connected UDP socket filters traffic to one peer, but that association can be changed by calling `connect` again.

</details>
