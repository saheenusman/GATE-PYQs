# 2009 CS Q47: Minimum permissible rate of sequence number increase

## Question

While opening a TCP connection, the initial sequence number is to be derived using a time-of-day (ToD) clock that keeps running even when the host is down. The low order 32 bits of the counter of the ToD clock is to be used for the initial sequence numbers. The clock counter increments once per millisecond. The maximum packet lifetime is given to be 64s.

Which one of the choices given below is closest to the minimum permissible rate at which sequence numbers used for packets of a connection can increase?

- (A) 0.015/s
- (B) 0.064/s
- (C) 0.135/s
- (D) 0.327/s

<summary>Solution</summary>

**Official key:** the key table in the supplied PDF has no entry for Q47, so I cannot check against it. **I could not derive this answer rigorously from the question text, so treat it with caution.**

**What the commonly published solution does.** Published solutions (for example the GeeksforGeeks write-up of this question) take the sequence number as advancing once per maximum packet lifetime of $64$ s. The minimum rate is then

$$\frac{1}{64\ \text{s}} = 0.015625\ \text{per second} \approx 0.015/\text{s},$$

which is (A).

**Why I am not fully sure.**

- This calculation uses only the $64$ s lifetime. The $32$-bit counter and the $1$ ms tick given in the question play no part in it, which suggests the question is worded loosely.
- I cannot reproduce (B) $0.064/s$, (C) $0.135/s$ or (D) $0.327/s$ from the data given, so I cannot say why each is wrong beyond the fact that none equals $1/64$.

**Status note:** marked `unverified` because the key gives no answer and the answer rests on secondary sources and a loose reading. The only check run was the arithmetic: $1/64 = 0.015625$.

**Key idea:** the allowed rate is tied to the maximum packet lifetime: one sequence number step per $64$ s gives $1/64 \approx 0.015$ per second.
