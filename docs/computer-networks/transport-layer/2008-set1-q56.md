# 2008 CS Q56: Congestion window growth in TCP slow start

## Question

In the slow start phase of the TCP congestion control algorithm, the size of the congestion window

- (A) does not increase
- (B) increases linearly
- (C) increases quadratically
- (D) increases exponentially

<details class="success" markdown="1">
<summary>Answer</summary>

**B** (official key; see the Solution: disputed)

</details>

<details class="info" markdown="1">
<summary>Solution</summary>

**Status: disputed.** The official key is (B), but the textbook behaviour is exponential growth, which is (D). Both views follow.

**Slow start.** The congestion window starts at one segment. For every ACK received, the sender adds one segment to `cwnd`. In one round-trip time a window of $w$ segments produces $w$ ACKs, so `cwnd` becomes $2w$. So it **doubles every RTT**:

$$1,\ 2,\ 4,\ 8,\ 16,\ \ldots$$

This is **exponential** growth. The **linear** growth ("add one segment per RTT") belongs to the next phase, **congestion avoidance** (additive increase), which starts when `cwnd` reaches the slow start threshold.

**The key's view.** The key's (B) is the behaviour of congestion avoidance, not slow start.

- (A) is wrong: the window does increase.
- (C) quadratic is not a TCP growth law.

I record the key (B) but, by the standard description of slow start (RFC 5681), the correct answer is (D), so I mark the question disputed.

**Key idea:** slow start doubles the window every RTT (exponential); linear growth is congestion avoidance.

</details>
